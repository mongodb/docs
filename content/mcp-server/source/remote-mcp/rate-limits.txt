================================================
Rate Limits for MongoDB Atlas Managed MCP Server
================================================

Atlas applies rate limits to the requests that AI clients and agents
send to the {+atlas-managed-mcp-server+}. These limits help prevent a
single user or agent from overwhelming the service, and help protect
Atlas clusters and other downstream systems from unusually high
request volumes. The limits apply regardless of which :ref:`access
model <remote-mcp-access-models>` you use.

.. important::

   MongoDB is still evaluating usage patterns for the
   {+atlas-managed-mcp-server+}. The rate limits described on this
   page might change without prior notice.

Current Rate Limits
-------------------

The current rate limits for the {+atlas-managed-mcp-server+} are:

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Limit
     - Rate
   * - Requests per IP address
     - 2,000 requests per minute
   * - Requests per user
     - 500 requests per minute

Both limits apply to requests sent to the service. The per-IP limit
applies to requests from a single IP address, and the per-user limit
applies to requests from a single user.

.. important::

   These rate limits apply only to requests sent to the
   {+atlas-managed-mcp-server+}. The Atlas Administration API and the
   MCP Configuration API have their own rate limits, which apply
   separately. To learn about Atlas Administration API rate limits,
   see :ref:`api-rate-limiting`.

What Happens When You Exceed a Rate Limit
-----------------------------------------

When you exceed a rate limit, the {+atlas-managed-mcp-server+} returns
an HTTP `429 (Too Many Requests)
<https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/429>`__
response and does not process the request.

If you receive a 429 response:

- Wait before retrying. An immediate retry is likely to fail while you
  are still over the rate limit.
- Retry with exponential backoff, gradually increasing the wait time
  before each retry.
- Add a random delay (*jitter*) to avoid synchronized retries from
  multiple clients.
- If the response includes a ``Retry-After`` header, wait at least as
  long as the header specifies.

Atlas does not currently provide a way to inspect the rate limits of the
{+atlas-managed-mcp-server+} or your current usage against those limits.
You cannot request changes to these rate limits at this time. If the
current limits are too restrictive for your use case, contact your
MongoDB account team or `MongoDB Support
<https://support.mongodb.com/welcome>`__ to flag that the limits do not
meet your needs.
