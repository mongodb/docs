Overview
--------

The :guilabel:`Monitoring` page in the {+platform-short+} UI shows usage
and health metrics for your project and its workspaces. Use the page to
track agent invocations, error rates, token usage, memory activity, and
resource consumption over time. The page shows data for the current
project only.

Each section of the page shows metrics as tiles and trend cards. A tile
shows a single value for the selected time period. A trend card shows
how a metric changes over the selected time period. Trend cards group
data into 5-minute buckets for the :guilabel:`1h` period, hourly
buckets for the :guilabel:`24h` period, and daily buckets for the
:guilabel:`7d` and :guilabel:`30d` periods.

To learn how to view logs, deployment events, and live workspace
health, see the :ref:`agent-engine-monitor` guide. To learn how to
debug a specific agent run, see the
:ref:`agent-engine-inspect-traces` guide.

View Metrics
------------

To view metrics for your project, perform the following steps:

.. procedure::
   :style: normal

   .. step:: Open the Monitoring page.

      In the left navigation bar in the {+platform-short+} UI, under
      :guilabel:`Monitor`, click :guilabel:`Monitoring`.

   .. step:: Select a time period.

      Select :guilabel:`1h`, :guilabel:`24h`, :guilabel:`7d`, or
      :guilabel:`30d` to select a time period to monitor. The page
      shows the last 24 hours by default.

   .. step:: (Optional) Filter by workspace.

      To view metrics for a single workspace, select the workspace from
      the workspace filter, or click a row in the :guilabel:`By
      workspace` or :guilabel:`Compute by workspace` table. To return to
      project-wide metrics, select :guilabel:`All workspaces`.

The page refreshes its data automatically every 60 seconds.

.. _agent-engine-monitoring-ui-workspace-scope:

Workspace View
~~~~~~~~~~~~~~

When you view a single workspace, the page shows the same sections as
the project-wide view scoped to that workspace, with the following
exceptions:

- The :guilabel:`Networking` section is not available.
- The :guilabel:`By workspace` and :guilabel:`Compute by workspace`
  tables are not available.

Customize the Page
------------------

You can choose which trend cards appear in each section, and you can
show the :guilabel:`Compute` and :guilabel:`Networking` sections, which
are hidden by default. You can customize the page in the project-wide
view or in a single workspace view.

To customize the page, perform the following steps:

.. procedure::
   :style: normal

   .. step:: Click :guilabel:`Customize`.

      The period selector and workspace filter are hidden while you
      customize the page.

   .. step:: Select the content to show.

      - To show or hide a trend card, toggle the card in its section.
      - To show the :guilabel:`Compute` section, select
        :guilabel:`Show Compute`.
      - To show the :guilabel:`Networking` section, select
        :guilabel:`Show networking`.

   .. step:: Click :guilabel:`Save`.

      To discard your changes, click :guilabel:`Cancel`.

By default, the :guilabel:`Usage`, :guilabel:`Memory`, and
:guilabel:`Policy` sections show trend cards for the four metrics with
the highest volume. You cannot customize the :guilabel:`Health` trend
card.

Your browser stores your selections, so they persist across sessions
in the same browser. Your selections do not apply in other browsers or
on other devices.

Metrics Reference
-----------------

This section describes the metrics in each section of the
:guilabel:`Monitoring` page. Each metric shows the total for the
selected time period.

Health
~~~~~~

The :guilabel:`Health` section shows the outcome and duration of agent
runs. The section also contains :guilabel:`Invocations` and
:guilabel:`Errors` trend cards. The :guilabel:`Errors` trend card
appears only when errors occurred in the selected period.

The following table describes the metrics in the section:

.. list-table::
   :header-rows: 1
   :widths: 25 60 15

   * - Metric
     - Description
     - Unit
   * - :guilabel:`Invocations`
     - Number of agent runs that completed or failed. Runs that are
       waiting for approval are not counted.
     - Count
   * - :guilabel:`Error rate`
     - Number of failures divided by invocations. This value is zero
       when there were no invocations.
     - Percent
   * - :guilabel:`Failures`
     - Number of runs that ended in an error. Runs that are waiting for
       approval are not counted.
     - Count
   * - :guilabel:`Latency p50`
     - Median time from the start of a run to completion or error,
       including time spent waiting for approval.
     - ms or s
   * - :guilabel:`Latency p95`
     - Time within which 95 percent of runs finished, from the start
       of a run to completion or error, including time spent waiting
       for approval.
     - ms or s

The latency metrics appear only when latency data is available for the
selected period. To learn more about approvals, see
:ref:`agent-engine-human-in-the-loop`.

Usage
~~~~~

The :guilabel:`Usage` section shows model, tool, and runtime
consumption. The following table describes the metrics in the section:

.. list-table::
   :header-rows: 1
   :widths: 25 60 15

   * - Metric
     - Description
     - Unit
   * - :guilabel:`LLM calls`
     - Number of calls to language models.
     - Count
   * - :guilabel:`Input tokens`
     - Number of tokens sent to language models.
     - Count
   * - :guilabel:`Output tokens`
     - Number of tokens returned by language models.
     - Count
   * - :guilabel:`Tool sandbox calls`
     - Number of calls to tool sandboxes.
     - Count
   * - :guilabel:`Tool sandboxes`
     - Number of tool sandboxes used.
     - Count
   * - :guilabel:`Workload runtime`
     - Total time that agent and tool sandboxes ran during the selected
       period.
     - Duration
   * - :guilabel:`Platform uptime`
     - Total time that always-on platform services, including the
       orchestration engine and memory server, ran during the selected
       period. This value includes idle time.
     - Duration

A :guilabel:`Pod runtime` trend card, which combines workload runtime
and platform uptime, is available through :guilabel:`Customize`.

Memory
~~~~~~

The :guilabel:`Memory` section shows agent memory activity. The
following table describes the metrics in the section:

.. list-table::
   :header-rows: 1
   :widths: 25 60 15

   * - Metric
     - Description
     - Unit
   * - :guilabel:`Docs written`
     - Number of documents written to memory in the selected period.
       This value is not the current size of memory.
     - Count
   * - :guilabel:`Docs retrieved`
     - Number of documents retrieved from memory.
     - Count
   * - :guilabel:`Embedding tokens`
     - Number of tokens used to generate embeddings.
     - Count
   * - :guilabel:`Searches`
     - Number of memory search calls.
     - Count
   * - :guilabel:`Context tokens`
     - Number of memory tokens added to agent context.
     - Count
   * - :guilabel:`Memories consolidated`
     - Number of memories added through consolidation.
     - Count

To learn more about agent memory, see
:ref:`agent-engine-memory`.

Policy
~~~~~~

The :guilabel:`Policy` section shows the :guilabel:`Policy denials`
metric, which counts the calls that the :ref:`Policy Engine
<agent-engine-policy-engine>` denied. 

The metric counts denials from the ``AUTHORIZED_TOOLS`` policy type,
and from execution and session budget policies. The metric does not
count denials from the ``AUTHORIZED_MODELS`` policy type. To learn
more, see :ref:`agent-engine-policy-types`.

Memory Latency
~~~~~~~~~~~~~~

The :guilabel:`Memory latency` section shows the performance of
memory operations. Each metric appears only when your agents
performed the related memory operation during the selected time period.

The following table describes the metrics in the section:

.. list-table::
   :header-rows: 1
   :widths: 25 60 15

   * - Metric
     - Description
     - Unit
   * - :guilabel:`Context latency p50`
     - Median time to retrieve memory context.
     - ms or s
   * - :guilabel:`Context latency p95`
     - Time within which 95 percent of memory context retrievals
       finished.
     - ms or s
   * - :guilabel:`Write latency p95`
     - Time within which 95 percent of memory writes finished.
     - ms or s
   * - :guilabel:`Retrieval success`
     - Percentage of memory retrievals that succeeded.
     - Percent

Compute
~~~~~~~

The :guilabel:`Compute` section shows resource usage. The section is
hidden by default. To show the section, select :guilabel:`Show Compute`
after you select :guilabel:`Customize`. The section includes
:guilabel:`CPU` and :guilabel:`Memory` trend cards.

The following table describes the metrics in the section:

.. list-table::
   :header-rows: 1
   :widths: 25 60 15

   * - Metric
     - Description
     - Unit
   * - :guilabel:`CPU`
     - Mean CPU usage over the selected period.
     - Cores
   * - :guilabel:`CPU user`
     - Mean CPU usage in user mode.
     - Cores
   * - :guilabel:`CPU system`
     - Mean CPU usage in system mode.
     - Cores
   * - :guilabel:`Memory`
     - Current memory usage.
     - Bytes
   * - :guilabel:`Disk`
     - Current disk usage.
     - Bytes
   * - :guilabel:`Processes`
     - Current number of processes.
     - Count

Networking
~~~~~~~~~~

The :guilabel:`Networking` section shows project-wide egress traffic.
The section is hidden by default and is available in the project-wide
view only. To show the section, select :guilabel:`Show networking`
after you select :guilabel:`Customize`.

.. list-table::
   :header-rows: 1
   :widths: 25 60 15

   * - Metric
     - Description
     - Unit
   * - :guilabel:`Egress throughput`
     - Mean outbound traffic rate.
     - Bytes per second
   * - :guilabel:`Egress packets`
     - Mean outbound packet rate.
     - Packets per second
   * - :guilabel:`Active peers`
     - Current number of active peers.
     - Count
   * - :guilabel:`Peer registrations`
     - Number of peers registered.
     - Count
   * - :guilabel:`Peer removals`
     - Number of peers removed.
     - Count
   * - :guilabel:`Stale peers reaped`
     - Number of inactive peers removed automatically.
     - Count

When traffic uses more than one IP family, the section also shows a
:guilabel:`By IP family` table with the throughput and share of traffic
for each family. To learn more about egress, see
:ref:`agent-engine-network-egress`.

Breakdowns
~~~~~~~~~~

The :guilabel:`Breakdowns` section shows how usage is distributed. The
section includes the following tables:

- :guilabel:`By model`: Token usage and share for each model.
- :guilabel:`By pod type`: Total runtime for each pod type and its
  percentage of the combined runtime of all pod types. The 
  orchestration engine and memory server accrue runtime even when idle.
- :guilabel:`By tool`: Number of calls and error rate for each tool.
- :guilabel:`Compute by workspace`: CPU usage and share for each
  workspace. This table is available only in the project-wide view
  when you show the :guilabel:`Compute` section.
- :guilabel:`By workspace`: Token usage and share for each workspace.
  Deployed workspaces with no usage show ``0``. This table is available
  only in the project-wide view.

Empty and Error States
----------------------

The page shows the following messages when data is not available
depending on the cause:

- :guilabel:`No metrics in this time range`: No metrics exist for the
  :guilabel:`1h` or :guilabel:`24h` period. Select a longer period, or
  invoke an agent.
- :guilabel:`No metrics yet`: No metrics exist for the :guilabel:`7d`
  or :guilabel:`30d` period. Metrics appear after agents run in the
  project.
- :guilabel:`No data in this time range`: A section or table has no
  data for the selected period. Select a longer time period, or invoke
  an agent that uses the selected feature.
- :guilabel:`Monitoring data isn't available in this environment yet`:
  Monitoring is not configured for your environment. To learn more,
  see :ref:`agent-engine-monitor`.
- :guilabel:`Monitoring data couldn't be loaded`: The page or a
  section was unable to load data. The page retries automatically.
