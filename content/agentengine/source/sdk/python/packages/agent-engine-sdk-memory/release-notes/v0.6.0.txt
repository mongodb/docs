agent-engine-sdk-memory v0.6.0
==============================

What's new
----------

- Custom memory types.
  ``Memory.save(memory_type, content, tags=..., contextual_metadata=...)``
  and ``Memory.retrieve(memory_type, query, tags=..., top_k=...)``
  operate on memory types declared in the project's memory
  configuration. Built-in type names are rejected client-side — the
  dedicated per-type methods remain the way to use those. Requests carry
  no identity fields; the platform stamps org, project, and user.
  Platforms that do not serve the custom-type routes, or that have the
  feature disabled, raise ``MemoryNotSupportedError``.
- Error-message extraction now also reads a top-level ``detail`` field
  from error response bodies, so FastAPI-style errors surface their
  message instead of the raw body.
- ``TagScalar`` (the allowed tag value types:
  ``str | int | float | bool``) is exported from the package root.
- Client-side validation failures on ``save`` / ``retrieve`` (built-in
  or empty type names, tag-syntax violations) raise
  ``MemoryClientError``, which now subclasses ``ValueError``, so a plain
  ``except ValueError`` still catches them.

Breaking changes
----------------

- The ``MemoryCrudClient`` protocol gains required ``create_custom`` and
  ``retrieve_custom`` methods. Out-of-tree implementations must add them
  to keep satisfying the protocol — both for type checking and for
  ``isinstance`` checks, since the protocol is ``runtime_checkable``.
