{+atlas-core-full+} is the fully managed cloud database and associated
database, built on the architecture where compute and storage run on
the same node. It is available across {+Free-clusters+},
{+Flex-clusters+}, and dedicated cluster tiers.

To learn about different database editions and how they compare, see
:ref:`atlas-editions`. For a side-by-side view, see
the :ref:`edition comparison diagram <atlas-infinite-vs-core>`.

Existing |service| cluster documentation describes {+atlas-core-full+}
by default. This page is the starting point for {+atlas-core-full+} and
helps you identify which edition existing content applies to.

Architecture
------------

{+atlas-core-cluster+}s provision compute and storage in a
coupled fashion. Each data-bearing node runs on a virtual machine with
attached storage.

Architectural Characteristics
-----------------------------

The following characteristics describe how {+atlas-core-full+}
provisions and scales resources:

- **Compute scales by cluster tier**: You change a node's compute
  capacity by selecting a different cluster tier. Compute capacity and
  storage capacity are coupled on the same node, so {+service+} restarts
  the cluster's nodes when you change the tier. On dedicated clusters,
  {+service+} performs a rolling restart with no expected downtime.
- **{+service+} provisions storage per cluster**: {+service+} provisions
  storage capacity for the cluster, and your application can use that
  capacity at any time.
- **Storage limits depend on the cluster tier**: You scale a node's
  storage capacity and IOPS independently of its compute capacity on
  dedicated clusters, up to the maximum storage capacity for the cluster
  tier. To add storage capacity beyond that maximum, you scale the
  cluster to a higher tier.
- **Node recovery requires an initial sync**: When {+service+} replaces
  a node, the new node performs an initial sync to copy your
  application's data from the other nodes before it serves queries.
- **Large workloads may require sharding**: When your application's data
  approaches the compute or storage capacity of a single shard, you
  shard the cluster to scale horizontally.
- **Analytics, search, and AI workloads run on separate systems**: Each
  workload type runs on its own system with its own copy of the data.
