==================================================
Quick Start for the |k8s-op-short|
==================================================

.. meta::
   :description: Deploy and connect to a MongoDB replica set with the Kubernetes Operator and Ops Manager on a local kind cluster, then move on to a production deployment.

The |k8s-op-full| uses the |k8s| API and tools to manage MongoDB
clusters running within your |k8s| cluster. |k8s-op-short| works together 
with |onprem|. This tutorial demonstrates how to deploy |onprem| on 
|k8s| and then deploy and connect to your first MongoDB replica set 
with |k8s-op-short|. You can use |kind| to quickly set up a cluster.
To learn more, see `Kind <https://kind.sigs.k8s.io/>`_.

Use this tutorial to evaluate |k8s-op-short|. Because |kind| runs a
single node on your local machine, the deployment that you create
here can't survive node loss and isn't sized for production traffic.
After you finish, see :ref:`kind-quick-start-next-steps` to learn how
to move to a production deployment.

Prerequisites
-------------

This tutorial requires:

- A running |k8s| cluster.
- `Helm <https://helm.sh/docs/intro/install/>`_ installed on your 
  local machine.
- |k8s| nodes running on :ref:`supported hardware architectures
  <k8s-supported-hardware-arch-compatibility>`.
- The |mongo-shell| installed on your local machine.

If you use |kind| with Docker Desktop, allocate at least **8 GB of 
memory** and **4 CPUs** in the Docker Desktop resource settings. 
|onprem| requires a minimum of 5 GB of memory for the application 
and additional resources for the {+appdb+} and the |k8s-op-short|.

Next Steps
----------

The deployment that you created runs on a single |kind| node and uses
the default resource settings. To move from this evaluation
deployment to a production deployment, follow this path:

1. :ref:`Plan the production deployment
   <plan-k8s-operator-install>` to choose an architecture, confirm
   version compatibility, and set the |k8s-op-short| deployment
   scope.
2. :ref:`Install the Kubernetes Operator <install-k8s>` on a
   production |k8s| cluster that has more than one node and a
   ``storageClass`` that supports volume expansion.
3. :ref:`Apply production best practices <k8s-considerations>` for
   storage, persistence, availability zones, and resource limits.
4. :ref:`Secure the deployment <k8s-security>` with |tls|,
   authentication, and encryption at rest.
5. :ref:`Deploy on multiple Kubernetes clusters
   <multi-cluster-overview-ref>` if you must survive the loss of an
   entire |k8s| cluster.
