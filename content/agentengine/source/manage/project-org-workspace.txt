Overview
--------

The {+mdb-ai-platform+} uses a three-tier hierarchy to organize your teams
and agents: organizations contain projects, and projects
contain workspaces. Each tier serves a distinct purpose and scopes
user access and configuration to the appropriate level.

Tier Relationships
------------------

Every project belongs to exactly one organization, and every workspace
belongs to a project in that organization. The following diagram shows this
relationship:

.. code-block:: text
   :copyable: false

   Organization
   └── Project (one or more per organization)
       └── Workspace (one per deployed agent)

Tier Descriptions
-----------------

The following table summarizes each tier:

.. list-table::
   :header-rows: 1
   :widths: 20 45 35

   * - Tier
     - Description
     - Learn More

   * - Organization
     - The top-level container for your teams and resources on the {+platform-short+}.
       Create one organization per company, department, or team that requires
       shared user management across multiple projects.
     - :ref:`agentic-platform-manage-org`

   * - Project
     - A grouping of resources for a specific team or application.
       Each project has its own service accounts and sharing policy. You can
       assign roles at the project level, and organization roles also
       apply within the project.
       Create one project per team or application area.
     - :ref:`agentic-platform-manage-projects`

   * - Workspace
     - The runtime environment for a single deployed agent within a
       project. Each workspace holds the settings specific to one agent,
       which include the agent framework, LLM model, enabled tools,
       agent card, GitOps source, and toggles for optional features
       such as memory and guardrails.
     - :ref:`agentic-platform-manage-workspaces`
