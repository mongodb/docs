=============================================
MongoDB {+atlas-infinite-full+} Cluster Costs
=============================================

.. default-domain:: mongodb

.. facet::
   :name: genre
   :values: reference

.. meta::
   :description: Understand Atlas Infinite billing, where compute, storage, backup, and data transfer are metered independently so each layer scales and bills on its own.

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

{+atlas-infinite-full+} meters compute, storage, and backup as
independent dimensions. |service| bills you for what you consume in
each dimension, metered hourly.

You incur {+atlas-infinite-full+} costs for the following items:

- Compute
- Storage
- Backup
- Data Transfer

To learn more about {+atlas-infinite-full+}, see
:ref:`atlas-infinite-edition`.

For supported configurations, see :ref:`atlas-infinite-availability`.

Compute Costs for {+atlas-infinite-full+}
-----------------------------------------

{+atlas-infinite-full+} meters compute per highly available shard (HA
shard). An HA shard is a two-node compute billing unit that consists of
a primary and a standby. {+atlas-infinite-full+} uses this node pair to
provide high availability. An HA shard is an {+atlas-infinite-full+}
billing unit only, and is distinct from a MongoDB :term:`shard`. In
addition to each HA shard, {+atlas-infinite-full+} meters any additional
nodes that you add.

|service| meters compute hourly, based on the configured cluster tier of
the HA shards and any additional nodes. |service| bills compute
independently of storage, so you can resize compute without changing
your storage costs.

|service| bills compute for your provisioned nodes even when the cluster
is idle.

Storage Costs for {+atlas-infinite-full+}
-----------------------------------------

{+atlas-infinite-full+} stores all of your data in a managed storage
layer. All compute nodes, including transactional and workload-specific
(for example, read-only or analytical) nodes, share this storage layer.

|service| meters storage hourly by the volume of uncompressed logical
data that you store, measured in gigabyte-hours (GB-hours). Because
storage is decoupled from compute, |service| bills storage independently
of the compute nodes that run your queries.

On an {+atlas-infinite-cluster+}, storage includes the data inserted and
stored in your database {+cluster+} and the oplog collection,
``local.oplog.rs``.

To learn how the oplog behaves on an {+atlas-infinite-cluster+}, see
:ref:`atlas-infinite-oplog`.

Backup Costs for {+atlas-infinite-full+}
----------------------------------------

|service| bills backup storage on {+atlas-infinite-full+} edition as a
separate billing dimension, independent of compute and of your primary
storage. |service| meters backup hourly by the volume of uncompressed
storage that your backups consume, measured in gigabyte-hours
(GB-hours).

{+atlas-infinite-full+} includes 24 hours of continuous cloud backup at
no additional cost. If you extend backup retention beyond the default
24-hour window, |service| bills the additional backup storage that your
retained snapshots or incremental changes consume. |service| bills
this retained history as backup, not as cluster storage.

Data Transfer Costs for {+atlas-infinite-full+}
-----------------------------------------------

|service| charges for data transfer on {+atlas-infinite-cluster+}s,
following the same data transfer billing as other |service| clusters.
To learn more, see :ref:`data-transfer-costs`.

|service| doesn't charge for data that {+atlas-infinite-full+} replicates
within the storage layer. Because the storage layer manages replication,
backup, and recovery internally, this internal data movement doesn't
count toward your data transfer costs.
