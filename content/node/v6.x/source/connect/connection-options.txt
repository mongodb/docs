Overview
--------

This page describes the connection options available in the {+driver-short+}
and explains how to apply them to your MongoDB connection.

How to Specify Connection Options
---------------------------------

The following sections describe how you can specify connection options by
using a connection string or a ``MongoClientOptions`` object.

.. _node-connection-options-uri:

Use the Connection String
~~~~~~~~~~~~~~~~~~~~~~~~~

You can include connection options in a connection string as
``<name>=<value>`` pairs. Pass the connection string to the ``MongoClient``
constructor. In the following example, the connection string contains the
``connectTimeoutMS`` option with a value of ``60000`` and the ``tls`` option
with a value of ``true``:

.. literalinclude:: /includes/connect/connection-options.js
   :language: javascript
   :dedent:
   :start-after: start-uri-connect-options
   :end-before: end-uri-connect-options
   :copyable: true

To learn more about connection string options, see
:ref:`Connection String Options <connections-connection-options>` in the
{+mdb-server+} manual.

.. _node-connection-options-client:

Use the MongoClientOptions Object
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

You can pass a ``MongoClientOptions`` object to the ``MongoClient``
constructor to configure connection settings in code. Configuring the
connection this way makes it easier to change settings at runtime and
helps you catch errors during compilation. This approach also provides
more configuration options than the connection string.

The following example sets the ``connectTimeoutMS`` option to ``60000``
milliseconds and enables TLS:

      Specify the Client Certificate Key File
      ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

      The ``tlsCertificateKeyFile`` option specifies the path to the client

      **Data Type:** ``string``

      **Default Value:** ``null``

      **Example:**

      to decrypt the client private key used for TLS connections.

      **Data Type:** ``string``

      **Default Value:** ``null``

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript
         :dedent:

      Allow Invalid Certificates
      ~~~~~~~~~~~~~~~~~~~~~~~~~~

      The ``tlsAllowInvalidCertificates`` option specifies whether the
      driver generates an error when the server's TLS certificate is
      invalid. Set this option to ``true`` for testing purposes only.

      **Data Type:** ``boolean``

      **Default Value:** ``false``

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript
         :dedent:
         :start-after: start-uri-tls-allow-invalid-certs
         :end-before: end-uri-tls-allow-invalid-certs
         :copyable: true

      Allow Invalid Hostnames
      ~~~~~~~~~~~~~~~~~~~~~~~

      The ``tlsAllowInvalidHostnames`` option specifies whether the driver
      generates an error when there is a mismatch between the server's
      hostname and the hostname specified by the TLS certificate. Set this
      option to ``true`` for testing purposes only.

      **Data Type:** ``boolean``

      **Default Value:** ``false``

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript
         :dedent:
         :start-after: start-uri-tls-allow-invalid-hostnames
         :end-before: end-uri-tls-allow-invalid-hostnames
         :copyable: true

      Relax TLS Constraints
      ~~~~~~~~~~~~~~~~~~~~~

      The ``tlsInsecure`` option relaxes TLS constraints as much as
      possible, such as allowing invalid certificates or hostname
      mismatches. Set this option to ``true`` for testing purposes only.

      **Data Type:** ``boolean``

      **Default Value:** ``false``

         :language: javascript
         :dedent:

      Socket Timeout
      ~~~~~~~~~~~~~~

      .. sharedinclude:: dbx/connection-options/socketTimeout.rst

      If a MongoDB process fails with an error or the network connection
      drops, you might not receive confirmation that the driver closed
      the corresponding socket. To ensure that the driver closes the
      socket in these cases, set the ``socketTimeoutMS`` option. Select
      a value for ``socketTimeoutMS`` that is two to three times longer
      than the expected duration of your slowest operation.

      **Data Type:** non-negative ``number``

      **Default Value:** ``0`` (no timeout)

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript

      Zlib Compression Level
      ~~~~~~~~~~~~~~~~~~~~~~

      The ``zlibCompressionLevel`` option sets the compression level for
      ``zlib`` to use. This option accepts an integer value between ``-1``
      and ``9``:

      - ``-1``: Default compression level.
      - ``0``: No compression.
      - ``1``: Fastest speed but lowest compression.
      - ``9``: Best compression but slowest speed.

      **Data Type:** ``number`` between ``-1`` and ``9`` (inclusive)

      **Default Value:** ``-1``

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript
         :dedent:
         :start-after: start-uri-zlib-level
         :end-before: end-uri-zlib-level

Write Concern Options
---------------------

.. tabs::

   .. tab:: Connection String
      :tabid: connection-string

      Write Concern
      ~~~~~~~~~~~~~

      .. sharedinclude:: dbx/connection-options/wConcern.rst

      You can also set the following options in the connection string to
      complete the write concern:

      - ``journal``: specifies whether the driver waits for the server to
        group commit to the journal file on disk.
      - ``wtimeoutMS``: specifies a time limit for the write concern.

      To learn more, see :manual:`Write Concern
      </reference/write-concern/>` in the {+mdb-server+} manual.

      **Data Type:**

      - ``w`` option: ``number`` or ``string``
      - ``journal`` option: ``boolean``
      - ``wtimeoutMS`` option: non-negative ``number``

      **Default Value:**

      - ``w`` option: ``1``
      - ``journal`` option: depends on the
        ``writeConcernMajorityJournalDefault`` replica set
        configuration setting
      - ``wtimeoutMS`` option: ``0`` (no timeout)

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript
         :dedent:
         :start-after: start-uri-write-concern
         :end-before: end-uri-write-concern
         :copyable: true

   .. tab:: Client Options
      :tabid: client-options

      Write Concern
      ~~~~~~~~~~~~~

      The ``writeConcern`` option specifies the level of acknowledgement
      requested from MongoDB for write operations, including the time
      limit.

      To learn more, see :manual:`Write Concern
      </reference/write-concern/>` in the {+mdb-server+} manual.

      The ``MongoClientOptions`` type also defines top-level ``w``,
      ``wtimeoutMS``, and ``journal`` options. These top-level options
      are deprecated. Set the properties on the ``writeConcern`` option
      instead, as shown in the example below.

      **Data Type:** ``WriteConcern`` or ``WriteConcernSettings`` object

      **Default Value:** ``w: 1``

      **Example:**

      .. literalinclude:: /includes/connect/connection-options.js
         :language: javascript
         :dedent:
         :start-after: start-client-write-concern
         :end-before: end-client-write-concern
         :copyable: true

      ~~~~~~~~~~~~~~~~

      The ``enableUtf8Validation`` option specifies whether the driver
      validates UTF-8 characters when it deserializes BSON documents
      from MongoDB. If you enable validation, the driver throws a
      ``BSONError`` when it reads data that contains invalid UTF-8
      characters. Disable UTF-8 validation only as a temporary
      workaround to query or export data.

      To learn more about UTF-8 characters, see `UTF-8
      <https://en.wikipedia.org/wiki/UTF-8>`__ on Wikipedia.

      **Data Type:** ``boolean``

      **Default Value:** ``true``

      SOCKS5 Proxy
      ~~~~~~~~~~~~

      You can route connections through a SOCKS5 proxy by setting the
      ``proxyHost`` option to the proxy's IPv4 address, IPv6 address, or
      domain name. The ``proxyPort`` option specifies the TCP port number
      of the proxy server. To authenticate to the proxy server, set the
      ``proxyUsername`` and ``proxyPassword`` options. If you omit the
      ``proxyPort`` option, the driver uses ``1080``. If you set one of
      the ``proxyUsername`` or ``proxyPassword`` options, you must set
      both. To learn more, see :ref:`node-socks`.

      **Data Type:**

        ``proxyPassword`` options
      - non-negative ``number`` for the ``proxyPort`` option

      Keep Alive Initial Delay
      ~~~~~~~~~~~~~~~~~~~~~~~~

      The ``keepAliveInitialDelay`` option specifies the number of
      milliseconds that the driver waits before initiating a
      :wikipedia:`Transmission Control Protocol (TCP) keepalive
      <Keepalive#TCP_keepalive>` on a socket. When the driver sends TCP
      keepalives, it checks whether the connection is active by sending
      periodic pings to your MongoDB deployment. This functionality
      works only if your operating system supports the
      ``SO_KEEPALIVE`` socket option. This option is not supported in a
      connection string.

      Driver version 5.3 deprecated the ``keepAlive`` option. As of
      driver version 6.0, the driver always sets ``keepAlive`` to
      ``true``.

      .. warning::

         If your firewall ignores or drops the keepalive messages, you
         might not be able to identify dropped connections.

      **Data Type:** non-negative ``number``

      **Default Value:** ``120000`` milliseconds (120 seconds)
