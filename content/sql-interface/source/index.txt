.. |interface| replace:: SQL Interface

The {+sql-interface+} for {+service+} and {+ea+}
lets non-developers query MongoDB data from the SQL tools they already use.
It provides live, read-only access over standard |odbc| and |jdbc| connections,
eliminating the need to learn {+mql+} or move data out of MongoDB for analytics.
This simplifies operational reporting, accelerates insights, and ensures data
remains accurate and consistent.

You can deploy the {+sql-interface+} three ways: directly on an
{+service+} {+dedicated-cluster+}, through an {+service+} {+fdi+}, or
on a self-managed {+ea+} deployment. For direct SQL access to a single
{+service+} {+cluster+}, use a {+dedicated-cluster+}. This is the
recommended path for most {+service+} connections, and it requires no
{+fdi+}. Use a {+fdi+} when a single SQL query must span more than one
data source, such as multiple {+clusters+} or |s3| buckets.

All three options provide live, read-only access and use the
{+asql+} dialect, which is SQL-92 compatible. You cannot use the
{+sql-interface+} to insert, update, or delete documents on any
deployment, and the {+sql-interface+} does not support other SQL
dialects.

{+sql-interface+} Components
----------------------------

The {+sql-interface+} deployment consists of four components:

- Your |bi| visualization and reporting tool used to analyze data, such as
  `Tableau <https://www.tableau.com/>`__ or
  `Power BI <https://www.microsoft.com/en-us/power-platform/products/power-bi>`__.

- A |jdbc| or |odbc| driver that connects your |bi| tool to your MongoDB database.
  The driver you select depends on your |bi| tool.

- JSON schema are required to translate SQL queries between your |bi| tool
  and MongoDB database. For {+fdi+}s, schema management is built into the
  {+atlas-ui+}. For {+dedicated-clusters+} and for self-managed {+ea+}
  deployments, you download the {+schema-builder+} as a CLI tool. To learn
  more, see :ref:`sql-schema-management`.

- A MongoDB database where your data resides, either an {+service+} cluster or a
  self-managed EA database.


Key Benefits of the {+sql-interface-full+}
-----------------------------------------

**Schema Improvements**
   Experience significantly improved schema integration. Schema
   computations adapt to your data and represent your collections
   natively. Schemas aren't cached and you can refresh them at any time
   without impacting connectivity.

**Simple & Secure** 
   Enjoy a simplified setup with no complex proxy configurations, allowing you 
   to connect directly to your MongoDB cluster. It offers robust authentication 
   with support for X509 and OIDC protocols.

**First-class SQL Experience**
   Leverage rich objects and arrays with native driver support, enhancing your 
   data interactions. Server restarts are seamless, ensuring uninterrupted 
   operations and high availability. The interface uses {+asql+}, a 
   MongoDB-Native SQL-92 compatible dialect, which supports complex transformations 
   like flattening nested objects and unwinding arrays directly within SQL queries.

**Unified Access**
   Provides the same drivers, connectors, and schema mapping for {+fdi+}s,
   {+dedicated-clusters+}, and self-managed EA databases.

**BI Tool Integration**
   The Power BI Connector is certified by Microsoft and the Tableau Connector
   is developed in partnership with Tableau. It supports Power BI with
   DirectQuery and Tableau Desktop, Tableau Server, Tableau Prep, and
   Tableau Cloud. Tableau Cloud supports SCRAM authentication only.

MongoDB {+sql-interface+} Compatibility Considerations
------------------------------------------------------

When using the {+sql-interface+}, consider the following points to ensure 
your setup is compatible and up-to-date:

* There is no official :abbr:`EOL (End of Life)` for {+sql-interface+} components,       
  including drivers, connectors, and the {+schema-builder+}.
  Instead, their lifecycle is tied to the compatibility of the MongoDB server versions 
  and language runtimes they are designed to work with.

* {+sql-interface+} components
  remain compatible with a MongoDB server version for up to 3 years after that server 
  version's :abbr:`EOL (End of Life)`. To learn more, see 
  `MongoDB Software Lifecycle Schedules <https://www.mongodb.com/legal/support-policy/lifecycles>`__.

* We recommend upgrading your {+sql-interface+} components to the latest version, 
  especially when upgrading your MongoDB server. This ensures access to new features, 
  performance enhancements, and long-term compatibility. To see the latest versions, 
  go to the `MongoDB download center <https://www.mongodb.com/try/download/sql-interface>`__.

* Later versions of {+sql-interface+} components might drop support for earlier
  MongoDB server versions. We recommend reviewing
  the :ref:`sql-release-notes` to stay informed about compatibility changes and
  upgrade requirements.

Legacy Options
--------------

The |bic-full| is the legacy tool for connecting |bi| analytics tools to a MongoDB 
database or cluster. The |bic-short-no-link| reaches **End-of-Life (EOL) in September 2026**.
