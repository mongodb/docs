===========================================
MongoDB Atlas: Multi-Cloud Database Service
===========================================

.. default-domain:: mongodb

.. meta::
   :keywords: overview, atlas core, atlas infinite, editions, compare
   :description: MongoDB Atlas is a fully managed multi-cloud database service that simplifies deploying, managing, and scaling your databases on AWS, Azure, and Google Cloud.

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

|service-fullname| is a multi-cloud database service that simplifies 
deploying and managing your databases while offering the versatility 
you need to build resilient and performant global applications on the 
cloud providers of your choice.

|service| runs your databases on |aws|, |azure|, and |gcp|, and
handles the operational work of running them: provisioning, patching,
backup, monitoring, and scaling. You interact with your data through
the MongoDB Query API, so your application code, drivers, and tools
work the same way that they do against a self-managed deployment.

|service| offers two database editions, {+atlas-core-full+} and
{+atlas-infinite-full+}, which differ in how they manage compute and
storage. To understand the differences and choose between them, 
see :ref:`atlas-editions`.

What You Can Do with Atlas
--------------------------

|service| makes it easy to deploy and manage databases on-demand when
and where you need them. With |service|, you can:

- **Build AI-powered features**: Semantic search, RAG, and agents with
  automatic embeddings all run on your existing operational data.
- **Run transactional workloads at scale**: Flexible document modeling
  and elastic scaling handle both steady growth and traffic spikes.
- **Search and analyze live data where it lives**: Full-text, vector,
  and hybrid search plus real-time analytics run directly on |service|
  data, no separate systems to sync or manage.
- **Deploy anywhere with enterprise-grade security and resilience**: 
  Multi-cloud, multi-region, and built-in compliance controls support
  complex business needs, coupled with automated backups, self-healing,
  and automatic failover.
- **Scale from prototype to production on one platform**: The same APIs,
  drivers, and tools are available all the way from free tiers to scaled
  deployments.

Features
~~~~~~~~
|service| includes a mature feature set of services and capabilities designed
for scalability, integrations, and AI-centric workflows that you
can add as needed without having to deploy and maintain separate systems:

- Build :ref:`full-text search <atlas-search>` and 
  :ref:`Vector Search <avs-overview>` on your operational data so that RAG,
  recommendations, and AI agents work against the same data, indexes, and
  security model as the rest of the app.
- Drive your app's retrieval capacity with :ref:`Voyage AI <voyage-landing>`
  embedding models and APIs that turn data into high-accuracy vectors natively
  in the platform.
- :ref:`Automate embeddings <avs-auto-embeddings-overview>` with no need
  for pipelines or machine learning expertise, generated by MongoDB and updated
  automatically so AI agents can access accurate contextual information
  in real time.
- Orchestrate agents using a precise semantic search interface with 
  :ref:`long-term memory store <langgraph-js-long-term-memory>` integration
  and :ref:`lexical prefilters <fts-vectorSearch-ref>`.
- Use :ref:`Atlas Stream Processing <atlas-sp-overview>` to read, write, and
  transform streams of complex data as it arrives.

.. _atlas-editions:

Database Editions
-----------------

|service| offers two database editions. Both editions run MongoDB and
use the same interface, drivers, APIs, and most operational workflows.
They differ in how they provision compute and storage:

- **{+atlas-core-full+}**: the |service| cluster architecture where
  compute and storage run on the same node. It is available across
  {+Free-clusters+}, {+Flex-clusters+}, and dedicated cluster tiers.
- **{+atlas-infinite-full+}**: an architecture that separates compute
  from storage into independent layers, designed for mission-critical
  high-performance use cases. {+atlas-infinite-full+} is available as a
  public preview, and both the product and its documentation might
  change during the preview period.

The following diagram compares the two editions.

Compare Editions
~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 20 40 40

   * - Aspect
     - {+atlas-core-full+}
     - {+atlas-infinite-full+}

   * - Architecture
     - Compute and storage run on the same node. Each data-bearing
       node runs on a virtual machine with attached storage.
     - Compute and storage run as independent layers. MongoDB manages
       the storage layer separately from the compute nodes.

   * - Compute scaling
     - You change compute capacity by selecting a different cluster
       tier. {+service+} restarts the cluster's nodes when you change
       the tier, with no downtime on dedicated clusters.
     - You scale the cluster tier independently of storage. Scaling
       doesn't move your data, so it is fast.

   * - Storage scaling
     - You scale storage capacity and IOPS independently of compute on
       dedicated clusters, up to the maximum for the cluster tier. To
       add capacity beyond that maximum, you scale to a higher tier.
     - Storage capacity increases automatically based on usage,
       independently of the cluster tier, without downtime.

   * - Horizontal scaling
     - You shard a cluster when its data approaches the storage capacity,
       and add workload-specific nodes, like read-only or analytics nodes,
       as needed.
     - Higher storage capacity means you can store up to 128TB on a single
       shard without sharding. Adding workload-specific nodes is much faster. 

   * - Recovery
     - {+service+} monitors your database regularly, and performs auto-healing
       if it discovers an issue. If it replaces a node, the new node performs
       an initial sync before it serves queries.
     - {+service+} monitors your database regularly, and performs auto-healing
       if it discovers an issue. If it replaces a node, the new node immediately
       connects to the storage layer, with no need for an initial sync.

   * - Cloud provider and tier availability
     - {+Free-clusters+}, {+Flex-clusters+}, and dedicated cluster
       tiers, on AWS, Azure, and Google Cloud.
     - Public preview: ``M10`` through ``M60`` replica sets in
       supported AWS regions, with storage capacity up to 128 TB per
       replica set.

   * - Feature coverage
     - Supports the full |service| feature set.
     - Some |service| features aren't :ref:`supported during public
       preview <atlas-infinite-availability>`.

Choose an Edition
~~~~~~~~~~~~~~~~~

Consider :ref:`{+atlas-core-full+} <atlas-core-edition>` when: 

- You want the full |service| feature set
- You need multi-region or multi-cloud clusters (coming soon to
  {+atlas-infinite-full+})
- You need sharded clusters (coming soon to {+atlas-infinite-full+})

Consider :ref:`{+atlas-infinite-full+}
<atlas-infinite-edition>` when: 

- You want to scale compute and storage independently
- Your workload has spikes that are difficult to preprovision for
- You want to grow storage capacity without scaling the cluster tier
- You want faster failover and recovery

Confirm that your workload fits the :ref:`public preview
limitations <atlas-infinite-availability>` first.

The :ref:`{+atlas-infinite-full+} architecture
<atlas-infinite-architecture>` describes how the compute and storage
layers interact.
