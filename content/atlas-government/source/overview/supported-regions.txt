=====================================
Supported Cloud Providers and Regions
=====================================

.. meta::
   :description: Explore the supported regions for deploying MongoDB Atlas for Government clusters on AWS GovCloud, AWS Commercial, Azure Government, and Google Cloud with Assured Workloads.

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

.. include:: /includes/considerations/gov-commercial-regions.rst

|cloudgov-short| regions are certified at one of the following
|fedramp| compliance levels:

- **{+fedramp-d+}**: |aws-fr-high| (US) regions, |gaw| (US)
  regions, and |azure-gov| (US) regions. {+fedramp-d+} was formerly called FedRAMP® High.

- **{+fedramp-c+}**: |aws-fr-moderate| (US) regions.


AWS GovCloud
------------

|aws| GovCloud regions meet more stringent U.S. government security
requirements. To learn more, see the
`AWS GovCloud documentation <https://aws.amazon.com/govcloud-us>`__.

You can deploy an |cloudgov-short| cluster in the following government
regions:

- Northwestern US (``us-gov-west-1``)

- Eastern US (``us-gov-east-1``)

|aws-fr-moderate|
-----------------

If you leave :guilabel:`FedRAMP Class D (High) - Regions Only`
unselected during project creation, you can deploy an
|cloudgov-short| cluster in the following |aws| {+fedramp-c+}
regions:

- Northern Virginia (``us-east-1``)

- Ohio (``us-east-2``)

- Northern California (``us-west-1``)

- Oregon (``us-west-2``)

.. seealso:: |service| documentation

   Learn more about :atlas:`Cloud Providers and Regions </cloud-providers-regions>`

.. _atlasgov-azure-government:

Azure Government
----------------

|azure-gov| provides dedicated cloud regions for U.S. government
agencies and the partners that serve them. To learn more, see the
`Azure Government documentation <https://learn.microsoft.com/en-us/azure/azure-government/>`__.

You can deploy an |cloudgov-short| cluster in the following
|azure-gov| regions:

- USGov Virginia

- USGov Texas

- USGov Arizona

.. note::

   .. include:: /includes/facts/azure-gov-m30-minimum.rst

In |azure-gov| regions, |service| deploys clusters across
availability sets with two fault domains rather than across
Availability Zones. In a three-node replica set, two nodes share
a fault domain. To learn more, see :ref:`Azure Fault Domains
<microsoft-azure-fault-domains>` in the |service|
documentation.


.. _atlasgov-gcp-assured-workloads:

Google Cloud Assured Workloads
------------------------------

Assured Workloads is a |gcp| product that allows customers to configure sensitive workloads to support compliance and security requirements.

You can deploy an |cloudgov-short| cluster in GCP with Assured Workloads in all standard US regions.
For an updated list of supported regions, see `Assured Workloads locations <https://cloud.google.com/assured-workloads/docs/locations#us_regions>`__.

.. note::

   When you specify a |gcp| region name with the |service| API (as
   you would with Terraform, for example), you must include the
   suffix ``_AW`` with the region name.

   For example, to specify the |gcp| region ``us-east-1``, pass it
   to the |service| API as ``US_EAST_1_AW``.
