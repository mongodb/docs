   .. _auto-embedding-enable-disable:

   Enable or Disable Automated Embedding 
   -------------------------------------

   .. selected-content::
      :selections: atlas

      To enable Automated Embedding, you must create a {+avs+} index with 
      the ``autoEmbed`` type. To learn more, see :ref:`Create an Automated 
      Embedding Index <avs-create-index>`.

      To disable Automated Embedding at the organization level, use an
      :ref:`{+arp+} <atlas-resource-policies-overview>`. You can
      disable Automated Embedding entirely or disable it with project-level
      exceptions.

      To disable Automated Embedding entirely, use the following syntax in your {+arp+}:

      .. code-block:: text
         :copyable: true

         forbid (
           principal,
           action == ResourcePolicy::Action::"search.index.modify",
           resource
         )
         when {
           context.search.index.isAutoEmbed
         };

      To disable Automated Embedding with exceptions for specific projects,
      use the following syntax in your {+arp+}. Replace each ``<project-id>`` with
      the ID of the project to exempt. To find your project ID, see:
      :ref:`atlas-modify-project-settings`.

      .. code-block:: text
         :copyable: true

         forbid (
           principal,
           action == ResourcePolicy::Action::"search.index.modify",
           resource
         )
         when {
           context.search.index.isAutoEmbed
         }
         unless {
           resource in ResourcePolicy::Project::"<project-id-1>" ||
           resource in ResourcePolicy::Project::"<project-id-2>"
         };

      When active, these policies prevent new ``autoEmbed`` type indexes
      from being created. Indexes created before the resource policy was
      activated are not affected and must be deleted manually to maintain
      compliance.

      To apply this policy to your organization:

      .. procedure::
         :style: normal

         .. step:: In |service|, go to the :guilabel:`Organization Settings` page.

            a. If it's not already displayed, select your desired
               organization from the |ui-org-menu| in the navigation bar.

            #. In the sidebar, click :guilabel:`Organization Settings`.

         .. step:: Go to the :guilabel:`Resource Policies` page.

            In the sidebar, click :guilabel:`Resource Policies` under
            the :guilabel:`Configurations` header.

         .. step:: Click :guilabel:`Create policy`.

         .. step:: Name, describe, and define your policy.

            a. Give the policy a unique name.
            #. (Optional) Add a description.
            #. In the :guilabel:`Cedar Policy` field, paste the Cedar
               policy. Replace ``<project-id>`` with your project ID.

         .. step:: Click :guilabel:`Create policy`.

   .. selected-content::
      :selections: self

      To enable Automated Embedding, you must do the following: 

      .. procedure::

         .. step:: Create a {+voyageai+} API key for indexing operations.

            To learn more, see :ref:`voyage-api-keys`.

            To learn more, see :ref:`voyage-api-keys`.

         .. step:: Configure ``mongot`` to use the API keys.

            To learn more, see :ref:`voyage-api-key-for-auto-embed`.

         .. step:: Create an ``autoEmbed`` type {+avs+} index.

            To learn more, see :ref:`Create an Automated Embedding Index <avs-types-vector-search>`.

   .. _auto-embed-inference-scope:

   Configure the Inference Scope
   -----------------------------

   The inference scope controls where |service| runs embedding model
   inference for the Automated Embedding indexes on a cluster. By default,
   inference can run in any cloud provider and geography. If you need to
   keep the processing of your text inside a specific geography, set the
   inference scope of your cluster to the United States (``US``) or Europe
   (``EU``).

   .. important::

      Inference scoped to the United States is Generally Available.
      Inference scoped to Europe is in Preview and isn't recommended for 
      production workloads. The Preview feature and the corresponding 
      documentation might change at any time during thePreview period. 
      To learn more, see `Preview Features
      <https://www.mongodb.com/docs/preview-features/>`__.

   .. selected-content::
      :selections: atlas

      Considerations
      ~~~~~~~~~~~~~~

      Before you change the inference scope, review the following
      behavior:

      - You can configure the inference scope only for dedicated clusters.
        You can't configure it for {+Free-cluster+}s or {+Flex-cluster+}s.
      - Each cluster has its own inference scope. The scope applies to all
        existing and new Automated Embedding indexes on the cluster.
      - |service| doesn't re-embed your data when you change the scope.
        Existing embeddings remain queryable. The new scope applies to text
        that |service| processes after the change completes, including
        index-time and query-time embedding generation.
      - Some embedding models might not be available in a scoped geography.
        If an existing index on the cluster uses a model that the new scope
        doesn't support, |service| rejects the update. Similarly, you can't
        create an index that uses a model that the current scope doesn't
        support.
      - Inference scoped to a specific geography is billed at 1.1 times the
        rate for unscoped inference, which can run in any geography. To learn
        more, see :ref:`auto-embed-scoped-inference-pricing`.

      Required Access
      ~~~~~~~~~~~~~~~

      To view the inference scope, you must have :authrole:`Project Read Only`
      access or higher to the project. To change the inference scope, you
      must have :authrole:`Project Search Index Editor` access or higher to
      the project.

      Procedure
      ~~~~~~~~~

      To view and change the inference scope, use the {+atlas-ui+}, the
      {+atlas-cli+}, or the {+atlas-admin-api+}.

      Each scope has a ``cloud`` and a ``geography`` value, which you set
      together. The following table lists the combinations that you can set:

      .. list-table::
         :header-rows: 1
         :widths: 20 20 60

         * - ``cloud``
           - ``geography``
           - Description

         * - ``ANY``
           - ``ANY``
           - Inference can run in any cloud provider and geography. This
             is the default.

         * - ``ANY``
           - ``EU``
           - Inference runs in Europe.

         * - ``ANY``
           - ``US``
           - Inference runs in the United States.

      .. tabs:: 

         .. tab:: Atlas UI
            :tabid: atlas-ui

            .. include:: /includes/crud-embeddings/automated/procedures/steps-auto-embed-configure-inference-scope-ui.rst

         .. tab:: Atlas CLI
            :tabid: atlas-cli

            .. include:: /includes/crud-embeddings/automated/procedures/steps-auto-embed-configure-inference-scope-acli.rst

         .. tab:: Atlas Administration API
            :tabid: atlas-api

            The ``autoEmbeddingInference`` resource stores the inference scope in
            the following fields:

            - ``configured`` contains the scope that you set.
            - ``effective`` contains the read-only scope that |service| applies to
              your cluster.

      .. include:: /includes/crud-embeddings/automated/procedures/steps-auto-embed-configure-inference-scope-api.rst

   .. selected-content::
      :selections: self

      You can configure the inference scope only for {+service+} clusters.
      The inference scope doesn't apply to self-managed deployments.

   .. _auto-embedding-usage:

   View Automated Embedding Usage
   ------------------------------

   To view aggregated token usage and embedding model requests for 
   Automated Embedding service, you can use {+avs+} dashboard or 
   |service| metrics.

   Monitor Dashboard
   ~~~~~~~~~~~~~~~~~

   .. selected-content::
      :selections: atlas

      .. procedure:: 
         :style: normal

         .. step:: Log in to `{+service+} <https://cloud.mongodb.com>`__.

         .. include:: /includes/nav/steps-search-simple.rst

         .. step:: Click the :guilabel:`Automated Embedding` section if it's not already expanded.

         .. step:: Click :guilabel:`Usage` under :guilabel:`Automated Embedding`.

            The `Automated Embedding Usage <https://cloud.mongodb.com/go?l=https%3A%2F%2Fcloud.mongodb.com%2Fv2%2F%3Cproject%3E%23%2FautoEmbedding%4E%23%2Fusage%2F>`__
            page displays. The :guilabel:`Automated Embedding Usage` page
            displays the following information:

            .. list-table::
               :header-rows: 1
               :widths: 20 80

               * - Section
                 - Description

               * - Usage Summary
                 - Overview of your Automated Embedding usage, including total
                   tokens used and remaining free tokens.

               * - Usage by Model or Index
                 - Breakdown of total token usage by embedding model or selected 
                   index during a selected time period.

               * - Usage by Operation
                 - Breakdown of token requests by operation type (indexing and
                   querying).

         .. step:: Filter the usage data by date range and model.

   .. selected-content::
      :selections: self

      The following procedure only applies to |api| keys created from the 
      {+atlas-ui+}. For |api| keys created directly from |voyage|, see 
      :voyage-docs:`Rate Limits </rate-limits>`.

      .. procedure:: 
         :style: normal

         .. step:: Log in to `{+service+} <https://cloud.mongodb.com>`__.

         .. step:: Go to the Usage page in the Atlas UI.

            a. If it's not already displayed, select your desired organization
               from the :icon-mms:`office` :guilabel:`Organizations` menu in
               the navigation bar.
               
            #. At the organization level, click :guilabel:`Usage` under the 
               :guilabel:`AI Model APIs` header in the navigation bar.

         .. step:: Filter the usage data by date range, project, model, geography, and environment.

         .. step:: View the token usage and embedding model requests for Automated Embedding.

            The :guilabel:`Usage` page displays usage metrics for all model API keys in your 
            organization. The page provides the following tabs:

            - :guilabel:`Usage Activity`: Shows detailed usage metrics and charts for your organization.
            - :guilabel:`Free Usage`: Shows free quota consumption by model.
            - :guilabel:`Paid Usage`: Shows paid usage by model and API key.

            To learn more, see :ref:`Usage Page Features <voyage-usage-page-features>`.

   .. _auto-embed-metrics:

   Monitor Metrics
   ---------------

   .. selected-content::
      :selections: atlas

      To monitor Automated Embedding usage using metrics:

      .. procedure:: 
         :style: normal

         .. step:: Log in to `{+service+} <https://cloud.mongodb.com>`__.

         .. step:: Go to the :guilabel:`Metrics` view for your cluster.

            a. If it's not already displayed, select your desired organization
               from the :icon-mms:`office` :guilabel:`Organizations` menu in
               the navigation bar.

            #. If it's not already displayed, select your desired project
               from the :guilabel:`Projects` menu in the navigation bar.

            #. Click on your cluster name to open the :guilabel:`Cluster` sidebar.

            #. In the sidebar, click :guilabel:`Metrics`.

         .. step:: Select the :guilabel:`Auto Embedding Metrics` to review.

            You can monitor Automated Embedding usage through the following metrics 
            in the :guilabel:`Auto Embedding Metrics` section:

            .. list-table::
               :header-rows: 1 
               :widths: 30 70 

               * - Metric 
                 - Description 
            
               * - :guilabel:`Auto Embedding Index Embedding Request` 
                 - The Auto Embedding Index Embedding Request graph displays the 
                   number of requests to generate embeddings for indexing operations. 
                   Rates are shown for each embedding model in use.

               * - :guilabel:`Auto Embedding Index Tokens` 
                 - The Auto Embedding Index Tokens graph displays the number of tokens
                   used for indexing operations.

               * - :guilabel:`Auto Embedding Query Embedding Request` 
                 - The Auto Embedding Query Embedding Request graph displays the number of
                   requests to generate embeddings for query operations.

               * - :guilabel:`Auto Embedding Query Tokens` 
                 - The Auto Embedding Query Tokens graph displays the number of tokens
                   used for query operations.

               * - :guilabel:`Auto Embedding Replication Lag` 
                 - The Auto Embedding Replication Lag graph displays the replication lag
                   in milliseconds for Automated Embedding indexing operations.

            For each cluster, {+service+} displays a single graph that aggregates
            token usage across all Automated Embedding indexes on the cluster. The
            graph includes token usage from both the initial sync and steady-state
            updates, and displays a separate line for each embedding model that
            your indexes use so you can compare token usage by model.

            If you deployed Search Nodes for workload isolation, {+service+}
            displays this graph in the :guilabel:`Search Nodes` metrics view for
            each Search Node instead of the cluster metrics view.

   .. selected-content::
      :selections: self

      Automated Embedding metrics are not available for self-managed deployments.

   View Rate Limits 
   ~~~~~~~~~~~~~~~~

   .. selected-content::
      :selections: atlas

      To view rate limits for Automated Embedding:

      .. procedure:: 
         :style: normal

         .. step:: Log in to `{+service+} <https://cloud.mongodb.com>`__.

         .. step:: Go to the :guilabel:`Search & Vector Search` page for your project.
               
            a. If it's not already displayed, select your desired organization
               from the :icon-mms:`office` :guilabel:`Organizations` menu in
               the navigation bar.

            #. If it's not already displayed, select your desired project
               from the :guilabel:`Projects` menu in the navigation bar.

               :guilabel:`Database` header.

   .. _auto-embedding-increase-rate-limits:

   Increase Rate Limits
   ~~~~~~~~~~~~~~~~~~~~

   .. selected-content::
      :selections: atlas

      If you are using a free cluster and need to increase rate limits for
      Automated Embedding, add a payment method to upgrade to a paid tier. To
      learn more, see :ref:`atlas-payment-method`.

      If you are on a Paid Tier, rate limits don't increase automatically. To
      increase your rate limits beyond the baseline limits for your project,
      contact `MongoDB Support <https://support.mongodb.com/>`__.

   .. selected-content::
      :selections: self

      For |api| keys created from the {+atlas-ui+}, see :ref:`voyage-rate-limits`. 
      For |api| keys created directly from |voyage|, see 
      :voyage-docs:`Rate Limits </rate-limits>`.
