======================================
Geographies for {+voyageai+} Inference
======================================

.. default-domain:: mongodb

.. meta::
   :keywords: geography, EU inference, data residency
   :description: Learn how to scope Voyage AI inference to the Europe or United States Geography and which endpoint each Geography uses for embedding and reranking requests.

.. contents:: On this page

.. include:: /includes/facts/note-geography-preview.rst

A **Geography** is a named group of cloud provider regions inside
which |service| processes the content that you submit for
inference through the {+voyage-api+}. A Geography is not the same
as the cloud provider region where your |service| cluster runs.
The cluster region governs where |service| stores your cluster's
data, while the inference Geography governs where |service|
processes your content for inference, and you set each one
separately.

When you scope a {+model-api-key+} to a Geography, requests that
use that key run on {+voyageai+} models hosted inside that
Geography. To learn more about the Geography concept, including
the available Geographies and the Designated Services that honor
them, see :atlas:`Geographies and Designated Services in Atlas
</geographies>`.

.. _voyage-geographies-endpoints:

{+voyage-api+} Geography Endpoints
-----------------------------------------------

Each Geography has its own {+voyage-api+} endpoint. The endpoint
that you call must match the Geography that your
{+model-api-key+} is scoped to.

.. include:: /includes/facts/geography-endpoints.rst

To create a key that is not scoped to a Geography, set
``geography`` to ``any``. To learn how keys and endpoints
correspond, see :ref:`voyage-api-overview`.

To learn what a Geography guarantees and how to decide whether
to scope a key to one, see :atlas:`Geographies and Designated
Services in Atlas </geographies>`.
