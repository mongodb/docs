.. _interpret-explain-plan:

==============================
Interpret Explain Plan Results
==============================

.. default-domain:: mongodb

.. facet::
   :name: genre
   :values: reference

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

You can use explain results to determine the following information about
a query:

- The amount of time a query took to complete
- Whether the query used an index
- The number of documents and index keys scanned to fulfill a query

.. note::

   Explain plan results for queries are subject to change between
   MongoDB versions.

.. tabs-drivers::

   tabs:
     - id: shell
       content: |
         The :method:`cursor.explain("executionStats")
         <cursor.explain()>` and the
         :method:`db.collection.explain("executionStats")
         <db.collection.explain()>` methods provide statistics about the
         performance of a query. These statistics can be useful in
         measuring if and how a query uses an index. See
         :method:`db.collection.explain()` for details.

     - id: compass
       content: |
         |compass| provides an :compass:`Explain Plan </query-plan/>`
         modal, which displays statistics about  the performance of a
         query. These statistics can be useful in measuring if and how a
         query uses an index.

Query with No Index
~~~~~~~~~~~~~~~~~~~

            :language: javascript
            :copyable: true
            :category: usage example

         This query matches ``3809`` of the ``21349`` documents in
         the collection.

         To view the query plan selected, chain the
         :method:`cursor.explain("executionStats") <cursor.explain()>`
         cursor method to the end of the :command:`find` command:

         .. io-code-block::
            :copyable: true

            .. input:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/range-explain.snippet.range-explain.js
               :language: javascript
               :category: usage example

            .. output:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/range-explain-no-index-output.sh
               :language: javascript

         - :data:`queryPlanner.winningPlan.stage
           <explain.queryPlanner.winningPlan.stage>` displays
           ``COLLSCAN`` to indicate a collection scan.

           Collection scans indicate that the
           :binary:`~bin.mongod` had to scan the entire collection
           document by document to identify the results. This is a
           generally expensive operation and can result in slow
           queries.

         - :data:`executionStats.nReturned
           <explain.executionStats.nReturned>` displays ``3809`` to
           indicate that the winning query plan returns 3,809
           documents.

         - :data:`executionStats.totalKeysExamined
           <explain.executionStats.totalKeysExamined>` displays ``0``
           to indicate that this query is not using an index.

         - :data:`executionStats.totalDocsExamined
           <explain.executionStats.totalDocsExamined>` displays
           ``21349`` to indicate that MongoDB had to scan all 21,349
           documents in the collection to find the 3,809 matching
           documents.

     - id: compass
       content: |
         The following query retrieves documents where the
         ``year`` field has a value between ``2000`` and ``2005``,
         inclusive:

         Copy the following filter into the Compass query bar and click
         :guilabel:`Find`:

         .. code-block:: javascript

            { year: { $gte: 2000, $lte: 2005 } }

         This query matches ``3809`` of the ``21349`` documents in
         the collection.

         To view the query plan, click :guilabel:`Explain` in the
         query bar.

         |compass| displays the query plan as follows:

         .. figure:: /images/compass-movies-no-index.png
            :alt: Compass no-index query plan for the movies
                  collection
            :figwidth: 600px

         Visual Tree
         ```````````

         - The :guilabel:`Query Performance Summary` shows the
           execution stats of the query:

           - :guilabel:`Documents Returned` displays ``3809`` to
             indicate that the winning query plan returns 3,809
             documents.

           - :guilabel:`Documents Examined` displays ``21349``
             to indicate that MongoDB had to scan all 21,349
             documents in the collection to find the 3,809 matching
             documents.

           - :guilabel:`Index Keys Examined` displays ``0`` to indicate
             that this query is not using an index.


         - |compass| displays the ``COLLSCAN`` query stage to indicate
           that a collection scan was used for this query. Collection
           scans indicate that the :binary:`~bin.mongod` had to scan the
           entire collection document by document to identify the
           results. This is a generally expensive operation and can
           result in slow queries.

         Raw JSON
         ````````

         The :guilabel:`Explain Plan` details can also be viewed in raw
         JSON format by clicking the :guilabel:`Raw Output` option:

         .. figure:: /images/compass-movies-no-index-raw-json.png
            :alt: Compass no-index query plan raw JSON
            :figwidth: 600px

The difference between the number of matching documents and the number
of examined documents may suggest that the query might benefit from the
use of an index to improve efficiency.

Query with Index
~~~~~~~~~~~~~~~~

.. tabs-drivers::

   tabs:
     - id: shell
       content: |
         To support the query on the ``year`` field, add an index
         on the ``year`` field:

         .. literalinclude:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/create-year-index.snippet.create-year-index.js
            :language: javascript
            :copyable: true
            :category: usage example

         To view the query plan statistics, use the
         :method:`~cursor.explain("executionStats")` method:

         .. io-code-block::
            :copyable: true

            .. input:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/range-explain.snippet.range-explain.js
               :language: javascript
               :category: usage example

            .. output:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/range-explain-index-output.sh
               :language: javascript

         - :data:`queryPlanner.winningPlan.inputStage.stage
           <explain.queryPlanner.winningPlan.inputStage>` displays
           ``IXSCAN`` to indicate index use.

         - :data:`executionStats.nReturned <explain.executionStats.nReturned>`
           displays ``3809`` to indicate that the winning query plan
           returns 3,809 documents.

         - :data:`executionStats.totalKeysExamined
           <explain.executionStats.totalKeysExamined>` displays ``3809``
           to indicate that MongoDB scanned 3,809 index entries. The
           number of keys examined match the number of documents
           returned, meaning that the :binary:`~bin.mongod` only had
           to examine index keys to return the results. The
           :binary:`~bin.mongod` did not have to scan all of the
           documents, and only the 3,809 matching documents had to be
           pulled into memory. This results in a very efficient query.

         - :data:`executionStats.totalDocsExamined
           <explain.executionStats.totalDocsExamined>` display ``3809``
           to indicate that MongoDB scanned 3,809 documents.

     - id: compass
       content: |
         To support the query on the ``year`` field, add an index
         on the ``year`` field:

         1. Click the :guilabel:`Indexes` tab for the
            ``sample_mflix.movies`` collection.

         2. Click :guilabel:`Create`, then select :guilabel:`Index` from
            the dropdown menu.

         3. Select ``year`` from the
            :guilabel:`Select or type a field name` dropdown.

         4. Select ``1 (asc)`` from the :guilabel:`Select a type`
            dropdown.

         5. Click :guilabel:`Create Index`.

         .. note::

            Leaving the index name field blank causes |compass| to
            create a default name for the index.

         You can now see your newly created index in the
         :guilabel:`Indexes` tab:

         .. figure:: /images/compass-show-year-index.png
            :alt: Compass showing the year index in the Indexes tab
            :figwidth: 600px

         Return to the :guilabel:`Documents` tab for the
         ``sample_mflix.movies`` collection and re-run the query from
         the previous step:

         .. code-block:: javascript

            { year: { $gte: 2000, $lte: 2005 } }

         Open the :guilabel:`Explain Plan` modal. |compass| displays the query
         plan as follows:

         .. figure:: /images/compass-movies-with-index.png
            :alt: Compass explain plan with the year index
            :figwidth: 600px

         Visual Tree
         ```````````

         - The :guilabel:`Query Performance Summary` shows the
           execution stats of the query:

           - :guilabel:`Documents Returned` displays ``3809`` to
             indicate that the winning query plan returns 3,809
             documents.
           
           - :guilabel:`Documents Examined` displays ``3809`` to
             indicate that MongoDB scanned 3,809 documents.

           - :guilabel:`Index Keys Examined` displays ``3809``
             to indicate that MongoDB scanned 3,809 index entries.
             The number of keys examined match the number of
             documents returned, meaning that the
             :binary:`~bin.mongod` only had to examine index keys to
             return the results. The :binary:`~bin.mongod` did not
             have to scan all of the documents, and only the 3,809
             matching documents had to be pulled into memory. This
             results in a very efficient query.

           - At the bottom of the :guilabel:`Query Performance Summary`,
             |compass| shows that the query used the ``year`` index.

         - To the left of the :guilabel:`Query Performance Summary`,
           |compass| displays the query stages ``FETCH`` and ``IXSCAN``.
           ``IXSCAN`` indicates that the :binary:`~bin.mongod` used an
           index to satisfy the query before executing the ``FETCH``
           stage and retrieving the documents.

         Raw JSON
         ````````

         The explain details can also be viewed in raw JSON format by
         clicking the :guilabel:`Raw Output` option:

         .. figure:: /images/compass-movies-with-index-raw-json.png
            :alt: Compass explain plan with year index raw JSON
            :figwidth: 600px

Without the index, the query scans the entire collection to return
the matching documents. The query also has to scan the entirety of
each document, potentially pulling them into memory. This results in
an expensive and potentially slow query operation.

When run with an index, the query scans only as many index entries
and documents as it returns, resulting in a more efficient query.

      **Compare Performance of Indexes**

      To manually compare the performance of a query using more
      than one index, you can use the :method:`~cursor.hint()`
      method in conjunction with the :method:`~cursor.explain()`
      method.

      Consider the following query:

      .. literalinclude:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/range-rated-query.snippet.range-rated-query.js
         :language: javascript
         :copyable: true
         :category: usage example

      This query matches ``235`` documents.

      To support the query, add a :ref:`compound index
      <index-type-compound>`. With compound indexes, the order
      of the fields matter.

      For example, add the following two compound indexes. The
      first index orders by ``year`` field first, and then the
      ``rated`` field. The second index orders by ``rated`` first,
      and then the ``year`` field.

      .. literalinclude:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/create-compound-indexes.snippet.create-compound-indexes.js
         :language: javascript
         :copyable: true
         :category: usage example

      Evaluate the effect of the first index on the query:

      .. io-code-block::
         :copyable: true

         .. input:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/hint-year-rated.snippet.hint-year-rated.js
            :language: javascript
            :category: usage example

         .. output:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/hint-year-rated-output.sh
            :language: javascript

      MongoDB scanned ``246`` index keys
      (:data:`executionStats.totalKeysExamined
      <explain.executionStats.totalKeysExamined>`) to return ``235``
      matching documents (:data:`executionStats.nReturned
      <explain.executionStats.nReturned>`).

      Evaluate the effect of the second index on the query:

      .. io-code-block::
         :copyable: true

         .. input:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/hint-rated-year.snippet.hint-rated-year.js
            :language: javascript
            :category: usage example

         .. output:: /code-examples/tested/command-line/mongosh/tutorial/analyze-query-plan/hint-rated-year-output.sh
            :language: javascript

      MongoDB scanned ``235`` index keys
      (:data:`executionStats.totalKeysExamined
      <explain.executionStats.totalKeysExamined>`) to return ``235``
      matching documents (:data:`executionStats.nReturned
      <explain.executionStats.nReturned>`).

      The second compound index, ``{ rated: 1, year: 1 }``, is
      therefore the more efficient index for supporting the example
      query, as the MongoDB server only needs to scan ``235``
      :data:`index keys <explain.executionStats.totalKeysExamined>`
      to find all matching documents using this index, compared to
      ``246`` when using the compound index
      ``{ year: 1, rated: 1 }``.
