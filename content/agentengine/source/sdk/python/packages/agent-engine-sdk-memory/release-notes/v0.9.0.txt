agent-engine-sdk-memory v0.9.0
==============================

What's new
----------

- ``Memory.build_context`` and ``Memory.build_context_from_sources``
  accept two new response-shaping options. ``format_style``
  (``"openai"``, ``"claude"``, or ``"jinja2"``; a ``FormatStyle`` enum
  is exported for type annotations) selects the format of the assembled
  context, and invalid values raise ``ValueError`` locally.
  ``include_memories=True`` adds the post-budget list of selected memory
  chunks to the response (``selected_memories``), so you can inspect
  exactly which memories were used, with their ids, sources, and
  similarity scores.
- Both options work on hosted (Gateway) and direct (OE) connections. In
  app-bound mode they raise ``MemoryNotSupportedError`` when set.
- Known server caveat: the server infers the format from its configured
  model when ``format_style`` is omitted, and currently re-infers when
  an explicit value matches its default model type. An explicit
  ``"openai"`` is therefore honored verbatim only on servers with an
  OpenAI-family model configured; ``"claude"`` and ``"jinja2"`` are
  always honored.

Breaking changes
----------------

- Custom ``MemoryRuntime`` implementations: the protocol's
  ``build_context`` and ``build_context_from_sources`` gained the
  optional ``format_style`` and ``include_memories`` parameters. Runtime
  behavior is unchanged (the facade forwards them only when set), but
  type checkers will flag existing implementations until they accept the
  new parameters.
