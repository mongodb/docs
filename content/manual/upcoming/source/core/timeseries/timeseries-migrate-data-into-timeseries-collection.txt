If your collection stores data that you want to compare across time
intervals, use a time series collection to improve performance and storage.
For more information about the benefits of time series collections, see
:ref:`manual-timeseries-collection`.

About this Task
---------------

This page covers migrating data that is already in a MongoDB collection.
If your data is in a relational database, use `Relational Migrator
<https://www.mongodb.com/docs/relational-migrator/>`__ to migrate your
data into a time series collection.

You can use the :pipeline:`$out` aggregation stage to migrate data from an
existing collection into a :ref:`time series collection
<manual-timeseries-collection>`. MongoDB does not guarantee output order when
you migrate data with :pipeline:`$out`. To maintain order, sort your data before
you migrate it with an aggregation pipeline.

.. note::

   To migrate your time series data with :binary:`~bin.mongodump` and
   :binary:`~bin.mongorestore` instead, run :binary:`~bin.mongorestore`
   with the :option:`--noIndexRestore <mongorestore.--noIndexRestore>`
   option, because :binary:`~bin.mongorestore` can't create indexes on
   time series collections. To preserve the time ordering of your
   measurements, also run the command with the
   ``--maintainInsertionOrder`` option so that documents are inserted in
   order, from oldest to newest.

Next Steps
----------

If your original collection had secondary indexes, manually recreate
them now.

If your time series collection includes ``timeField`` values before
``1970-01-01T00:00:00.000Z`` or after ``2038-01-19T03:14:07.000Z``,
MongoDB logs a warning and disables some query optimizations that make
use of the :ref:`internal clustered index
<manual-timeseries-internal-index>`. To regain query performance and
resolve the log warning, :ref:`create a secondary index
<timeseries-add-secondary-index>` on the ``timeField``.
