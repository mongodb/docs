=========================
Install the |k8s-op-full|
=========================

.. meta::
   :description: Install the MongoDB Controllers for Kubernetes Operator with kubectl, Helm, or OpenShift. Review the prerequisites and considerations, then verify your installation.

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

.. note::

   This tutorial presumes some knowledge of |k8s|. If you are
   unfamiliar with |k8s|, review the |k8s| documentation on
   :k8sdocs:`Kubernetes objects
   </concepts/overview/working-with-objects/>` and
   :k8sdocs:`custom resources
   </concepts/extend-kubernetes/api-extension/custom-resources/>`
   before you begin. The |k8s-op-short| represents |mms| and MongoDB
   deployments as custom resources. You create and manage them with
   ``kubectl`` in the same way that you manage any other |k8s|
   object. To learn how these custom resources relate to each other,
   see :ref:`k8s-architecture`.

-------------

Considerations
--------------

Review the following planning topics. To learn more, see
:ref:`plan-k8s-operator-install`.

- Decide whether to install on a single |k8s| cluster or on multiple
  |k8s| clusters. See :ref:`k8s-which-to-install`.
- Confirm that your versions of |k8s|, OpenShift, MongoDB, and |mms|
  are compatible. See :ref:`k8s-compatibility`.
- Set the scope of the |k8s-op-short| deployment, which determines
  the namespaces that the |k8s-op-short| watches. See
  :ref:`k8s-deployment-scopes`.
- Apply the production recommendations for storage, persistence, and
  CPU and memory bounds. See :ref:`k8s-considerations`.

Install with |k8s|
------------------

The installation procedure varies based on how you want to configure your
environment:

   .. tab:: Using kubectl
      :tabid: kubectl

      .. include:: /includes/install/same-namespace-kubectl.rst

      .. include:: /includes/steps/install-kubectl.rst

   .. tab:: Using Helm
      :tabid: helmonline

      Use the `MongoDB Helm Charts for Kubernetes <https://mongodb.github.io/helm-charts>`__.

      .. include:: /includes/steps/install-k8s-online-helm.rst

      Install a Specific Daily Build with Helm
      ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

      MongoDB rebuilds |k8s-op-short| images every day to integrate the 
      latest security and OS updates.

      By default, ``helm`` installs the latest build for the version of 
      the |k8s-op-short| you specify.

      To install an earlier build, specify the build ID as a parameter with 
      ``--set build=<build-id>``. Build IDs are always in the format 
      ``-b<YYYYMMDD>T000000Z``, where ``<YYYYMMDD>`` is the date that the 
      build you want to use was created.

      .. example::

         This example shows how to install the |k8s-op-short| with the latest 
         image:

         .. code-block:: sh
            :copyable: false

            helm install mongodb-kubernetes-operator mongodb/mongodb-kubernetes

         This example shows how to install the |k8s-op-short| with the image 
         created at midnight on February 5th, 2021:

         .. code-block:: sh
            :copyable: false

            helm install mongodb-kubernetes-operator mongodb/mongodb-kubernetes \
              --set build=-b20210205T000000Z

      .. note::
         
         MongoDB recommends using the default (latest) build.
  
.. _install-k8s-openshift:

Install with OpenShift
----------------------

Before you begin, ensure that the ``MANAGED_SECURITY_CONTEXT`` flag is set
to ``true`` when you deploy the |k8s-op-short| to OpenShift. This value is
pre-defined in the `values-openshift.yaml
<https://raw.githubusercontent.com/mongodb/helm-charts/main/charts/mongodb-kubernetes/values-openshift.yaml>`__ file.
