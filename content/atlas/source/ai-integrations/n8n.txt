.. _n8n:

===========================================
Integrate MongoDB with n8n for AI Workflows
===========================================

.. default-domain:: mongodb

.. facet::
   :name: genre
   :values: reference

.. meta::
   :description: Integrate MongoDB with n8n to build automations and agentic workflows without code by using the MongoDB, MongoDB Atlas Vector Store, and MongoDB Chat Memory nodes.
   :keywords: n8n, automation, workflow, vector database, vector search, AI agent, chat memory, automation platform, integration

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 2
   :class: singlecol

You can integrate MongoDB with `n8n <https://n8n.io/>`__ to build automations 
and agentic workflows using their no-code visual interface. This page provides an 
overview of the integration and describes the different types of 
`nodes <https://docs.n8n.io/workflows/components/nodes/>`__  that you can use in your workflows.

Get Started with |n8n|
----------------------

To use the MongoDB nodes in |n8n|, complete the following steps:

.. procedure::
   :style: normal

   .. step:: Install |n8n|.

      To install |n8n|, see the `n8n documentation
      <https://docs.n8n.io/deploy/host-n8n/install-options/one-line-setup>`__ or run the following command
      by using `npm <https://docs.n8n.io/hosting/installation/npm>`__:

      .. code-block::

         npx n8n

   .. step:: Configure your MongoDB credentials in |n8n|.

      All MongoDB |n8n| nodes require MongoDB credentials. To learn how to add
      your credentials, see `MongoDB Credentials
      <https://docs.n8n.io/integrations/builtin/credentials/mongodb/>`__ in the
      |n8n| documentation.

   .. step:: Create a vector search index.

      If you plan to use the :ref:`n8n-vector-store`, create a
      :ref:`{+avs+} index <avs-types-vector-search>` on your
      collection. To learn how to create the index by using the MongoDB
      node in |n8n|, see :ref:`n8n-create-vector-index`.

To learn how to build a basic AI agent using |n8n| and MongoDB,
see :ref:`n8n-get-started`.

.. _n8n-mongodb-node:

MongoDB Node
------------

The MongoDB node allows you to automate work in MongoDB and integrate
MongoDB with other nodes in your |n8n| workflows.

MongoDB Node Usage
~~~~~~~~~~~~~~~~~~

Use the MongoDB node in any of your custom |n8n| workflows.

MongoDB Node Operations
~~~~~~~~~~~~~~~~~~~~~~~

The MongoDB node supports the following operations:

.. list-table::
   :widths: 20 20 60
   :stub-columns: 1
   :header-rows: 1
   
   * - Category
     - Operation
     - Description
    
   * - **Document Operations**
     - Aggregate Documents
     - Perform aggregation operations to process and transform data using
       MongoDB aggregation pipelines. To learn more, see
       :method:`db.collection.aggregate()`.

   * -
     - Find Documents
     - Query and retrieve documents from your MongoDB collections with
       flexible filtering options. To learn more, see
       :method:`db.collection.find()`.

   * -
     - Insert Documents
     - Add new documents to your MongoDB collections. To learn more, see
       :method:`db.collection.insertMany()`.

   * -
     - Update Documents
     - Modify existing documents in your collections. To learn more, see
       :method:`db.collection.updateOne()`.

   * -
     - Delete Documents
     - Remove documents from your collections. To learn more, see
       :method:`db.collection.deleteMany()`.

   * -
     - Find and Replace Documents
     - Search for documents and replace them with new content. To learn
       more, see :method:`db.collection.findOneAndReplace()`.

   * -
     - Find and Update Documents
     - Search for documents and update specific fields. To learn more,
       see :method:`db.collection.findOneAndUpdate()`.

   * - **Search Index Operations**
     - Create Search Indexes
     - Create new search and vector search indexes on your collections.
       To learn more, see :method:`db.collection.createSearchIndex()`.

   * -
     - List Search Indexes
     - Retrieve information about existing search indexes. To learn
       more, see :pipeline:`$listSearchIndexes`.

   * -
     - Update Search Indexes
     - Modify existing search index configurations. To learn more, see
       :method:`db.collection.updateSearchIndex()`.

   * -
     - Drop Search Indexes
     - Remove search indexes that are no longer needed. To learn more,
       see :method:`db.collection.dropSearchIndex()`.

.. tip::

   To learn more, see 
   `n8n MongoDB node documentation <https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.mongodb/>`__

.. _n8n-vector-store:

MongoDB Atlas Vector Store Node
-------------------------------

The MongoDB Atlas Vector Store node enables you to
use :ref:`{+avs+} <avs-overview>` in your agentic workflows.

To use this node, you must have a
:ref:`{+avs+} index <avs-types-vector-search>` on your collection. To
learn how to create the index in |n8n|, see
:ref:`n8n-create-vector-index`.

Vector Store Node Usage
~~~~~~~~~~~~~~~~~~~~~~~

Use the MongoDB Vector Store node in the following 
workflow patterns:

.. tabs::

   .. tab:: AI Agent Tool
      :tabid: ai-agent

      Connect directly to an AI agent as a tool to perform 
      :ref:`agentic RAG <agentic-rag>`.

      .. code-block:: text

         AI Agent (tools connector) → MongoDB Vector Store

      For a tutorial, see :ref:`n8n-get-started`.

      To learn more about AI agents in |n8n|, see
      `AI agent node <https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.agent/>`__.

   .. tab:: Regular Node
      :tabid: regular

      Use the MongoDB Atlas Vector Store as a regular node to insert or retrieve
      documents in your custom workflows:

      .. code-block:: text

         Trigger → MongoDB Vector Store (Insert/Get) → Next Node

      To learn more, see `Nodes <https://docs.n8n.io/workflows/components/nodes/>`__.

   .. tab:: As Retriever
      :tabid: retriever

      Use the node as a retriever in a question-answering chain:

      .. code-block:: text

         Question and Answer Chain → Vector Store Retriever → MongoDB Vector Store

      To learn more about Q&A in |n8n|, see |n8n-qa-chain|.

   .. tab:: As Question-Answering Tool
      :tabid: qa-tool

      Use the node as a question-answering tool for an AI agent:

      .. code-block:: text

         AI Agent → Vector Store Question Answer Tool → MongoDB Vector Store

      To learn more about the question-answering tool in |n8n|, see
      `Vector Store Question Answer Tool node <https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.toolvectorstore/>`__.

Vector Store Operation Modes
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The MongoDB Vector Store node supports the following operation modes.
The retrieve document mode is only available in certain workflow patterns.

.. list-table::
   :widths: 30 70
   :header-rows: 1
   :stub-columns: 1

   * - Operation Mode
     - Description

   * - .. _n8n-vector-store-mode-get-many:

       **Get Many**
     - Retrieve multiple documents using similarity search based on a prompt.
       Returns documents with similarity scores. To learn more, see
       `Get Many parameters
       <https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.vectorstoremongodbatlas/#get-many-parameters>`__.

   * - .. _n8n-vector-store-mode-insert:

       **Insert Documents**
     - Add new documents with vector embeddings to your collection.
       To learn more, see `Insert Documents parameters
       <https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.vectorstoremongodbatlas/#insert-documents-parameters>`__.

   * - .. _n8n-vector-store-mode-retrieve-chain:

       **Retrieve Documents (As Vector Store for Chain/Tool)**
     - Only available when you use the node as a retriever or a tool.
       Must be connected to a retriever node or root node.
       To learn more, see `Retrieve Documents (As Vector Store for
       Chain/Tool) parameters
       <https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.vectorstoremongodbatlas/#retrieve-documents-parameters-as-vector-store-for-chaintool>`__.

   * - .. _n8n-vector-store-mode-retrieve-agent-tool:

       **Retrieve Documents (As Tool for AI Agent)**
     - Only available when you use the node as a tool for an AI agent.
       The agent uses this vector store
       when the name and description are relevant to the prompt.
       To learn more, see `Retrieve Documents (As Tool for AI Agent)
       parameters
       <https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.vectorstoremongodbatlas/#retrieve-documents-as-tool-for-ai-agent-parameters>`__.

.. _n8n-chat-memory:

MongoDB Chat Memory Node
------------------------

The MongoDB Chat Memory node allows you to use MongoDB as a 
:ref:`memory store <avs-agent-memory>` for storing chat history in your AI workflows. 
This enables persistent conversation context across workflow executions.

Chat Memory Node Usage
~~~~~~~~~~~~~~~~~~~~~~

You must use the MongoDB Chat Memory node as a `sub-node <https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/>`__
by adding it to the :guilabel:`Memory` section of an AI agent node. For a tutorial, see :ref:`n8n-get-started`.

.. note::

   If you add multiple MongoDB Chat Memory nodes to your workflow, all nodes
   access the same memory instance by default. For separate memory instances,
   use different session IDs in each memory node.

.. _n8n-chat-memory-parameters:

Chat Memory Node Parameters
~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. collapsible::
   :heading: Chat Memory Parameter Reference
   :sub_heading: Configure the MongoDB Chat Memory node with these parameters.
   :expanded: false

   .. list-table::
      :widths: 30 70
      :header-rows: 1

      * - Parameter
        - Description

      * - Session ID
        - Method for determining how the session key is identified.
          You can define the session key through a connected trigger, or you can define the key manually.

      * - Session Key
        - Unique identifier for the chat session.

      * - Collection Name
        - Name of the collection to store chat history. MongoDB creates the
          collection if it doesn't exist. Defaults to ``n8n_chat_histories``.

      * - Database Name
        - Name of the database to store chat history. If not provided, |n8n| uses
          the database from credentials.

      * - Context Window Length
        - Number of previous interactions to consider for context.

.. tip::

   To learn more, see 
   `n8n MongoDB Chat Memory node documentation <https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.memorymongochat/#node-parameters>`__
