===========================
Aggregation Pipeline Limits
===========================

.. meta::
   :description: Understand the limitations of MongoDB's aggregation pipeline, including result size, number of stages, and memory usage constraints.

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

Aggregation operations with the :dbcommand:`aggregate` command have the
following limitations.

Result Size Restrictions
------------------------

The :dbcommand:`aggregate` command can either return a cursor or store
the results in a collection. Each document in the result set is subject
to the 16 mebibyte :limit:`BSON Document Size limit <BSON Document
Size>`. If any single document exceeds the :limit:`BSON Document Size
limit <BSON Document Size>`, the aggregation produces an error. The
limit only applies to the returned documents. During the pipeline
processing, the documents may exceed this size. The
:method:`db.collection.aggregate()` method returns a cursor by default.

.. _agg-memory-push-accumulator:

``$push`` Accumulator Memory Limit
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The ``$push`` accumulator cannot write temporary files to disk. The
``internalQueryMaxPushBytes`` server parameter controls the ``$push`` memory
limit and if the accumulated array exceeds that limit, MongoDB returns an error
even when :ref:`allowDiskUse <aggregate-cmd-allowDiskUse>` is ``true``. By
default, the parameter is 104857600 bytes (100 megabytes). You can raise the
limit at runtime with the :dbcommand:`setParameter` command, up to a maximum of
2147483647 bytes.
