==============================
Inspect Agent Execution Traces
==============================

.. facet::
   :name: genre
   :values: tutorial

.. meta::
   :description: Learn how to inspect execution traces on the MongoDB Agentic AI Platform. View sessions, runs, and steps to debug latency and errors.
   :keywords: observability, debugging, sessions, runs, steps, arize

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 2
   :class: singlecol

Overview
--------

An execution trace is a record of everything that happens while your
agent processes a request. It shows which steps run, how long each one
takes, and how many tokens each model call uses. Each time your agent
runs, the {+platform-short+} records a trace automatically.

Use traces to answer two kinds of questions:

- **What happened?** Traces show the sequence of tool calls, model
  calls, and other steps an agent takes to produce a response. Check
  this when a run produces an unexpected or wrong result.
- **Why was it slow?** Traces show how long each step takes, so you can
  find the specific step responsible for a slow run instead of
  guessing.

A trace is composed of three levels: a session, its runs, and each
run's steps. A **session** is a conversation thread with a unique
session ID, created whenever your agent is invoked. A session can
contain several **runs**, one for each execution turn. A run, in turn,
can contain several **steps**: the individual operations an agent
performs, such as a model call or a tool call. To learn what each step
kind means, see :ref:`Step Kinds
<agent-engine-inspect-traces-step-kinds>` later on this page.

You can view traces in two places:

- The :guilabel:`Playground`, where a :guilabel:`Traces` drawer on the
  right side of the page shows the trace for your own interactive test
  sessions as they run.
- The :guilabel:`Traces` page, under :guilabel:`Monitor`, which shows
  every session in the project across all workspaces. A session appears
  here regardless of whether your agent was invoked through the Playground, the UI, the
  REST API, or the CLI, so this is where you find real end-user
  activity. The Playground only ever shows your own sessions.

.. _agent-engine-inspect-traces-step-kinds:

Step Kinds
~~~~~~~~~~

Every step in a trace has a kind, displayed as an icon and a label. The
following table describes each kind:

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - Kind
     - Description

   * - LLM (large language model) call
     - A call to a large language model, such as generating a response or
       deciding which tool to use next.

   * - Tool call
     - A call to a tool the agent has access to, such as a database
       query or an external API request.

   * - Memory
     - A read from or write to the agent's memory store. To learn more,
       see :ref:`agent-engine-add-memory`.

   * - Guardrail
     - A content check applied to the agent's input or output. To learn
       more, see :ref:`agent-engine-guardrails`.

   * - Policy check
     - A check of whether the agent is allowed to take an action, such
       as calling a specific tool or model. To learn more, see
       :ref:`agent-engine-policy-engine`.

   * - Agent-to-agent call
     - A call from one agent to another agent in the same project,
       shown as :guilabel:`Subagents` in the Playground filter. To
       learn more, see :ref:`agent-engine-agent-to-agent`.

   * - Graph node
     - A node in the agent's execution graph that isn't one of the
       other step kinds, such as a routing or control-flow step.

   * - Human review
     - A pause in execution while the run waits for a person to approve
       or reject an action. To learn more, see
       :ref:`agent-engine-human-in-the-loop`.

.. note::

   A long-running ``Human review`` step isn't a performance problem.
   The agent isn't doing any work while it waits for a decision.

Prerequisites and Access
------------------------

You can view a project's traces with any org or project-level read
role. These roles include Organization Admin, Organization Member,
Project Owner, Project Member, and Agent Developer.

With permission from your organization, MongoDB support engineers can
also view your traces through a read-only Data Viewer. An org admin
grants this access for a limited time. While the grant is active, the
Data Viewer shows the same sessions, runs, and steps as the Traces
page. A banner in the Data Viewer states that the view is
read-only, and identifies the grant's expiry. Step payloads, such as
tool call inputs and outputs, are redacted in this view. To learn how
to grant this access, see :ref:`agent-engine-support-access`.

View Traces in the Playground
-----------------------------

The {+platform-short+} shows a :guilabel:`Traces` drawer next to the
Playground chat panel. The drawer updates live as the current run
executes. Turn on the :guilabel:`Timeline` toggle to show step
duration bars alongside the chat.

The run summary at the top of the drawer shows the run's prompt and,
if the run stopped or was blocked, a status badge.

Below the prompt, a summary line reports the run's total duration, the
time to first event, and a count of steps by kind, such as "2 tools."
Time to first event is the delay before the agent's first visible
step. This is separate from the run's total duration, so a run can be
slow to start without being slow to complete, or the reverse.

Each step in the run appears on the timeline with an icon, a label, and
either a token count, a duration, or both, depending on its kind.
Select a step to see its details: a model call shows its prompt,
completion, and total token counts, while a tool call shows its input
and output. Filter the list by category, such as :guilabel:`LLM` or
:guilabel:`Tools`, to isolate one step kind when a run has many
steps.

You can stop an in-progress run in the following ways:

- Stop the entire run by using the stop control in the chat input bar.
  To learn more, see :ref:`agent-engine-invoke-agent-stop-playground`.

- Stop a single in-progress call by using the stop control on that call's step.
  To learn more, see :ref:`agent-engine-invoke-agent-interrupt`.

View Traces on the Traces Page
------------------------------

The Traces page covers every session in the project across all
workspaces. Use it to find a specific end user's session or a direct
invocation.

Find a Session
~~~~~~~~~~~~~~

.. procedure::
   :style: normal

   .. step:: Open the Traces page.

      In the left navigation, select :guilabel:`Traces` from the
      :guilabel:`Monitor` section.

   .. step:: Filter the session list.

      Filter by the search input, time range (**1h**, **24h**, **7d**,
      **30d**), workspace dropdown, or status dropdown to narrow the
      list.

   .. step:: Select a session.

      Select a session to open its runs timeline.

The sessions list shows the following columns:

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - Column
     - Description

   * - Session
     - The session title, taken from the first message, and its run
       count.

   * - Session ID
     - The session's unique identifier. Copy this to cross-reference a
       session against the ``session_id`` filter on the runtime logs
       endpoint. To learn more, see :ref:`agent-engine-monitor`.

   * - Duration
     - Total active time across all runs in the session, excluding
       idle time between runs.

   * - Tokens
     - Total tokens consumed across all runs in the session. This is a
       lower bound: it doesn't count some token usage, such as memory
       extraction.

   * - Workspace
     - The deployed agent that produced the session.

   * - Last activity
     - When the session was last updated.

   * - Latest run
     - The status of the most recent run in the session.

Read the Runs Timeline
~~~~~~~~~~~~~~~~~~~~~~

Opening a session shows its runs as a shared timeline. Three summary
cards at the top total the session's duration, tokens, and memory
activity (recalls and saves) across every run shown. The tokens and
memory totals are lower bounds: they reflect only the runs and steps
that have finished, so they can undercount while a run is still active.

A sort dropdown and an :guilabel:`Elapsed time`/:guilabel:`Tokens`
toggle change how the timeline reads. The dropdown controls which run
you see first. The toggle controls what a bar's length measures:
duration in :guilabel:`Elapsed time` view and token count in
:guilabel:`Tokens` view.

In :guilabel:`Elapsed time` view, the horizontal axis represents
elapsed time since the run starts. A step's bar is positioned and
sized by when it starts and how long it runs. This lets you determine which
steps run sequentially and which overlap. Because every run in the
session shares the same axis, you can also compare separate runs
against each other at a glance. In :guilabel:`Tokens` view, there is no
time axis: bars are left-aligned and sized in proportion to each
step's token count.

The following image shows a session's runs timeline while a run is in
progress:

.. figure:: /images/agentengine-session-runs-timeline-v2.png
   :alt: A session's runs timeline showing completed and running steps
   :figwidth: 600px

Each run's header reports its relative start time, total duration, time
to first event, total tokens, and the slowest step it contains, in the
form ``slowest: <step> (<duration>)``.

An in-progress run shows a stop control. Stopping a run
changes its status to **Stopping…** and then to **Stopped** once it
halts. Cancellation isn't always instantaneous because a step may need
to finish its current operation first. The interrupted step shows a
matching **Stopped** badge, identifying exactly which step the stop
interrupted.

An in-progress tool or LLM call also shows a stop control on its step
row. Stopping a single call marks that row as :guilabel:`Stopped` with
the call's partial duration, and the run continues from the
interrupted result. To learn more about tool call interruption, see
:ref:`agent-engine-invoke-agent-interrupt`.

Each step row shows an icon and a name. Depending on the step's
state, it shows either a duration or a state label. A completed step
shows its duration, and an LLM call also shows its token count. A step
still in progress shows **Running…**.

Select a step to open its details in a side panel, including its kind,
status, duration, and who invoked the run. The panel also shows the
step's inputs and outputs, such as the messages sent to and returned
from a model call.

Find the Cause of a Slow Run
----------------------------

When a run takes longer than expected, use the following signals to
find the specific step responsible:

- Start with the run header's **slowest step** callout, in the form
  ``slowest: <step> (<duration>)``. Select that step to inspect its
  details directly.
- If the run was slow to start rather than slow to finish, check
  **time to first event** instead of the slowest step. A consistently
  high value across runs means the delay happens before any step you
  can inspect even starts.
- If a run's total token count is high but no single step stands out
  in the :guilabel:`Elapsed time` view, switch to the :guilabel:`Tokens`
  view. A step can be a token bottleneck without being the slowest step
  by wall-clock time.
- If a run's total duration is high but its steps all look fast, check
  whether the run waited on a human review. If it did, the run
  header replaces its duration and time-to-first-event fields with an
  ``active`` / ``review`` split, such as "2min 3s active - 1h 30min
  review". High review time means the run was paused in the
  human-in-the-loop review queue, not actually running slowly. To
  learn more, see :ref:`agent-engine-human-in-the-loop`.

Export Traces to Arize
----------------------

In addition to viewing your project's traces on the :guilabel:`Traces`
page, you can export them to your own observability tool. The
{+platform-short+} sends traces by using the OpenTelemetry Protocol
(OTLP) over HTTP, a vendor-neutral format that most observability
tools accept. By default, traces stay on the {+platform-short+} only.

This section shows how to export traces to `Arize
<https://arize.com/>`__. To export to a destination
without preset settings, select :guilabel:`Custom (no preset)`
from the :guilabel:`Preset` menu in the :guilabel:`Trace Export` window,
and enter its OTLP connection details manually.

.. important::

   Currently, you must export the full content of your traces when
   configuring trace export. This content includes model prompts
   and completions, tool call inputs and outputs, and other sensitive
   information. Metadata-only redaction is not yet available.

.. _agentengine-traces-export-prerequisites:

Before You Start
~~~~~~~~~~~~~~~~

Before you configure trace export to Arize, ensure that you have the
following resources:

- Arize project. To learn how to create a tracing project, see
  `Instrument your Agent <https://arize.com/docs/ax/get-started/get-started-tracing>`__
  in the Arize documentation.
- Arize Space ID and project name, which send exported spans to the
  specified Arize project. The Space ID appears in your browser's
  address bar when you open your Space's home page in Arize,
  in the form ``spaces/<space_id>/home``. The project name
  is the name you gave the project when you created it.
- Arize API key. To learn how to create an API key, see `Arize API keys
  <https://arize.com/docs/ax/security-and-settings/api-keys>`__.

Configure Trace Export
~~~~~~~~~~~~~~~~~~~~~~

.. procedure::
   :style: normal

   .. step:: Open the Traces page.

      Sign into the {+platform-short+} and navigate to the project that
      contains the agent you want to export traces from.

      From the left navigation bar, select :guilabel:`Traces` from
      the :guilabel:`Monitor` section.

   .. step:: Turn on trace export.

      In the top right of the :guilabel:`Traces` page, click
      the :guilabel:`Export` status chip to open the :guilabel:`Trace Export`
      window.

      Switch the :guilabel:`Enable trace export` toggle to the on position.

   .. step:: Configure the destination.

      In the :guilabel:`Destination` section of the :guilabel:`Trace Export`
      window, configure the following settings:

      a. From the :guilabel:`Preset` menu, select :guilabel:`Arize`.
         The preset prefills the OTLP endpoint and protocol, and it adds
         the :guilabel:`space_id` and :guilabel:`openinference.project.name`
         fields.

         .. tip::

            Click the **Setup guide** link below the **Preset**
            field to open Arize's OpenTelemetry instrumentation documentation.

      #. Confirm the :guilabel:`OTLP endpoint` value. The Arize preset
         prefills ``https://otlp.arize.com/v1/traces``.
      #. Confirm the :guilabel:`Protocol` value. The Arize preset sets this
         field to ``HTTP/protobuf``, the only supported protocol.
      #. In :guilabel:`space_id`, enter your Arize Space ID.
      #. In :guilabel:`openinference.project.name`, enter your Arize
         project name. Arize uses this value to send incoming spans
         to the correct project.
      #. In :guilabel:`Destination API key`, enter your Arize API key,
         and then click :guilabel:`Save key`. The {+platform-short+}
         stores the key and doesn't display it again.
      #. Confirm the :guilabel:`Auth header name` value. The Arize
         preset sets this field to ``api_key``.

   .. step:: Configure content delivery.

      In the :guilabel:`Delivery` section of the :guilabel:`Trace Export`
      window, configure the following settings:

      a. Confirm that :guilabel:`Egress mode` is set to
         :guilabel:`Agent Engine + customer mirror`. This field is
         read-only.
      #. Select the :guilabel:`I understand that full span content,
         including prompts, completions, and tool payloads, will be
         sent to the destination.` checkbox. This sets
         :guilabel:`Content mode` to :guilabel:`Full content`, which is
         currently the only available content mode.
      #. Confirm that :guilabel:`Sampling` is set to :guilabel:`Always
         on`. Currently, this is the only available sampling policy.
      #. Leave :guilabel:`Skip TLS verification` unchecked. This feature
         is not yet available.

   .. step:: Save your settings.

      Click :guilabel:`Save settings`. After saving, a popup message
      appears that reads ``"Export is on"``. The :guilabel:`Export`
      status chip updates to include your destination and an
      :guilabel:`ON` badge.

   .. step:: Verify that traces appear in Arize.

      Invoke the agent in this project, either from the Playground UI or
      through the invocation API. To learn more, see
      :ref:`agent-engine-invoke-agent`.

      The resulting trace appears on the :guilabel:`Traces` page in
      the {+platform-short+} UI. The spans also appear in Arize,
      on your Space's :guilabel:`Traces` page.

Troubleshoot Trace Export
~~~~~~~~~~~~~~~~~~~~~~~~~

If the :guilabel:`Save settings` button stays disabled, or saving
fails, verify the following requirements:

- You must change at least one setting before you can save your
  settings.
- You must check the full-content box in the :guilabel:`Delivery`
  section.
- If you saved a :guilabel:`Destination API key`, you must also set
  :guilabel:`Auth header name`.
- You must save a :guilabel:`Destination API key` or set at least one
  header value, such as :guilabel:`space_id`. You can save the settings
  with only one of these set, but Arize requires both to authenticate.
- Don't check the :guilabel:`Skip TLS verification` box. This can
  prevent your settings from saving.
- If the window reports that trace export isn't enabled in this
  environment, the feature isn't available for your project yet.

If your traces do not appear in Arize after you invoke your agent, verify
the following requirements:

- You must use the ``https://otlp.arize.com/v1/traces`` endpoint.
  Ensure that your endpoint doesn't omit the ``/traces`` suffix.
- Verify that your ``space_id`` and ``openinference.project.name`` match
  the values in your Arize project.
- Verify that you saved the correct Arize API key. To change it, click
  :guilabel:`Replace key` in the :guilabel:`Destination API key`
  section and enter the new key.
