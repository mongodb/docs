=========================================
MongoDB {+atlas-infinite-full+}: Overview
=========================================

.. default-domain:: mongodb

.. facet::
   :name: genre
   :values: reference

.. meta::
   :keywords: atlas infinite, atlas infinite edition, atlas core, public preview
   :description: Atlas Infinite separates compute from storage so you can recover from failures, scale compute and storage independently, and simplify operational workflows across your clusters.

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

{+atlas-infinite-full+} is a |service-fullname| edition, built on an
architecture that separates compute from storage into independent
layers, designed for mission-critical high-performance use cases, with
built-in security controls. This design delivers high performance,
scalability, and elasticity: you can scale compute and storage
independently and rapidly, recover quickly from failures, and simplify
operational workflows.

To learn how this documentation is organized across editions, see
:ref:`atlas-infinite-about-docs`.

Architecture
------------

The following diagram shows how {+atlas-infinite-full+} separates
compute from storage.

.. figure:: /images/infinite/atlas-infinite-storage-overview.svg
   :width: 720px
   :alt: Diagram showing Atlas Infinite compute nodes, a primary and a standby, connecting to a separate Atlas-managed storage layer.
   :align: center

   Compute and storage as independent layers in {+atlas-infinite-full+}

In {+atlas-infinite-full+}, compute and storage are separate layers.
Your application's queries, transactions, and aggregations run on
compute nodes. MongoDB manages the storage layer independently of the
compute layer, so operations such as scaling the cluster tier, adding
read-only nodes, and recovering from a node failure run without moving
or replicating data. Your application connects to your
{+atlas-infinite-cluster+} using MongoDB drivers and other connection
methods. You can also access and manage the cluster with MongoDB
programmatic tools.

To learn more about the architecture, see
:ref:`atlas-infinite-architecture`.

Benefits
--------

By separating compute from storage, {+atlas-infinite-full+} lets you:

- **Scale independently**: You scale the cluster tier and storage
  capacity independently, so scaling the cluster tier doesn't require
  scaling storage capacity.
- **Scale quickly**: Scaling {+atlas-infinite-full+} vertically and
  horizontally is quick, so you don't have to preprovision for peaks or
  preplan scaling in anticipation of events.
- **Simplify operations**: In {+atlas-infinite-full+}, you can increase
  storage capacity without downtime.
- **Maximize throughput and performance**: {+atlas-infinite-full+} runs
  backup, restore, and point-in-time recovery at the storage layer,
  independently of the compute layer. This offloads that work from the
  compute layer, leaving more capacity to serve your application's
  workload.

Performance
~~~~~~~~~~~

The {+atlas-infinite-full+} architecture is optimized for performance.
Many workloads achieve high throughput on {+atlas-infinite-full+}.
Performance depends on the workload, so test with your own workload to
measure the impact.

Elasticity
~~~~~~~~~~

{+atlas-infinite-full+} scales compute and storage independently, so you
can add compute capacity for a workload spike without changing storage.
{+atlas-infinite-full+} supports
:ref:`auto-scaling for the cluster tier <cluster-autoscaling-compute-infinite>`,
and scales up and down in reaction to changes in demand. You can scale
horizontally by :ref:`adding read-only nodes
<atlas-infinite-workload-isolation>`, which read from the storage
layer and start serving reads in minutes.

Scalability
~~~~~~~~~~~

{+atlas-infinite-full+} scales storage independently of compute, so you
can increase storage capacity to support growing, enterprise-level
applications without scaling the cluster tier.

In {+atlas-infinite-full+}, you scale your cluster vertically by
increasing the cluster tier. A larger tier provides more storage
throughput and storage IOPS. When you scale your cluster vertically,
{+atlas-infinite-full+} doesn't move your data.

When you add read-only nodes to an {+atlas-infinite-cluster+}, they read
from the storage layer and start serving reads in minutes,
without an initial sync.

Security
--------

{+atlas-infinite-full+} is designed to be secure. It always
encrypts your data before it leaves the compute node, so the storage
layer cannot read your application's data. Encryption is mandatory, and
{+atlas-infinite-full+} supports customer-managed data encryption keys
(CMK/BYOK).

{+atlas-infinite-full+} supports the following security controls:

- :ref:`PrivateLink <private-endpoint>`
- :ref:`IP access lists <access-list>`
- :ref:`IAM and single sign-on (SSO) <atlas-federated-authentication>`
- :ref:`Auditing <set-up-database-auditing>`
- :ref:`Field-level encryption (FLE) <manual-csfle-feature>`
- :ref:`Network peering <vpc-peering>`

To learn how |service| encrypts your data at rest and which security
controls apply, see :ref:`Encryption at Rest on {+atlas-infinite-full+}
<atlas-infinite-encryption-at-rest>`.

Resilience and Recovery
-----------------------

In {+atlas-infinite-full+}, the storage layer keeps your data durable.
MongoDB doesn't rely on the compute nodes for the durability of your
data. An {+atlas-infinite-cluster+} has two electable compute nodes,
a primary and a standby. Together they form a highly available shard
(HA shard), a unit specific to {+atlas-infinite-full+} and distinct
from a MongoDB :term:`shard`. If the primary fails or restarts, the
standby becomes the primary. The storage layer coordinates the
failover from the primary to the standby instead of an election among
the {+cluster+}'s nodes and keeps your recent data readily available.
Backup, restore, and point-in-time recovery run at the storage layer.

To learn how replication and failover work on an
{+atlas-infinite-cluster+}, see :ref:`atlas-infinite-replication`. To
learn about backup and restore, see :ref:`atlas-infinite-backup`.

Operational Experience
----------------------

Your application runs on {+atlas-infinite-full+} without code changes.
{+atlas-infinite-full+} uses the MongoDB wire protocol and supports the
full MongoDB query API, including queries, aggregations, indexes, and
transactions.

{+atlas-infinite-full+} also works with the following tools:

- ``mongosh``
- Compass
- :ref:`{+atlas-admin-api+} <atlas-admin-api>`, with some endpoints
  specific to {+atlas-infinite-full+}
- Atlas CLI, with some commands specific to {+atlas-infinite-full+}
- :ref:`Terraform Provider <getting-started-terraform>`, with some
  attributes specific to {+atlas-infinite-full+}
- :ref:`{+sql-interface+} <connect-with-sql-overview>`, enabled
  directly on the cluster

On an {+atlas-infinite-cluster+}, you can enable the {+sql-interface+}
directly on the cluster rather than through a {+fdi+}.

{+service+} provides alerts specific to {+atlas-infinite-full+}.

Public Preview Availability
---------------------------

.. _atlas-infinite-supported:

Supported in Public Preview
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

{+atlas-infinite-full+} supports the following features in public
preview:

- The complete MongoDB database semantics and features. For the
  duration of public preview, {+atlas-infinite-cluster+}s run the
  latest MongoDB 9.x version, using the :guilabel:`Latest Version With
  Auto Upgrades` release option in the {+atlas-ui+}. To learn more,
  see :ref:`atlas-versions`.
- ``M10`` through ``M60`` :guilabel:`General` replica sets, and ``M40``
  through ``M60`` :guilabel:`Low-CPU` replica sets.
- Storage capacity up to 128 TB (logical) per replica set.
- Cloud provider regions: In public preview, {+atlas-infinite-full+}
  deploys on |aws| only. See the **{+atlas-infinite-full+} Support**
  column in the :ref:`Amazon Web Services (AWS) regions table
  <atlas-infinite-aws-regions>`. Each {+cluster+} deploys in one of
  these regions.
- Customer-managed data encryption keys (CMK/BYOK) through :ref:`AWS
  KMS <security-aws-kms>`.
- :ref:`PrivateLink <private-endpoint>`.
- :ref:`Backups <atlas-infinite-backup>`, with retention for up to 3
  years.
- |mongodump|, |mongorestore|, and |mongoimport|. To learn more, see
  :ref:`atlas-infinite-load-data`.
- :ref:`{+sql-interface+} <connect-with-sql-overview>`, enabled
  directly on the cluster.
- :ref:`{+adf+} <data-federation-overview>`.
- :ref:`{+atlas-sp+} <atlas-sp-overview>`.
- The :ref:`{+cluster-ai-assist+} <atlas-ai-cluster-assistant>`, which
  is aware of {+atlas-infinite-cluster+}s but does not have full
  context on their capabilities.

.. _atlas-infinite-not-supported:

Not Supported in Public Preview
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

{+atlas-infinite-full+} does not support the following features in
public preview. This list is subject to change over time as
{+atlas-infinite-full+} adds support for more features. Check back to
see which features are currently supported.

- **Multi-region clusters**: All nodes in an
  {+atlas-infinite-cluster+} deploy in the same region.
- **Multi-cloud clusters**: {+atlas-infinite-full+} doesn't support
  multi-cloud clusters in public preview. In public preview,
  {+atlas-infinite-cluster+}s deploy on |aws| only.
- **M80+ cluster tiers**: {+atlas-infinite-full+} does not support ``M80``
  and larger cluster tiers in public preview, in either the
  :guilabel:`General` or the :guilabel:`Low-CPU` cluster class.
- **Sharded clusters**: {+atlas-infinite-full+} does not support sharded
  clusters in public preview.
- **Global clusters**: {+atlas-infinite-full+} does not support global
  clusters in public preview. Global writes require a global cluster, so
  they aren't available either.
- **Atlas Search and Vector Search**: Atlas Search and Vector Search are
  not supported on {+atlas-infinite-cluster+}s in public preview.
- **Atlas Online Archive**: Atlas Online Archive is not supported on
  {+atlas-infinite-cluster+}s in public preview.
- **Atlas Kubernetes Operator**: {+ak8so+} doesn't support
  {+atlas-infinite-cluster+}s in public preview.
- **Cross-edition migration and restore**: {+atlas-infinite-full+} doesn't
  support live migration or backup and restore between {+atlas-core-full+}
  and {+atlas-infinite-cluster+}s.
- **Importing archived snapshots**: {+atlas-infinite-full+} doesn't support
  importing archived snapshots in public preview.
- **NVMe storage**: {+atlas-infinite-full+} does not support locally
  attached |nvme| |ssd| storage in public preview.
- **Database edition changes**: You can't change the database edition of
  a {+cluster+} after you create it, in either direction between
  {+atlas-core-full+} and {+atlas-infinite-full+}.
- **No oplog replay**: {+atlas-infinite-full+} doesn't support oplog
  replay. Don't use the :option:`mongodump --oplog <mongodump --oplog>`
  option or the :option:`mongorestore --oplogReplay
  <mongorestore.--oplogReplay>` option with {+atlas-infinite-cluster+}s.
- **Azure Key Vault and Google Cloud KMS**: {+atlas-infinite-full+}
  supports customer-managed keys only through :ref:`AWS KMS
  <security-aws-kms>` in public preview.
- **Cross-organization restores**: MongoDB manages a separate encryption
  key for each |service| organization, so you restore a snapshot within
  the organization that created it. To learn how |service| manages
  default encryption keys, see
  :ref:`atlas-infinite-encryption-at-rest`.
- **Atlas Charts**: {+atlas-infinite-full+} doesn't support {+charts+} in
  public preview.
- **MongoDB for VS Code**: {+atlas-infinite-full+} doesn't support the
  MongoDB for VS Code extension in public preview.
- **MongoDB MCP Server**: {+atlas-infinite-full+} doesn't support the
  MongoDB MCP Server in public preview.
- **MongoDB Agent Skills**: {+atlas-infinite-full+} doesn't support
  MongoDB Agent Skills in public preview.
- **Log downloads and log syncs**: {+atlas-infinite-full+} doesn't support
  downloading MongoDB logs or syncing logs to an external service in
  public preview.
- **Collection-level restore**: {+atlas-infinite-full+} doesn't support
  restoring individual collections in public preview.
- **Snapshot distribution**: {+atlas-infinite-full+} doesn't support
  copying snapshots to other regions in public preview.
- **Snapshot downloads and local restores**: {+atlas-infinite-full+}
  doesn't support downloading a snapshot or restoring one to a local
  deployment in public preview.
- **Uptime SLA**: {+atlas-infinite-full+} doesn't carry an uptime SLA in
  public preview.
- **Independent and asymmetric shard auto-scaling**:
  {+atlas-infinite-full+} doesn't support independent or asymmetric shard
  auto-scaling in public preview.
- **Database profiler**: {+atlas-infinite-full+} doesn't support enabling
  the database profiler in public preview.

.. _atlas-infinite-compare-editions:

Compare with Atlas Core
-----------------------

|service| offers two database editions: {+atlas-core-full+},
where compute and storage are coupled on the same node, and
{+atlas-infinite-full+}, a decoupled architecture where each layer
scales independently. To compare the two editions in detail, see
:ref:`atlas-editions`.
