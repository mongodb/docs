.. _om-api-rotate-identity-key:

==========================================
Rotate the Identity Key of an Installation
==========================================

.. default-domain:: mongodb

.. meta::
   :description: Rotate the identity key of your Ops Manager installation and review the outcome. If rotation fails, the current key stays active. This endpoint requires the Global Owner role.

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

Your |mms| installation generates an identity key: a key pair that the
installation uses to prove its identity when it connects to MongoDB. If
someone outside your organization obtains the private key, the key is
compromised, and they could impersonate your installation.

Use this endpoint to rotate the identity key. Rotating replaces the
key with a new key pair. If the rotation fails, |mms| applies no
change and the current key stays active. The response always contains
the outcome of the rotation.

.. important::

   Your |mms| installation must be able to connect to MongoDB to rotate
   the key. If it can't, the endpoint returns the HTTP status ``502``
   with the outcome ``UNREACHABLE`` or ``EA_UNAVAILABLE``.

Required Roles
--------------

To access this resource, your |api| key must have
the :authrole:`Global Owner` role. The Global Owner role is the
highest role in |mms|. Only users with this role can view and manage
license keys.

Request
-------

Send a ``POST`` request to start the rotation.

.. include:: /includes/api/base-api-uri.rst

.. code-block:: http

   POST /admin/artifacts/identity/rotate

Response
--------

The response contains the following fields:

.. list-table::
   :header-rows: 1
   :widths: 30 15 55
   :stub-columns: 1

   * - Field
     - Type
     - Description

   * - ``outcome``
     - string
     - Result of the rotation. |mms| returns one of the values in
       the following table.

   * - ``message``
     - string
     - Sentence that describes why |mms| didn't apply the rotation.
       This field is ``null`` when the outcome is ``ROTATED``.

The following table lists each outcome with its HTTP status and
message:

.. list-table::
   :header-rows: 1
   :widths: 20 10 70
   :stub-columns: 1

   * - Outcome
     - HTTP Status
     - Message

   * - ``ROTATED``
     - 200
     - |mms| returns no message.

   * - ``UNREACHABLE``
     - 502
     - MongoDB could not be reached to complete the rotation. No
       change was applied — the current key stays active. Try again
       shortly.

   * - ``EA_UNAVAILABLE``
     - 502
     - The MongoDB Enterprise Advanced service is unavailable. No
       change was applied — the current key stays active. Try again
       shortly.

   * - ``NOT_CONFIGURED``
     - 409
     - There is no enrollment identity to rotate yet — one is created
       on the first install.

   * - ``UNAUTHORIZED``
     - 409
     - MongoDB rejected the rotation's proof of possession. The
       current key stays active. Contact your MongoDB account team.

   * - ``CONFLICT``
     - 409
     - The enrollment identity changed concurrently. No change was
       applied — retry shortly.

   * - ``REJECTED``
     - 409
     - MongoDB rejected the rotation request. The current key stays
       active.

Example Request
---------------

Use ``curl`` to send a ``POST`` request to the ``/admin/artifacts/identity/rotate`` endpoint:

.. code-block:: sh

   curl --user "{PUBLIC-KEY}:{PRIVATE-KEY}" --digest \
        --header "Accept: application/json" \
        --include \
        --request POST \
        "https://{+opsmgr-url+}/api/public/v1.0/admin/artifacts/identity/rotate?pretty=true"
