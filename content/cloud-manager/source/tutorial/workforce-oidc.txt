.. _cm-oidc-authentication-workforce:

=============================================================
Set up {+wif+} Authentication with OIDC
=============================================================

.. default-domain:: mongodb

.. meta::
   :keywords: connect
   :description: Set up Workforce Identity Federation (OIDC) authentication in Cloud Manager: register an OIDC app with your identity provider, configure workforce authentication, and authorize users or groups.

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 2
   :class: singlecol

In MongoDB 7.0 and later, you can use {+wif+} with an external
|idp-full| (IdP), such as your corporate |idp|. {+wif+} authenticates
and authorizes your workforce, including employees, partners, and
contractors. 

With {+wif+}, you can:

- Manage your workforce access to MongoDB deployments through your
  existing |idp|.
- Enforce security policies such as password complexity, credential
  rotation, and |mfa| within your |idp|.

You can only create one {+wif+} per project, but you can 
:ref:`edit <cm-edit-workforce-configuration>` or recreate the configuration 
at any time.

Required Access
---------------

To configure {+wif+}, you must have
:authrole:`Project Owner` access to |mms|.

Prerequisites
-------------

You must meet these prerequisites:

- {+mongosh+} 1.9.1 or later.
- MongoDB 7.0 or later.
- At least one other authentication mechanism with {+mdbagent+} configured.

  .. note:: 
     
     The {+mdbagent+} can't connect to your deployment through |oidc|. You must
     enable another auth mechanism for the {+mdbagent+}. If |mms|
     doesn't manage {+magent+} or {+bagent+}, you must manually configure
     them to use the alternative authentication mechanism.
     
Procedures
----------

To access |mms| deployments with {+wif+}, follow these steps:

1. Configure a Workforce Identity Provider (one-time setup).
   
   a. :ref:`Configure your external identity provider <cm-configure-idp-oidc-workforce>`.

   b. :ref:`Configure Workforce Identity Provider in Cloud Manager <cm-configure-oidc-auth-workforce>`.

2. :ref:`Grant external identities (user principals) or groups access <cm-create-oidc-user-workforce>`.

3. :ref:`Authenticate to your Cloud Manager deployment <cm-connect-oidc-workforce>`.

.. _cm-configure-idp-oidc-workforce:

Configure an External Identity Provider App
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. include:: /includes/note-reset-auth.rst

To configure {+wif+} with |oidc|, register your |oidc| app
with an |idp| that supports the |oidc| standard. Examples include
Microsoft Entra ID, Okta, and Ping Identity.

You can configure your |oidc| app for these grant types:

- Authorization Code Flow with {+pkce+}
- Device Authorization Flow

MongoDB recommends that you use Authorization Code Flow with {+pkce+} for increased
security. Use Device Authorization Flow only if your users need
to access the database from machines with no browser.  

The |oidc| app registration steps can vary by |idp|. During
your app registration, set these items:

.. tabs::
   
      .. tab:: Generic
         :tabid: generic

         The generic registration steps for your OIDC app are as
         follows:

         .. include:: /includes/steps-register-oidc-application.rst
   
      .. tab:: Microsoft Entra ID
         :tabid: microsoft

         To register your |oidc| app with Microsoft Entra ID:
   
         .. include:: /includes/steps-register-oidc-application-azure-workforce.rst

Configure |oidc| Authorization
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB doesn't explicitly create database users for |oidc|. It maps
|oidc| users to MongoDB roles based on the configuration.

Follow the procedure for the authorization type that you selected
when :ref:`configuring OIDC authentication <cm-configure-oidc-auth-workforce>`:

Group Membership
^^^^^^^^^^^^^^^^

If you selected the ``Group Membership`` authorization type,
follow these steps to create a custom role that grants
authorization based on |idp| user group membership:

.. include:: /includes/steps-configure-oidc-user-group.rst

User ID
^^^^^^^

If you selected the ``User ID`` authorization type,
create a new user to grant an individual user authorization:

.. include:: /includes/steps/configure-oidc-user.rst

Manage an Existing {+wif+} Configuration
---------------------------------------------------------------------

To manage your {+wif+} configuration,
you can perform these actions.

Revoke JSON Web Key Sets (JWKS)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. note::
   
   Don't use this feature to rotate your signing keys. When you rotate 
   your |oidc| |idp| signing keys, MongoDB fetches the JWKS automatically
   upon expiration of the existing access tokens.

If your private key is compromised, you can immediately revoke the JSON
Web Key Sets cached in MongoDB nodes:

.. include:: /includes/steps-remove-oidc-jwks-token.rst
