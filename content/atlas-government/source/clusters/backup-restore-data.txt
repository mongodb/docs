.. _backup-restore:

===============================
Backup and Restore Cluster Data
===============================

.. meta::
   :description: Manage backups and restore data for clusters in MongoDB Atlas for Government projects, ensuring compliance with region-specific restrictions.

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

Backups are copies of your data that encapsulate the state of your
cluster at a given time. Backups provide a safety measure in the
event of data loss.

You must have the :authrole:`Project Owner` or
:authrole:`Project Backup Manager` role for an
|cloudgov-short| project to manage backups for or to restore a
backup to clusters in that project.

.. tip::

   |cloudgov-short| user roles are the same as 
   :atlas:`Atlas User Roles </reference/user-roles/>`.

You cannot restore backups between {+fedramp-c+} projects and
{+fedramp-d+} projects. If you create a backup from a cluster in
a {+fedramp-d+} project, you can restore the data to clusters in
{+fedramp-d+} projects. The same restriction applies to
{+fedramp-c+} projects.

Cross-cloud restore is supported among |aws-fr-high|, |gaw|, and
|azure-gov| regions. |azure-gov| regions support only ``M30`` or
higher cluster tiers, so restores to |azure-gov| require a target
cluster of ``M30`` or higher.

|cloudgov-short| backups for |aws-fr-high| deployments are stored
in |aws-fr-high| regions, and backups for |aws-fr-moderate|
deployments are stored in |aws-fr-moderate| regions.

For a list of regions by cloud provider, see :ref:`supported-regions`.

See the |service| documentation to configure 
:atlas:`Cloud Backups </backup/cloud-backup/overview/>`
