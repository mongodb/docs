===================================================
Export {+Cloud-Backup+} Snapshots to Object Storage
===================================================

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 2
   :class: singlecol

.. include:: /includes/fact-atlas-free-tier-limits.rst

|service| lets you export your {+Cloud-Backup+} snapshots to an object
storage service.

To learn how to restore an exported snapshot back into an |service|
{+cluster+}, see :ref:`cloud-provider-import-archive`.

To learn how to manage automated backup policies and schedules, see
:ref:`configure-backup-policy`.

.. _snapshot-export-supported-storage:

Supported Storage Services
--------------------------

|service| currently supports the following object
storage services:

- |aws| |s3| buckets
- {+az-bs+}
- {+gcs+} buckets

Additionally, {+service+} supports exporting snapshots to {+aws+} |s3|
buckets using PrivateLink.

How |service| Exports Snapshots 
-------------------------------

You can manually export individual snapshots or set up an export policy
for automatic export of your snapshots. For steps specific to your
object storage service, see :ref:`your cloud provider's export page
<cloud-backup-export-providers>`.

To set up automatic exports, add an export policy to your
{+Cloud-Backup+} schedule and set its frequency type to ``daily``,
``weekly``, ``monthly``, or ``yearly``. When a :ref:`backup policy item
<configure-backup-policy>` with the same frequency type creates a
snapshot, |service| exports that snapshot to your specified object
store.

|service| uploads an empty file to the
``/exported_snapshots/.permissioncheck`` path on your object store when
you add a new :ref:`object store <snapshot-export-supported-storage>`
for export and when you start an export. As the export progresses, you
may see partial results in your object storage service.

|service| persists documents in snapshots irrespective of
:manual:`Time to Live </tutorial/expire-data>` settings. You can access these
documents from your snapshot past their Time to Live deadline.

To learn about snapshot export pricing, see :ref:`Snapshot Export Costs
<snapshot-export-costs>`.

Exported Data Files
~~~~~~~~~~~~~~~~~~~

Each {+Cloud-Backup+} snapshot export job uploads the snapshot data to
the object store in gzip-compressed :ref:`Extended JSON v2
<mongodb-extended-json-v2>` documents. These files are not uploaded in
any particular order. Each file contains a chunk of documents from a
single collection in the snapshot. For sharded clusters {+service+}
creates a separate export job per replica set (shard), and specifies the
replica set name in the path of the uploaded files.

.. important:: 
  
  As the export progresses, you may see partial results in your object
  storage service. If an export job fails: 

  - |service| doesn't automatically try to export again.
  - |service| doesn't remove any partial data in your object store.

|service| uploads each data file to the following path on your object
store:

.. code-block:: sh
  :copyable: false

  /exported_snapshots/<orgName>/<projectName>/<clusterName>/<initiationDateOfSnapshot>/<timestamp>/<dbName>/<collectionName>/<shardName>.<increment>.json.gz

|service| replaces each placeholder in the path with these values:

.. list-table::
  :widths: 35 65

  * - ``<orgName>``
    - Name of your |service| organization.

  * - ``<projectName>``
    - Name of your |service| project.

  * - ``<clusterName>``
    - Name of your |service| cluster.

  * - ``<initiationDateOfSnapshot>``
    - Date when snapshot was taken.

  * - ``<timestamp>``
    - Timestamp when the export job was created.

  * - ``<dbName>``
    - Name of the database in the |service| cluster.

  * - ``<collectionName>``
    - Name of the |service| collection.

  * - ``<shardName>``
    - Name of the replica set. For sharded collections, this is
      the name of the
      :manual:`primary shard
      </core/sharded-cluster-shards/#primary-shard>`.

  * - ``<increment>``
    - Count that is incremented as chunks are uploaded. Starts
      at ``0``.

Exported Metadata Files
~~~~~~~~~~~~~~~~~~~~~~~

After |service| finishes exporting the snapshot data to your object
store, |service| also uploads a metadata file named ``.complete`` and a
metadata file named ``metadata.json`` for each collection:

.. collapsible:: 
   :heading: .complete Metadata File
   :sub_heading: Exported metadata file that contains information about the export job and the exported snapshot.
   :expanded: false

   For each collection in the snapshot export job, {+service+} uploads a
   metadata file named ``.complete`` to the following path on your
   object store:

   .. code-block:: shell
      :copyable: false

      /exported_snapshots/<orgUUID>/<projectUUID>/<clusterName>/<initiationDateOfSnapshot>/<timestamp>/

   .. note:: 

      By default, |service| uses organization and project UUIDs in the
      path for the metadata files. To use organization and project names
      instead of UUIDs, set the ``useOrgAndGroupNamesInExportPrefix``
      flag to ``true`` via the :oas-bump-atlas-op:`API
      <updategroupclusterbackupschedule>`. |service| replaces any spaces
      with underscores (``_``) and removes any :aws:`characters that
      might require special handling
      </AmazonS3/latest/userguide/object-keys.html>` and
      :aws:`characters to avoid
      </AmazonS3/latest/userguide/object-keys.html>` from the
      organization and project names in the path.

   The ``.complete`` metadata file is in |json| format and contains 
   the following fields: 

   .. list-table::
      :header-rows: 1
      :widths: 35 65

      * - Request Body Field
        - Description

      * - ``orgId``
        - Unique 24-hexadecimal digit string that identifies the
          |service| organization.

      * - ``orgName``
        - Name of the |service| organization.

      * - ``groupId``
        - Unique 24-hexadecimal digit string that identifies the
          project in the |service| organization.

      * - ``groupName``
        - Name of the |service| project.

      * - ``clusterUniqueId``
        - Unique 24-hexadecimal digit string that identifies the
          |service| cluster.

      * - ``clusterName``
        - Name of the |service| project.

      * - ``snapshotInitiationDate``
        - Date when snapshot was taken.

      * - ``totalFiles``
        - Total number of files uploaded to the object store.

      * - ``labels``
        - Labels of the {+cluster+} whose snapshot was exported.

      * - ``customData``
        - Custom data, if any, that you specified when creating the
          export job.

   .. example::

      .. code-block:: json
         :copyable: false

         {
           "orgId": "60512d6f65e4047fe0842095",
           "orgName": "org1",
           "groupId": "60512dac65e4047fe084220f",
           "groupName": "group1",
           "clusterUniqueId": "60512dac65e4047fe0842212",
           "clusterName": "cluster0",
           "snapshotInitiationDate": "2020-04-03T05:50:29.321Z"
           "totalFiles": 23,
           "labels": [
             {
               "key": "key1",
               "value": "xyz"
             },
             {
               "key": "key2",
               "value": "xyzuio"
             }
           ],
           "customData": [
             {
               "key": "key1",
               "value": "xyz"
             },
             {
               "key": "key2",
               "value": "xyzuio"
             }
           ]
         }

.. collapsible:: 
   :heading: metadata.json Metadata File
   :sub_heading: Exported metadata file that contains information about the exported collection, including its indexes and options.
   :expanded: false

   For each collection in the snapshot export job, {+service+} uploads a
   metadata file named ``metadata.json`` to the following path on your
   object store:

   .. code-block:: shell
      :copyable: false

      /exported_snapshots/<orgUUID>/<projectUUID>/<clusterName>/<initiationDateOfSnapshot>/<timestamp>/<dbName>/<collectionName>/metadata.json

   .. note::

      By default, |service| uses organization and project UUIDs in
      the path for the metadata files. To use organization and
      project names instead of UUIDs, set the
      ``useOrgAndGroupNamesInExportPrefix`` flag via the
      :oas-bump-atlas-op:`API
      <updategroupclusterbackupschedule>` to true.
      |service| replaces any spaces with underscores (``_``) and
      removes any :aws:`characters that might require special
      handling </AmazonS3/latest/userguide/object-keys.html>` and
      :aws:`characters to avoid
      </AmazonS3/latest/userguide/object-keys.html>` from the
      organization and project names in the path.

   The metadata file is in |json| format and contains the following
   fields:

   .. list-table::
      :header-rows: 1
      :widths: 35 65

      * - Request Body Field
        - Description

      * - ``collectionName``
        - Human-readable label that identifies the collection.

      * - ``indexes``
        - List of all the indexes on the collection in the format
          returned by :manual:`db.collection.getIndexes
          </reference/method/db.collection.getIndexes/#output>`
          command.

      * - ``options``
        - Configuration options defined on the collection. To learn
          more about the options, see :manual:`db.createCollection()
          </reference/method/db.createCollection/>` command.

      * - ``type``
        - (Optional) Type of collection. This field is only supported
          for time series collections, with a value of
          ``timeseries``. Leave this field unset for standard
          collections.

          |service| doesn't support export of ``view`` type
          collections.

      * - ``uuid``
        - Collection's UUID. To learn more about UUID, see
          :manual:`UUID </reference/method/UUID/>`.

   .. example::

      .. code-block:: json
         :copyable: false

         {
           "options":{
             "viewOn":"othercol",
             "pipeline":[{"$project":{"namez":"$name"}}]
           },
           "indexes":[],
           "collectionName":"viewcol",
           "type":"view"
         }

      .. code-block:: json
         :copyable: false

         {
           "options":{
             "timeseries":{
               "timeField":"timestamp",
               "granularity":"seconds",
               "bucketMaxSpanSeconds":{"$numberInt":"3600"}
             }
           },
           "indexes":[],
           "collectionName":"timeseriescol",
           "type":"timeseries"
         }

      .. code-block:: json
         :copyable: false

         {
           "indexes": [
             {
               "v":{"$numberInt":"2"},
               "key":{
                 "_id":{"$numberInt":"1"}
               },
               "name":"_id_"
             }
           ],
           "uuid":"342c40a937c34c478bab03de8ce44f3e",
           "collectionName":"somecol"
         }

Export to Your Cloud Provider
-----------------------------

The steps to export {+Cloud-Backup+} snapshots depend on your object
storage service. To set up |service| access, configure an export
bucket, and export snapshots, see the page for your cloud provider:

.. card-group::
   :columns: 3
   :style: compact

   .. card::
      :cta: AWS S3
      :url: https://www.mongodb.com/docs/atlas/backup/cloud-backup/export/aws-s3/

      Export snapshots to |aws| |s3| buckets, including over
      PrivateLink.

   .. card::
      :cta: Azure Blob Storage
      :url: https://www.mongodb.com/docs/atlas/backup/cloud-backup/export/azure-blob-storage/

      Export snapshots to {+az-bs+} containers.

   .. card::
      :cta: Google Cloud Storage
      :url: https://www.mongodb.com/docs/atlas/backup/cloud-backup/export/google-cloud-storage/

      Export snapshots to {+gcs+} buckets.
