======================
Run a Database Command
======================

Overview
--------

In this guide, you can learn how to use the {+driver-short+} to
run a database command. You can use database commands to perform a
variety of administrative and diagnostic tasks, such as fetching server
statistics, initializing a replica set, or running an aggregation pipeline.

.. important:: Prefer Driver Methods to Database Commands

   The driver provides wrapper methods for many database commands.
   If possible, we recommend using these methods instead of executing
   database commands.

   To perform administrative tasks, use the :mongosh:`MongoDB Shell </>`
   instead of the {+driver-short+}. The shell provides helper methods
   that might not be available in the driver.

   If there are no available helpers in the driver or the shell, you
   can use the ``db.runCommand()`` shell method or the driver's
   ``command`` and ``cursor_command`` methods, which are described in
   this guide.

``command`` Response
~~~~~~~~~~~~~~~~~~~~

The ``command`` method returns a ``Mongo::Operation::Result`` that contains
the response from the database for the given command.

You can access the fields of the raw command response document by using the following
methods:

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Method
     - Description

   * - ``acknowledged?``
     - Returns ``true`` if the server acknowledged the command, and ``false`` otherwise.

   * - ``inspect``
     - Returns a formatted string representation of the command response.

   * - ``ok?``
     - Returns ``true`` if the command succeeded, and ``false`` otherwise. If the ``ok?``
       method returns ``false``, the driver raises a ``Mongo::Error::OperationFailure`` .

   * - ``cluster_time``
     - Returns the cluster time reported in the server response. Cluster time is a
       logical time used for the ordering of operations. This field only
       applies to commands run on replica sets or sharded cluster.

   * - ``operation_time``
     - Returns the logical time of the operation execution.

For a full list of methods available on the ``Result`` object, see
the :ruby-api:`API documentation <Operation/Result.html>`.

.. tip::

   To learn more about logical time, see the Wikipedia entry on
   the :wikipedia:`logical clock <w/index.php?title=Logical_clock&oldid=1072010149>`.

Use the ``cursor_command`` Method
---------------------------------

Some database commands return their results in a cursor. To run these
commands, call the ``cursor_command`` method on your ``Mongo::Database``
instance. This method returns a ``Mongo::Cursor`` object that retrieves
additional batches of results from the server as you iterate over it. If
the command response doesn't contain a cursor, the driver raises a
``Mongo::Error::InvalidCursorOperation`` error.

Command Options
---------------

You can pass the following options to the ``command`` and
``cursor_command`` methods:

.. list-table::
   :header-rows: 1
   :widths: 20 25 55

   * - Option
     - Methods
     - Description

   * - ``:read``
     - ``command``, ``cursor_command``
     - The read preference to use for the command. The
       ``cursor_command`` method also uses this read preference for
       subsequent ``getMore`` commands. By default, both methods use
       the ``primary`` read preference.

   * - ``:session``
     - ``command``, ``cursor_command``
     - The session to use for the command. If you don't specify a
       session for the ``cursor_command`` method, the driver creates an
       implicit session that lasts for the lifetime of the cursor.

   * - ``:timeout_ms``
     - ``command``, ``cursor_command``
     - The operation timeout, in milliseconds. The value must be a
       non-negative integer. A value of ``0`` means no timeout. If you
       don't set this option, the method inherits the timeout from the
       database or the client.

   * - ``:batch_size``
     - ``cursor_command``
     - The ``batchSize`` value to send on ``getMore`` commands.

   * - ``:max_time_ms``
     - ``cursor_command``
     - The ``maxTimeMS`` value to send on ``getMore`` commands. To set
       a time limit on the initial command, include the ``maxTimeMS``
       field in the command document.

   * - ``:comment``
     - ``cursor_command``
     - A comment to attach to ``getMore`` commands.

   * - ``:cursor_type``
     - ``cursor_command``
     - The cursor type, either ``:tailable`` or ``:tailable_await``.
       This value must match the flags set in the command document.

   * - ``:timeout_mode``
     - ``cursor_command``
     - The timeout mode, either ``:cursor_lifetime`` or ``:iteration``.
