Compliance and Certification
----------------------------

FedRAMP Certification
~~~~~~~~~~~~~~~~~~~~~

|cloudgov| is a dedicated, isolated environment for U.S.
public-sector workloads, certified at FedRAMP® Class D (formerly
called FedRAMP® High). |cloudgov-short| is designed to
meet the security and compliance requirements of sensitive and
high-impact government workloads.

Regions certified for {+fedramp-d+} include |aws-fr-high| (US)
regions, |gaw| (US) regions, and |azure-gov| (US) regions.

|aws-fr-moderate| (US) regions are certified at FedRAMP® Class C
(formerly called FedRAMP Moderate). To learn more, see
:ref:`supported-regions`.

To learn more, visit the `official FedRAMP site
<https://www.fedramp.gov/>`__.

For questions about the |cloudgov-short| certification, or to
request compliance documentation, contact your MongoDB account
team or see the `MongoDB Trust Center
<https://www.mongodb.com/products/platform/trust/>`__.

Compliance
~~~~~~~~~~

MongoDB operates |cloudgov-short| under a shared responsibility
model, and |cloudgov| is covered by a dedicated SOC 2 Type II
report.

|cloudgov-short| supports workloads that handle personally
identifiable information (PII), protected health information
(PHI), and Criminal Justice Information Services (CJIS) data, such
as criminal justice systems, healthcare platforms, and
public-facing services. |avs| supports production AI and
retrieval-augmented generation (RAG) use cases within the
{+fedramp-d+} environment. To learn more, see
:ref:`atlas-gov-search`.

|cloudgov-short| runs on all three major cloud providers, so you
can migrate clusters between providers and avoid single-cloud
lock-in. This multi-cloud flexibility is valuable for agencies
looking to modernize their infrastructure. If your workloads no
longer require a government environment, you can migrate your
clusters to commercial |service|.

Encryption
~~~~~~~~~~

|cloudgov-short| encrypts data at rest and in transit by default,
and offers encryption in use for a stronger security posture:

- **In transit**: |cloudgov| and databases hosted in
  |cloudgov-short| support |tls| 1.2 and 1.3 to encrypt
  connections. You cannot disable |tls|. Additionally,
  :ref:`Queryable Encryption <qe-manual-feature-qe>` encrypts
  sensitive fields throughout the query lifecycle and decrypts them
  only on the client.

- **At rest**: |cloudgov-short| always encrypts your data at rest.
  Optionally, you can use customer-managed keys. To learn more, see
  Encryption at Rest on this page.


Preconfigured Security Features
-------------------------------

|tls|
~~~~~

|cloudgov| and databases hosted in |cloudgov-short| support
|tls| 1.2 and 1.3 to encrypt connections. You cannot disable
|tls|.

|fips| 140-3
~~~~~~~~~~~~

|cloudgov-short| automatically enables |fips| 140-3 for all
MongoDB-managed infrastructure.

Required Security Features
--------------------------

You *must* configure the following security features:

- :ref:`IP access list <allow-ip>`, and

- :ref:`Database user authentication <database-access>`.

Optional Security Features
--------------------------

A subset of commercial |service|
:atlas:`optional security features </setup-cluster-security/#optional-security-features>`
are available in |cloudgov-short| with some limitations.

Encryption at Rest
~~~~~~~~~~~~~~~~~~

If you choose to enable customer-managed keys (CMK), you must use
KMS keys in |aws-fr-high|, |gaw|, or |azure-gov| regions for
|cloudgov-short| projects restricted to {+fedramp-d+} regions. For
|aws-fr-moderate| region-only projects, you must use KMS keys in
|aws-fr-moderate| regions.

To learn more, see :atlas:`Customer Key Management with AWS KMS
</security-aws-kms/>` and :atlas:`Manage Customer Keys with Google
Cloud KMS </security-gcp-kms/>` in the |service| documentation.

.. _atlasgov-encryption-in-use:

Encryption in Use
~~~~~~~~~~~~~~~~~

|cloudgov-short| supports :ref:`Queryable Encryption
<qe-manual-feature-qe>`. Queryable Encryption:

- Helps you protect sensitive data in use without changing how you
  query it.

- Encrypts sensitive fields throughout the query lifecycle and
  decrypts them only on the client.


.. _atlasgov-vpc-peering:

|vpc| Peering in |cloudgov-short|
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- You can peer |aws-fr-high| regions with MongoDB clusters only in
  |aws-fr-high| regions. You can peer |aws-fr-moderate| regions
  with MongoDB clusters only in |aws-fr-moderate| regions.
- You can peer |gaw| regions with MongoDB clusters only in
  |gaw| regions.
- You can peer |azure-gov| regions with MongoDB clusters only in
  |azure-gov| regions.

To learn more, see :atlas:`Set up a Network Peering Connection
</security-vpc-peering/>` in the |service| documentation.

Private Endpoints
~~~~~~~~~~~~~~~~~

- You can link |aws-fr-high| regions with MongoDB clusters only in
  |aws-fr-high| regions. You can link |aws-fr-moderate| regions
  with MongoDB clusters only in |aws-fr-moderate| regions.
- You can link |gaw| regions with MongoDB clusters only in
  |gaw| regions.
- You can link |azure-gov| regions with MongoDB clusters only in
  |azure-gov| regions.

To learn more, see :atlas:`Set up a Private Endpoint
</security-private-endpoint/>` in the |service| documentation.

To learn more, see :atlas:`Configure a Backup Compliance Policy

Outbound IP Addresses
~~~~~~~~~~~~~~~~~~~~~

You can use the following endpoints:

- Use the :oas-bump-atlas-op:`Return All IP Addresses for One Project
  <getgroupipaddresses>` endpoint to retrieve all outbound IP
  addresses for the clusters in your project. To use this endpoint,
  your API key must have the :authrole:`Project Read Only` role.

- Use the :oas-bump-atlas-op:`Return All Control Plane IP Addresses
  <listcontrolplaneipaddresses>` endpoint to retrieve all outbound
  IP addresses for the Atlas control plane, categorized by cloud
  provider.
