   .. _manage-private-endpoint-connection-strings:

   Manage Private Endpoint Connection Strings
   ------------------------------------------

   .. include:: /includes/fact-private-endpoint-connection-strings-preview.rst

   The following procedures describe how to opt your project in to
   private endpoint connection strings and how to create, view,
   edit, and delete them. To learn how connection strings work, see
   :ref:`private-endpoint-connection-strings-resource`.

   .. _enable-private-endpoint-connection-strings:

   Enable or Disable Private Endpoint Connection Strings
   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   The private endpoint connection strings setting defaults to
   disabled for each project. When you enable it, |service| imports
   the project's existing private endpoint-aware connection strings
   as read-only records. The import doesn't change any |dns|
   records, so your existing connection strings continue to resolve.
   If the process is interrupted, enable the setting again to resume
   it.

   When you disable the setting, your project returns to the
   default private endpoint-aware connection string behavior, and
   |service| removes the imported connection string records.
   |service| prevents you from disabling the setting until you
   resolve certain issues. For example, you must first delete any
   self-managed connection strings in the project. The error message
   lists each issue and its resolution.

   To enable or disable the setting:

   .. procedure::
      :style: normal

      .. include:: /includes/nav/steps-project-settings.rst

      .. step:: Enable or disable the private endpoint connection
         strings setting.

   Create a Private Endpoint Connection String
   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   To create a connection string:

   .. procedure::
      :style: normal

      .. include:: /includes/nav/steps-network-access.rst

      .. step:: Navigate to the connection strings for your
         dedicated cluster.

         a. In the sidebar, click :guilabel:`Private Endpoint`.

         #. In the sidebar, click :guilabel:`Dedicated Cluster`.

         #. Click the :guilabel:`Connection Strings` tab.

      .. step:: Click :guilabel:`Create connection string`.

      .. step:: Select a {+cluster+} from the :guilabel:`Cluster`
         dropdown.

         The dropdown displays high-level information about each
         {+cluster+}. :guilabel:`Continue` remains disabled until
         you select a {+cluster+}.

      .. step:: Enter a :guilabel:`Connection String Name`.

         The {+atlas-ui+} pre-fills a default name, such as
         ``ConnectionString0``. Connection string names must be
         unique within the project.

      .. step:: Click :guilabel:`Continue`.

      .. step:: Select the endpoints to include in the connection
         string.

         a. Expand an :guilabel:`Atlas Endpoint Service Region`
            group and select its endpoints. To learn which
            endpoints your {+cluster+}'s topology requires, check
            the :guilabel:`Private Endpoint Connection String
            Tips` panel or see :ref:`pecs-selection-rules`.

         #. Optional. For an eligible sharded {+cluster+} on
            |aws|, leave :guilabel:`Create an Optimized Connection
            String` toggled on to create an :ref:`optimized
            connection string <optimized-connection-strings>`.

         #. Click :guilabel:`Continue`.

         If the selection is invalid, the page displays an error
         that identifies the failed rule and how to resolve it.

      .. step:: Review your selection, then click
         :guilabel:`Generate String`.

   |service| validates the connection string after you click
   :guilabel:`Generate String`:

   - The connection string displays a :guilabel:`Pending` status
     until validation completes. |service| notifies you when the
     connection string is ready to use.

   - If validation fails, the connection string displays an
     :guilabel:`Error` status. Select the link in the notification
     to view the error details.

   View Private Endpoint Connection Strings
   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   The :guilabel:`Connection Strings` tab lists each connection
   string's name, ID, endpoints included, status, last updated time,
   and available actions.

   To view your connection strings:

   .. procedure::
      :style: normal

      .. include:: /includes/nav/steps-network-access.rst

      .. step:: Navigate to the connection strings for your
         dedicated cluster.

         a. In the sidebar, click :guilabel:`Private Endpoint`.

         #. In the sidebar, click :guilabel:`Dedicated Cluster`.

         #. Click the :guilabel:`Connection Strings` tab.

   Edit a Private Endpoint Connection String
   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   You can edit only self-managed connection strings. Imported
   connection strings are read-only. To learn more, see
   :ref:`private-endpoint-connection-strings-resource`.

   To edit a connection string:

   .. procedure::
      :style: normal

      .. include:: /includes/nav/steps-network-access.rst

      .. step:: Navigate to the connection strings for your
         dedicated cluster.

         a. In the sidebar, click :guilabel:`Private Endpoint`.

         #. In the sidebar, click :guilabel:`Dedicated Cluster`.

         #. Click the :guilabel:`Connection Strings` tab.

      .. step:: In the :guilabel:`Actions` column of the connection
         string, click :guilabel:`Edit`.

   |service| validates your changes against the
   :ref:`endpoint selection rules <pecs-selection-rules>`.

   Delete a Private Endpoint Connection String or Endpoint
   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   Before you delete a connection string, update any applications
   that use it. After you delete a connection string, it stops
   resolving and clients can no longer use it to connect.

   To delete a connection string:

   .. procedure::
      :style: normal

      .. include:: /includes/nav/steps-network-access.rst

      .. step:: Navigate to the connection strings for your
         dedicated cluster.

         a. In the sidebar, click :guilabel:`Private Endpoint`.

         #. In the sidebar, click :guilabel:`Dedicated Cluster`.

         #. Click the :guilabel:`Connection Strings` tab.

      .. step:: In the :guilabel:`Actions` column of the connection
         string, click :guilabel:`Delete`.

   You can't delete a private endpoint while a connection string
   uses it. To find the connection strings that use an endpoint,
   check the endpoint's :guilabel:`Used in Connection Strings`
   column on the :guilabel:`Atlas Endpoint Services` tab.

   To delete an in-use endpoint, do one of the following steps:

   - Remove the endpoint from the connection strings that use it.

   - Delete those connection strings.

   .. note::

      If you pause or delete a {+cluster+}, |service| deletes its
      connection strings. Resuming a paused {+cluster+} doesn't
      restore them. Create a new connection string if needed.

   .. _pecs-region-add-guardrail:

   Add a Region to a Cluster with Connection Strings
   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   When you add a region to a multi-region {+cluster+}, |service|
   verifies that the change doesn't break your existing connection
   strings. |service| blocks the region addition if it would leave
   a connection string without endpoint coverage in the new region.
   The error names each affected connection string and how to
   resolve the issue.

   To proceed with the region addition, do one of the following for
   each affected connection string:

   - Create a private endpoint in the new region, then edit the
     connection string to include that endpoint. You can add an
     endpoint to a connection string before the {+cluster+} has
     nodes in that region.

   - Delete the connection string.

   Connection strings that select endpoints in a single region,
   such as regionalized strings for sharded {+clusters+}, don't
   block region additions.

   .. _manage-remote-regions:

   Manage Accepted Endpoint Regions
   --------------------------------

   .. selected-content::
      :selections: aws, None

      You can configure which |aws| regions can connect to your
      private endpoint service. This enables cross-region private
      endpoint connectivity, allowing applications in different |aws|
      regions to connect to your {+service+} clusters through private
      endpoints.

      To add or remove accepted endpoint regions from the
      {+atlas-ui+}:

      .. include:: /includes/steps-manage-accepted-endpoint-regions-aws.rst

   .. selected-content::
      :selections: azure, None

      {+az-pl+} doesn't use accepted endpoint regions. To connect to a
      private endpoint from a different |azure| region, select that
      region from the :guilabel:`Private Endpoint Region` list when you
      create the private endpoint. To learn more, see
      :ref:`manage-accepted-endpoint-regions`.

   .. selected-content::
      :selections: gcp, None

      |gcp| private endpoints don't use accepted endpoint regions. To
      learn how to connect from a different region, see
      :ref:`manage-accepted-endpoint-regions`.
