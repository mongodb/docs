General Changes
---------------

Change Stream Pre-Image Metrics
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the
``changeStreamPreImages.purgingJob.docsDeleted`` and
``changeStreamPreImages.purgingJob.bytesDeleted`` serverStatus metrics
may report estimates rather than exact values. These estimates occur
when size and count information is not available for the
``config.system.preimages`` collection. For details, see
:ref:`server-status-changeStreamPreImages`.

MongoDB 9.0 also adds a new ``changeStreamPreImages.markerCreation``
serverStatus document. This document reports metrics related to the
pre-image sampling passes that build the initial truncation
information used to remove pre-images. For details, see
:ref:`server-status-changeStreamPreImages`.

Multi-Document Transaction Limit
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the server limits the number of concurrently
open multi-document transactions for external clients. When the number
of open transactions reaches the limit set by the
:parameter:`maxConcurrentMultiDocumentTransactions` parameter (default
``10000``), the server rejects new multi-document transactions and
returns a ``TooManyOpenTransactions`` error. To learn more, see
:parameter:`maxConcurrentMultiDocumentTransactions`.

Per-Operation Memory Limit
~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, MongoDB limits the total amount of memory
that a single query operation can use. By default, the limit is 1
gigabyte or 20% of the memory available to the server process,
whichever is greater. Operations that exceed the limit fail with
:error:`ExceededMemoryLimit <146>` or
:error:`QueryExceededMemoryLimitNoDiskUseAllowed <292>`. In earlier
versions, an operation could use an unbounded amount of memory.

The 100 megabyte per-stage memory limit and the spill-to-disk
behavior of individual stages are unchanged. To learn more, see
:ref:`operation-memory-limit`.

Server-side JavaScript
~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the server-side JavaScript functions
(:group:`$accumulator`, :expression:`$function`, and :query:`$where`)
are no longer deprecated. MongoDB 9.0 re-enables these functions using a
WebAssembly (WASM)-based JavaScript engine, which improves security
through stronger sandboxing and isolation than prior versions. These
functions were previously deprecated in MongoDB 8.0. To learn more, see
:ref:`server-side-javascript`.

Renamed Server Status Metrics
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 renames the
``shardingStatistics.databaseVersionUpdateCounters`` document,
introduced in MongoDB 8.3, to
:serverstatus:`shardingStatistics.databaseShardingMetadataStatistics`.
MongoDB 9.0 also replaces the fields of the renamed document with a
new set of metrics.

MongoDB 9.0 renames the ``metrics.changeStreams.showExpandedEvents``
metric to :serverstatus:`metrics.changeStreams.option.showExpandedEvents`.
If you monitor the metric by name, update your monitoring to use the new
name.

Sharding
--------

``checkMetadataConsistency`` Inconsistency Types
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the following :dbcommand:`checkMetadataConsistency`
:ref:`inconsistency types <inconsistency-types>`:

- :data:`AuthoritativeShardCatalogCollectionsPresent`
- :data:`IncompatibleUniqueIndexOnShardedCollection`
- :data:`InconsistentShardCatalogCollectionMetadata`
- :data:`LegacyShardCacheCollectionsPresent`

MongoDB 9.0 removes the ``ShardCatalogCacheCollectionMetadataMismatch``
inconsistency type.

``checkMetadataConsistency`` Chunk Check Threshold
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds a ``performStrictChunkChecksIfBelowThreshold`` option
to the :dbcommand:`checkMetadataConsistency` command. Use this option
to set a chunk-count threshold for a shard's chunk comparison. Below
the threshold, the command performs a full comparison. At or above
it, the command performs a lighter, count-only comparison. For
details, see :ref:`checkMetadataConsistency-chunk-check-threshold`.

Cursor Namespace in Command Responses
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, when you run a ``find``, ``aggregate``, or ``listIndexes``
command on a time series collection, the ``cursor.ns`` field in the
response returns the user-facing namespace you originally targeted. In previous
versions, the server could return the internal namespace.

Change Stream Shard Targeting
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, change streams on sharded clusters open
cursors only on the shards that hold relevant data and adjust
targeting automatically as the cluster topology changes. MongoDB 9.0
also adds the ``ignoreRemovedShards`` parameter to the
:pipeline:`$changeStream` aggregation stage. When set to ``true``, a
change stream continues and skips events from a shard that was removed
from the cluster instead of returning an error. For details, see
:pipeline:`$changeStream`.

BSON Validation
~~~~~~~~~~~~~~~

MongoDB 9.0 deprecates the :setting:`net.wireObjectCheck` configuration option
and its corresponding ``--objcheck`` and  ``--noobjcheckand`` CLI arguments.
Starting in 9.0, MongoDB validates all BSON objects that the server ingests by
default. If the server receives invalid BSON data, MongoDB returns an error.

Document Validation
~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 introduces a new schema validation level of ``constraint``.
With the ``constraint`` validation level, MongoDB applies the validation
rules to all document inserts and updates, and guarantees that *every*
document in the collection satisfies the rules. For details, see
:ref:`upgrade-to-constraint-validation`.

Time Series
-----------

Data Storage
~~~~~~~~~~~~

Starting in 9.0, MongoDB stores time series collections as a single
namespace that contains time series data compressed into buckets. Time
series collections are no longer writable non-materialized views.

Aggregation
-----------

$queryStats Output
~~~~~~~~~~~~~~~~~~

MongoDB 9.0 updates the :pipeline:`$queryStats` output to streamline metrics
organization. This update includes the following new output fields:

.. list-table::
   :header-rows: 1
   :widths: 38 72

   * - Field
     - Description

   * - ``metrics.cursor``

     - A document that contains metrics relevant to the cursor and batching
       protocol

   * - ``metrics.queryExec``

     - A document that contains metrics relevant to query execution

   * - ``metrics.queryPlanner``

     - A document that contains metrics relevant to the query planner

   * - ``metrics.writes``

     - A document that contains metrics relevant to operation writes

For more information on the new output structure, see :ref:`$queryStats Output
<queryStats-output>`.

Command Support
```````````````

Starting in  9.0, MongoDB collections and reports query statistics for
:dbcommand:`update`, :dbcommand:`insert`, and :dbcommand:`delete`
commands. For details, see :ref:`queryStats-update-query-shape`,
:ref:`queryStats-insert-query-shape`, and
:ref:`queryStats-delete-query-shape`.

Query Stats Enabled by Default
``````````````````````````````

Starting in MongoDB 9.0, ``$queryStats`` collects stats by default for
both read and write operations. MongoDB collects stats for a sample of
operations rather than for every operation. MongoDB samples read
operations at the rate set by the
:parameter:`internalQueryStatsSampleRate` parameter and write operations
at the rate set by the
:parameter:`internalQueryStatsWriteCmdSampleRate` parameter. Both
parameters default to ``0.01``, which samples 1% of operations.

Because :pipeline:`$queryStats` reports only the operations that
MongoDB samples, its output represents a subset of the operations run
against your deployment.

Query Language
--------------

Null Comparisons on Dotted Paths
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, a dotted path that does not resolve to a
non-null value evaluates as ``null``. The new behavior applies when a
field in the path holds an empty array, an array of scalar values, or
an array that contains a nested array.
Comparisons to ``null`` that use the :query:`$eq`, :query:`$ne`,
:query:`$in`, :query:`$nin`, :query:`$gte`, and :query:`$lte`
operators reflect the new semantics. Equality matching in the
:pipeline:`$lookup` stage also reflects the new semantics. Queries
that compare a dotted path to ``null`` can return different results
after you upgrade. For details, see :ref:`9.0-compatibility`.

Security
--------

``useInternalAuthzForX509`` Parameter
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the :parameter:`useInternalAuthzForX509`
parameter. When set to ``true``, clients that authenticate
using ``MONGODB-X509`` use internal authorization,
even when LDAP authorization is configured. For details, see
:parameter:`useInternalAuthzForX509`.

``usersInfo`` ``authenticatedMechanism`` Field
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the ``authenticatedMechanism`` field to the
:dbcommand:`usersInfo` command. This optional string field
specifies an authentication mechanism to determine which
authorization backend ``usersInfo`` queries when looking up
user authorization information. For details, see
:dbcommand:`usersInfo`.

``mongocryptd`` Deprecated
~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, ``mongocryptd`` is deprecated. Use the
{+shared-library+} instead. The {+shared-library+} replaces
``mongocryptd`` and does not require you to start a separate process.
For details, see :ref:`csfle-reference-install-lib` and
:ref:`qe-csfle-install-library`.

Audit Log Improvements
~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the ``directRemote`` field to audit messages in
the ``mongo`` schema and the ``direct_endpoint`` field to audit
messages in the {+ocsf+} schema. These fields record the literal
TCP peer for a session, independent of any client address that a
PROXY protocol header asserts. For details, see
:ref:`event-audit-messages-mongo` and
:ref:`event-audit-messages-ocsf`.

Replication
-----------

New replSetGetStatus Metrics for Phase Tracking
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the following metrics are available when using
the :dbcommand:`replSetGetStatus` command during a logical initial sync:

- :data:`replSetGetStatus.initialSyncStatus.phase`
- :data:`replSetGetStatus.initialSyncStatus.totalAttempts`
- :data:`replSetGetStatus.initialSyncStatus.bytesPerSecond`

Each document in
:data:`~replSetGetStatus.initialSyncStatus.initialSyncAttempts` also
reports the ``phase``, ``nodeUptimeSecs``, and ``phaseDurations`` for that
attempt. For details, see
:data:`replSetGetStatus.initialSyncStatus.initialSyncAttempts`.

Diagnostics
-----------

Improved Diagnostics for Unindexable Documents
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, key-extraction failures on :ref:`2dsphere
<2dsphere-index>` indexes produce structured diagnostics that make
unindexable documents easier to identify:

- Geo key-extraction failures now throw the named error codes
  :error:`510` (``GeoKeyExtractionFailed``) and :error:`511`
  (``GeoKeyExtractionFailedTimeseries``), which replace the previous
  unnamed assertion codes.

- Failed geo inserts and index builds now include a
  ``writeErrors[].errInfo`` document that contains the ``failingPath``,
  ``underlyingCode``, ``underlyingReason``, and ``failingElement``
  fields. Existing field names are unchanged, but the error reason
  string is now bounded to 256 characters.

- The :data:`validate.errors` output for geo key-extraction failures
  now emits a bounded, self-contained message and writes full
  per-document detail to the :binary:`~bin.mongod` log. Identical
  failures on the same index and path are deduplicated into a single
  message, so to map a failure back to specific documents, consult the
  log instead of the :dbcommand:`validate` output. Full per-document
  detail is logged only when :ref:`log redaction
  <log-message-log-redaction>` is disabled. For details, see
  :dbcommand:`validate`.
