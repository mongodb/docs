===========================
Push Logs to AWS S3 bucket
===========================

.. meta::
   :description: Push logs from `mongod`, `mongos`, and audit logs to an AWS S3 bucket from an `M10+` cluster every 5 minutes using Atlas.

.. default-domain:: mongodb

.. facet::
   :name: genre
   :values: tutorial

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

You can continually push logs from ``mongod``, ``mongos``, and audit logs to an 
|aws| |s3| bucket from an ``M10+`` {+cluster+}.
|service| exports logs every 5 minutes.

Required Access
---------------

To push logs to an |aws| |s3| bucket, you must have 
:authrole:`Project Owner` or :authrole:`Organization Owner` access to 
|service|.

To push logs to an |aws| |s3| bucket using the {+atlas-admin-api+}, you 
must have :authrole:`Project Owner` access to |service|.

Considerations
--------------

- You can't specify which logs to send. |service| sends all ``mongod``, ``mongos``, and audit logs.
- Push-based log export doesn't support Bring Your Own Key (BYOK).
- You can only push logs to an |aws| |s3| bucket from an ``M10+`` |service| {+cluster+}.
- |service| doesn't export log lines over 10 MB.

.. _pble-eol:

End of Life and Migration
-------------------------

MongoDB is phasing out Push-Based Log Export in favor of
:ref:`external log sinks <export-logs>`, which offer 1-minute export
intervals, |aws| |kms| encryption, support for Multi-Region Access
Points, additional destinations, and per-destination log type
selection.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Date
     - Milestone

   * - February 4, 2026
     - Push-Based Log Export deprecated.

   * - September 2026
     - External log sinks are generally available and enabled for
       all accounts.

   * - October 30, 2026
     - Push-Based Log Export stops accepting new configurations.
       Existing exports continue to run uninterrupted.

   * - February 4, 2027
     - Push-Based Log Export reaches end of life. MongoDB no longer
       provides security updates, bug fixes, or technical support
       for push-based log export. Existing configurations continue
       to run until MongoDB retires the feature in coordination
       with your account team.

Migrate to External Log Sinks
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

To migrate from Push-Based Log Export to an external log sink,
complete the following steps.

.. procedure::
   :style: normal

   .. step:: Update your {+atlas-admin-api+} integrations.

      Replace calls to
      ``/api/atlas/v2/groups/{groupId}/pushBasedLogExport`` with
      calls to ``/api/atlas/v2/groups/{groupId}/logIntegrations``.

   .. step:: Create an |aws| |s3| log export integration.

      Configure the integration to use the same |aws| |iam| role
      and |s3| bucket as your push-based configuration. To preserve
      the push-based daily-folder path structure, set
      ``useLegacyPathStructure`` to ``true``. For configuration
      steps, see :ref:`export-logs-external-sinks`.

   .. step:: Validate log delivery.

      Confirm that |service| delivers logs to your bucket as
      expected. During this validation period, push-based log
      export and the external log sink both deliver logs, so your
      bucket contains duplicate entries.

   .. step:: Disable push-based log export.

      After you validate delivery, disable your push-based
      configuration. The duplicate deliveries stop.

If you encounter blockers during migration, contact |mdb-support|.

Prerequisites
-------------

You will need:

- an |aws| |iam| role with `sts:AssumeRole <https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html>`__ that grants |service| access to your |aws| resource with a maximum session duration set to 12 hours.
- an existing |aws| |s3| bucket.
- An ``M10+`` |service| {+cluster+}.

Procedure
---------

.. note::

   During the procedure, |service| creates a role policy to access the |s3| bucket with the following permissions:

   * `s3:ListBucket <https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListBuckets.html>`__
   * `s3:PutObject <https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html>`__
   * `s3:GetObject <https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html>`__
   * `s3:GetBucketLocation <https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetBucketLocation.html>`__
