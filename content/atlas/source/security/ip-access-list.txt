|service| only allows client connections to the {+database-deployment+}
from entries in the project's IP access list. Each entry is either a
single IP address or a |cidr|\-notated range of addresses. For |aws|
{+clusters+} with one or more :ref:`VPC Peering <vpc-peering>`
connections to the same |aws| region, you can specify a Security Group
associated with a peered |vpc|.

.. _find-your-public-ip:

Find Your Public IP Address
---------------------------

Before you add an entry to the IP access list, you must know
the public IP address that you want to grant access to. Use an
IP lookup tool, such as `whatismyipaddress.com
<https://whatismyipaddress.com/>`__, to find the public IP
address of the network you're connecting from.

If you connect from a virtual machine hosted on a cloud provider
instead of your own network, use that provider's console to find
the address:

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - Cloud Provider
     - Where to Find It

   * - |aws|
     - In the |aws| EC2 console, select your instance, then check
       the :guilabel:`Networking` tab for the
       :guilabel:`Public IPv4 address`.

   * - |gcp|
     - In the |gcp| console, go to the :guilabel:`VM instances`
       page. The :guilabel:`External IP` column shows the
       instance's public IP address.

   * - |azure|
     - In the |azure| portal, select your virtual machine, click
       :guilabel:`Networking`, then check the IP configuration for
       the network interface.

.. note::

   Public IP addresses for home and office networks can change
   over time. If you lose access to your {+cluster+} unexpectedly,
   verify that your current public IP address still matches an
   entry in the IP access list.

.. include:: /includes/fact-cidr-notation.rst

Manage IP Access List Entries
-----------------------------

.. note::

   .. sharedinclude:: cet/atlas/shared-responsibility-model-intro.rst

For |service| {+clusters+} deployed on :ref:`google-gcp` or
:ref:`microsoft-azure`, add the IP addresses of your |gcp| or |azure|
services to |service| project IP access list to grant those services
access to the {+cluster+}.

The IP access list applies to all {+database-deployment+}s in the
project and can have up to 200 IP access list entries, with the
following exception: projects with an existing sharded {+cluster+}
created *before* August 25, 2017 can have up to 100 IP access list
entries.

|service| supports creating temporary IP access list entries that
expire within a user-configurable 7-day period.

.. note::

   To restrict access to MongoDB {+atlas-ui+} for specific IP addresses,
   configure the UI IP Access List for your |service| organization.
   Although a standard IP Access List can't block access to the |service| UI,
   the UI IP Access List lets you restrict access to your |service|
   organization's management interface to only the trusted IP addresses
   or |cidr| ranges you specify. You can also restrict sign-in to {+atlas-ui+}
   through your |idp| authentication policies by using |service|
   federated authentication.
