.. _atlas-ui-read-preference:

=============================================
Configure Read Preference in the {+atlas-ui+}
=============================================

.. meta::
   :description: Set a read preference for your Atlas UI connection to route Data Explorer reads to secondary or analytics nodes, with optional tag sets and a maximum staleness value.

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

By default, the {+atlas-ui+} reads from the primary member of your
cluster. To send reads to a different member instead, such as an
:term:`analytics node <analytics node>`, set a
:ref:`read preference <replica-set-read-preference>` for your
connection.

.. important::

   Your read preference setting applies only to your current browser 
   session. After you close or reload the page, the {+atlas-ui+} uses the
   default read preference again.

Before You Begin 
----------------

To configure a read preference, you must have at least :authrole:`Project Data
Access Read Only` access to the project.

Steps
-----

.. procedure::
   :style: normal

   .. include:: /includes/nav/steps-data-explorer.rst

   .. step:: Disconnect from your cluster.

      You can't edit an active connection. In the
      :guilabel:`Connections` sidebar, click the
      :icon-fa5:`ellipsis-h` icon next to your cluster. In the
      drop-down menu that appears, click :guilabel:`Disconnect`.

   .. step:: Open the :guilabel:`Edit Connection` dialog box.

      Click the :icon-fa5:`ellipsis-h` icon next to your cluster. In
      the drop-down menu that appears, click
      :guilabel:`Edit connection`.

   .. step:: Select a read preference mode.

      Under :guilabel:`Read Preference`, select one of the following
      modes:

      - :guilabel:`Default`, which leaves the read preference unset so
        that the {+atlas-ui+} reads from the primary
      - :guilabel:`Primary`
      - :guilabel:`Primary Preferred`
      - :guilabel:`Secondary`
      - :guilabel:`Secondary Preferred`
      - :guilabel:`Nearest`

      To learn how each mode routes reads, see
      :ref:`replica-set-read-preference-modes`.

   .. step:: Optional. Specify read preference tags and max staleness.

      If you select :guilabel:`Primary Preferred`,
      :guilabel:`Secondary`, :guilabel:`Secondary Preferred`, or
      :guilabel:`Nearest`, you can also set the following fields:

      - :guilabel:`Read Preference Tags`: Enter each tag set as
        comma-separated ``key:value`` pairs, such as
        ``nodeType:ANALYTICS,region:US_EAST_1``. To add another tag
        set, click the :icon-lg:`Plus` icon.

        The {+atlas-ui+} tries tag sets in order. To fall back to any
        eligible member when no member matches your tag sets, leave the
        last tag set empty. To learn which tags |service| applies to
        your cluster nodes, see :ref:`replica-set-tags`.

      - :guilabel:`Max Staleness Seconds`: The maximum
        :manual:`replication lag </core/read-preference-staleness/>`,
        in seconds, that a secondary can have and still be eligible for
        reads. You must set :guilabel:`Max Staleness Seconds` to at least 
        ``90``.

   .. step:: Click :guilabel:`Connect`.

      The {+atlas-ui+} reconnects to your cluster and routes reads
      according to your read preference.

Example
-------

To read only from the analytics nodes in your cluster, set the
following values in the :guilabel:`Edit Connection` dialog box:

- :guilabel:`Read Preference`: :guilabel:`Secondary`
- :guilabel:`Read Preference Tags`: ``nodeType:ANALYTICS``
