=======================
Toggle Telemetry Status
=======================

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 2
   :class: singlecol

Enable or disable telemetry collection for your |mms| installation.

.. important::

   Starting in |mms| 9.0.2 and 8.0.28, this endpoint turns product
   usage telemetry on or off. Turning it off requires an active
   telemetry exemption on the installed license key. |mms| checks
   the license key on every request. To learn how to request an
   exemption, see :ref:`Telemetry Exemption
   <om-product-usage-telemetry-exemption>`.

Required Roles
--------------

This endpoint requires an API key that has the :authrole:`Global Owner` role.

--------

   * - Name
     - Type

   * - enabled
     - boolean
     - required
     - Set to ``true`` to enable telemetry, or ``false`` to disable
       telemetry. Starting in |mms| 9.0.2 and 8.0.28, ``false``
       turns off product usage telemetry: |mms| stops collecting
       and sending it, and ``next_job`` becomes ``null``. Setting
       ``false`` requires an active telemetry exemption on the
       installed license key. To learn how to request an exemption,
       see :ref:`Telemetry Exemption
       <om-product-usage-telemetry-exemption>`

403 Response Without an Exemption
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

This section applies to |mms| 9.0.2, 8.0.28, and later.

If you disable product usage telemetry without an active telemetry
exemption on the installed license key, the endpoint returns a
``403`` error and makes no change. The error body reads:

.. code-block:: json

   { "details": "Product usage collection requires a license
     telemetry exemption", "error": "Forbidden" }

The :ref:`Retrieve Telemetry Data
<om-get-telemetry-collection-details>` endpoint still reports
``"enabled": true``. With an active exemption, the request succeeds
and returns an empty JSON object (``{}``).
