.. _agentengine_memory_configure:

agentengine memory configure
----------------------------

Upload project-level memory server configuration.

Synopsis
~~~~~~~~

Upload the ‘memory:’ section of a project-config.yaml to the project’s
stored memory config.

With no [path], the file is resolved the way ‘agentengine dev up’
resolves it: the nearest stack marker (an agent.yaml or a memory-only
project marker) is found first, then the nearest project-config.yaml at
or above that stack root, stopping at the repository root (a directory
containing a .git directory). Only when no stack is found does it fall
back to project-config.yaml in the current directory. A stack that
resolves with no project-config.yaml is an error.

Only the memory sub-document is stored. The config is delivered to the
memory server by a background worker and before the next ‘agentengine
deploy’, but the memory server reads its config only at startup: run
‘agentengine memory apply’ to make it take effect.

Memory is project-scoped. The target project comes from --context, this
directory’s pin, or explicit target flags. No initialized agent
directory is required.

Examples:

.. code-block:: bash

    agentengine memory configure 
    agentengine memory configure --context production

.. code-block:: bash

   agentengine memory configure [path] [flags]
