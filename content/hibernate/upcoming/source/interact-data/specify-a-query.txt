Specify a Query
===============

Overview
--------

In this guide, you can learn how to use the {+extension-long+} to specify
a database query.

You can refine the set of documents that a query returns by creating a
**query filter**. A query filter is an expression that specifies the search
criteria MongoDB uses to match documents in a read or write operation.
To create MongoDB query filters, use Hibernate Query Language (HQL) or
Jakarta Persistence Query Language (JPQL) statements.

.. tip::

   To learn more about HQL and JPQL syntax, see `A Guide to Hibernate Query Language
   <{+query-guide+}>`__ in the {+orm+} documentation.

.. note:: Query Support

   The {+extension-long+} does not support all MongoDB and Hibernate query features. To learn more,
   see :ref:`Query Support <hibernate-mongo-query-support>` on the Feature Compatibility
   page.

.. _hibernate-query-null-comparison:

Compare Field Values to Null
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

When you compare a field to ``null`` by using a comparison operator,
the {+extension-short+} applies MongoDB Query Language null semantics
instead of the ternary logic that {+orm+} defines.

.. note:: Hibernate Ternary Logic for ``null``

   {+orm+} v6.3 and later evaluate a comparison to ``null`` as
   ``null``, which a predicate treats as ``false``. The
   {+extension-short+} does not implement this behavior. To learn more
   about which features the {+extension-short+} supports, see
   :ref:`Data Type Support <hibernate-data-support>` on the Feature
   Compatibility page.

MongoDB comparison operators evaluate both a missing field and a field
that stores an explicit ``null`` value to ``null``. As a result, a
``= null`` comparison matches documents in which the field stores
``null`` and documents in which the field is absent. A ``<> null`` or
``!= null`` comparison matches documents in which the field stores any
other value.

The following example uses the ``=`` operator to retrieve documents
that have a ``null`` or missing ``cast`` value from the
``sample_mflix.movies`` collection:

.. tabs::

   .. tab:: Session
      :tabid: session

      .. io-code-block::
         :copyable:

         .. input:: /includes/interact-data/Query.java
            :start-after: start-null-comparison-query-session
            :end-before: end-null-comparison-query-session
            :language: java
            :dedent:

         .. output::
            :visible: false

            ...
            Title: Song of Lahore
            Title: A Sinner in Mecca
            Title: Very Semi-Serious

   .. tab:: EntityManager
      :tabid: entitymanager

      .. io-code-block::
         :copyable:

         .. input:: /includes/interact-data/Query.java
            :start-after: start-null-comparison-query-em
            :end-before: end-null-comparison-query-em
            :language: java
            :dedent:

         .. output::
            :visible: false

            ...
            Title: Song of Lahore
            Title: A Sinner in Mecca
            Title: Very Semi-Serious

The {+extension-short+} translates this query to the
following ``$match`` stage:

.. code-block:: json
   :copyable: false

   {
     "$match": {
       "cast": { "$eq": null }
     }
   }

Comparisons that use the ``>``, ``>=``, ``<``, and ``<=`` operators
follow the :ref:`MongoDB BSON comparison order <bson-types-comparison-order>`
for non-existent fields. Because ``null`` is its own BSON type,
A ``>= null`` or ``<= null`` comparison matches documents in which the field stores
``null`` or is missing. A ``> null`` or ``< null`` comparison matches no documents.

To match ``null`` and missing values by using a predicate instead of a
comparison operator, see the :ref:`hibernate-query-is-null` and
:ref:`hibernate-query-is-not-null` sections of this guide.

.. _hibernate-query-expressions:

Use Computed Expressions
------------------------

You can compute a value from field values, literals, and query
parameters. You can then return that value in a ``SELECT`` clause or
compare it in a ``WHERE`` clause. The {+extension-short+}
translates a computed expression to a MongoDB aggregation
expression.

The {+extension-short+} supports the following arithmetic operators
in computed expressions:

- ``+``: Addition, which translates to ``$add``
- ``-``: Subtraction, which translates to ``$subtract``
- ``*``: Multiplication, which translates to ``$multiply``
- ``/``: Division, which translates to ``$divide``
- Unary ``-`` and ``+``

.. note:: Division Always Returns an Integer

   The {+orm+} translates division in a MongoDB aggregation pipeline to 
   the MongoDB ``$divide`` operator, which always returns a double. The
   {+extension-short+} truncates the result by wrapping ``$divide`` in
   ``$toInt``, or ``$toLong`` if the result type is ``BIGINT``. This
   behavior applies to the ``/`` operator and the
   Criteria API ``quot()`` method, regardless of whether you enable the
   {+orm+} ``PORTABLE_INTEGER_DIVISION`` setting.

   The ``div`` operator is not supported.

You can also use the comparison operators described in the
:ref:`hibernate-query-comparison` section within computed
expressions.

.. important:: Operand Limitations

   An operand of a computed expression must be a field reference, a
   literal, or a query parameter. The {+extension-short+} does not
   support function calls as operands. 
   
   Because {+orm+} rewrites the HQL ``%`` operator to a ``mod()`` function call, 
   ``%`` is also unsupported. To perform a modulo operation, use the Criteria API
   ``CriteriaBuilder.mod()`` method, which translates to the MongoDB
   ``$mod`` operator. 
   
   The Criteria API ``CriteriaBuilder.quot()``
   method behaves identically to the ``/`` operator.

.. _hibernate-query-computed-filter:

Filter on a Computed Expression
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

In the ``WHERE`` clause, you can compare a computed expression to a value
or compare two field values to each other. When either
side of a comparison is not a direct field reference or value, the
{+extension-short+} wraps the comparison in the MongoDB
:manual:`$expr </reference/operator/query/expr>` operator. Comparisons
between a field and a value continue to use the compact
``{ field: { operator: value } }`` form.

The following example retrieves ``"Hairspray"`` movies released fewer
than 20 years before 2026:

.. tabs::

   .. tab:: Session
      :tabid: session

      .. io-code-block::
         :copyable:

         .. input:: /includes/interact-data/Query.java
            :start-after: start-computed-filter-session
            :end-before: end-computed-filter-session
            :language: java
            :dedent:

         .. output::
            :visible: false

            Title: Hairspray, Year: 2007

   .. tab:: EntityManager
      :tabid: entitymanager

      .. io-code-block::
         :copyable:

         .. input:: /includes/interact-data/Query.java
            :start-after: start-computed-filter-em
            :end-before: end-computed-filter-em
            :language: java
            :dedent:

         .. output::
            :visible: false

            Title: Hairspray, Year: 2007

The {+extension-short+} translates the preceding query to the
following ``$match`` stage, in which the ``title`` comparison uses
the compact form and the computed comparison uses ``$expr``:

.. code-block:: json
   :copyable: false

   {
     "$match": {
       "$and": [
         { "title": { "$eq": "Hairspray" } },
         { "$expr": { "$lt": [ { "$subtract": [ 2026, "$year" ] }, 20 ] } }
       ]
     }
   }

Use Predicate Operators
-----------------------

The {+extension-short+} supports the following predicate comparison operators in your query statements:

- :ref:`EXISTS <hibernate-query-exists>`
- :ref:`BETWEEN <hibernate-query-between>`
- :ref:`IN <hibernate-query-in>`
- :ref:`NOT IN <hibernate-query-not-in>`
- :ref:`IS NULL <hibernate-query-is-null>`
- :ref:`IS NOT NULL <hibernate-query-is-not-null>`

.. note::

   The {+extension-short+} does not support all comparison operators. 
   To learn more about support limitations, see :ref:`Query Support <hibernate-query-support>` on
   the Feature Compatibility page.

.. _hibernate-query-exists:

EXISTS
~~~~~~

The ``EXISTS`` predicate matches documents that have a specific field 
and returns only one result for each matching parent
document, regardless of how many array elements match.

.. note:: EXISTS Subquery Limitations

   The {+extension-short+} supports ``EXISTS`` subqueries only over an
   array field of the parent entity, and only in the ``WHERE`` clause.
   The {+extension-short+} does not support ``EXISTS`` subqueries that:
   
   - Query over an entity without first specifying a field
   - Compare fields in the same parent document
   - Appear in the ``SELECT`` clause 

For a full example, see the 
:ref:`hibernate-query-elements-embedded-array` section of this guide.

The ``IN`` predicate matches documents where a field value equals any
value in a specified list. You can supply the list values as literals,

            :language: java
            :dedent:

         .. output::
            :visible: false

            ...
            Title: Kadhal Kottai
            Title: Gotti
            Title: It's Just a Ride

   .. tab:: EntityManager
      :tabid: entitymanager

      .. io-code-block::
         :copyable:

         .. input:: /includes/interact-data/Query.java
            :start-after: start-in-query-em
            :end-before: end-in-query-em
            :language: java
            :dedent:

            :visible: false

            ...
            Title: Kadhal Kottai
            Title: Gotti
            Title: It's Just a Ride

The {+extension-short+} translates the preceding ``IN`` predicate to the
following ``$match`` stage:

.. code-block:: json
   :copyable: false

   {
     "$match": {
       "year": { "$in": [ 1994, 1996 ] }
     }
   }

An empty list is valid, but it never matches any documents. For example, 
``year in ()`` matches no documents.

.. note:: IN Predicate Limitations

   The {+extension-short+} supports the ``IN`` predicate only when the
   value to the left of ``IN`` is a field path. The
   {+extension-short+} does not support ``IN`` predicates that:

   - Take a subquery as the list of values.
   - Test a value against an array-valued expression, as in
     ``:value in m.cast``. To match a value against an array field, use
     the ``array_contains()`` function instead. 
   
   To learn more about querying an array, see the :ref:`hibernate-query-array` 
   section of this guide.

   {+extension-short+} does not support ``NOT IN`` predicates that:

   - Take a subquery as the list of values.
   - Test a value against an array-valued expression, as in
     ``:value not in m.cast``.

Query a Field on an Embedded Document
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

You can reference a field on an embeddable type by using a dotted path expression in the 
``SELECT``, ``WHERE``, ``ORDER BY``, and ``UPDATE`` clauses of an 
HQL or JPQL query. You can also chain
multiple embeddable names in a path expression to reference a
field on a nested embeddable within another embeddable.

.. important:: Query Limitations

   Path expressions do not support embeddable fields that
   use the ``@ColumnTransformer`` annotation to define a 
   custom read expression.

   The {+extension-short+} also rejects the following
   ``@Struct`` aggregate embeddable mappings when it builds the
   entity model:

   - A ``@Struct`` aggregate embeddable used as an ``@Id`` field
   - A polymorphic ``@Struct`` aggregate embeddable hierarchy

   You can't use a path expression to reference a field on these types.

and the other is from 2007. The query matches documents that have a ``title`` value 
of ``"Hairspray"`` and an ``awards.wins`` value greater than ``10``:

.. _hibernate-query-elements-embedded-array:

Query on Elements of an Embedded Array
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

When a field of your entity stores an array of ``@Struct`` aggregate
embeddables, you can use an ``EXISTS`` subquery to match parent
documents in which at least one element of that array meets your
criteria. The {+extension-short+} translates the subquery to the
MongoDB :manual:`$elemMatch </reference/operator/query/elemMatch>`
operator, which applies all criteria to the same array element.

.. code-block:: json
   :copyable: false

.. _hibernate-query-array:

Query an Array Field
---------------------

The {+extension-short+} supports the following functions for
querying array fields:

- ``array_contains()``: Match documents where an array field contains a specified value
- ``array_contains_nullable()``: Match documents where an array field contains a specified
  value, including ``null`` values
- ``array_includes()``: Match documents where an array field includes another array value
- ``array_includes_nullable()``: Match documents where an array field includes another
  array value, including ``null`` values

.. tip::

   To learn more about array functions, see `Functions for dealing with arrays <{+user-guide+}#hql-functions-arrays>`__
   in the {+orm+} user guide.
