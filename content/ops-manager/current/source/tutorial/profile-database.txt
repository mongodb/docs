.. _profile-databases:

====================
Profile Slow Queries
====================

.. meta::
   :description: Profile databases using Ops Manager to gather statistics on database operations, identify slow queries, and suggest indexes for performance improvement.

.. default-domain:: mongodb

.. note:: **Available only with the {+mdbagent-wa+}**

   This feature is available only with the {+mdbagent-wa+}. To learn 
   more about the {+mdbagent-wa+}, see
   :ref:`add-mdb-processes`.
   
.. facet::
   :name: genre
   :values: reference

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

The |mms| :guilabel:`Profiler` page displays profiling data for slow
queries on your databases. The Profiler recognizes a query
as slow if it takes longer to execute than the :ref:`slow query
threshold <slow-queries>` set for your |mongod| instance. 

The |mms| Profiler identifies slow queries by tailing slow query 
:ref:`log data <mongodb-logs>` from your |mongod| instances. |mms|
displays this data on a process's :guilabel:`Profiler` page. To view the
:guilabel:`Profiler` page for a process, click the process in the
:guilabel:`Deployment` view and then click the :guilabel:`Profiler` tab. 

The :guilabel:`Profiler` page displays a chart and a table that describe
metrics for the profiled database operations. To improve the performance
of slow operations, you can use the :ref:`Performance Advisor
<performance-advisor>` to suggest indexes for your databases.

.. note:: 

   The |mms| Profiler is different than the MongoDB :ref:`database
   profiler <database-profiling>`, which collects data about
   :ref:`database commands <database-commands>` executed against a
   running |mongod| instance and writes data to the
   :data:`system.profile <<database>.system.profile>` collection. 
   
   The |mms| Profiler is controlled by a :ref:`project-level setting
   <enable-profiling-manually>`, which determines whether |mms| agents
   tail the slow query and send them to |mms|, and whether the
   :guilabel:`Performance Advisor` and :guilabel:`Profiler` pages are
   available for that project. The |mms| Profiler does not write to the
   :data:`system.profile <<database>.system.profile>` collection.

.. _considerations-profile-database:

Considerations
--------------

.. important:: 
 
   Read the following considerations before you enable |mms| Profiling.

Security
~~~~~~~~

Profile data may include sensitive information including the content of
database queries. Ensure that exposing this data to |mms| is consistent
with your information security practices.

Data Display Limitations
~~~~~~~~~~~~~~~~~~~~~~~~~

The |mms| Profiler displays up to the limit that it reaches first:

- The most recent 10,000 operations, or
- The most recent 10MB of logs.

Monitoring tries to minimize its effect on the monitored systems.
If polling profile data slows database performance, |mms| throttles how
often it collects data.

|mms| displays no more than 10,000 data points in the
:guilabel:`Profiler` charts.

Log data is processed in batches. Data can be delayed up to five minutes
from real time.

Time to Propagate Changes to the {+mdbagent+}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

With profiling enabled, configuration changes made in |mms| can
take up to 2 minutes to propagate to the agent and 1 more minute before
profiling data appears in the |mms| interface.

.. _enable-profiling-through-automation:
.. _enable-profiling-manually:

Enable Profiling
----------------

As of |mms| version 4.4, |mms| enables the |mms| Profiler by default.
Your |mongod| instance collects profile data for operations longer than
the :ref:`slow operation threshold <slow-queries>` and reports them to
|mms|. The threshold for slow operations applies to the entire |mongod|
instance. |mms| defaults this threshold to 100 ms. To change the
threshold, see :ref:`slow-queries`.

To disable the |mms| Profiler for an |mms| project, navigate to the
:ref:`project settings <manage-group-settings>` and toggle the
:guilabel:`Performance Advisor and Profiler` setting to :guilabel:`On`
or :guilabel:`Off`. This stops |mms| from tailing the |mongod| logs for
slow query data, and disables the :guilabel:`Performance Advisor` and
:guilabel:`Profiler` pages for that project. 

The :guilabel:`Performance Advisor and Profiler` setting doesn't affect
whether the :ref:`MongoDB database profiler <database-profiling>` is
enabled on a given |mongod| process, only whether |mms| collects and
displays profiling data for slow queries.

.. _profiler-interface:

Profiler Interface
------------------

The |mms| :guilabel:`Profiler` page contains two displays for database
profile information: a chart and a table. The following sections
describe how to filter the data in each display. 

.. _profiler-chart:
.. _profiler-chart-set-filter:

Filter the Profiler Chart
~~~~~~~~~~~~~~~~~~~~~~~~~

You can filter the Profiler chart by metric and time period. To filter
the chart: 

1. From the :guilabel:`Display` drop-down menu, select the metric
   you want to view in the chart. Available options are:

   - Operation Execution Time (default)
   - Keys Examined
   - Docs Returned
   - Examined:Returned Ratio
   - Num Yields
   - Response Length
   
#. From the :guilabel:`View Last` drop-down menu, select the time
   period you want to view in the chart. Available options are:

   - 24 hr (default)
   - 12 hr
   - 6 hr
   - 1 hr
   - 15 min

.. _profiler-table:
.. _profiler-table-set-filter:

Filter the Profiler Table
~~~~~~~~~~~~~~~~~~~~~~~~~

You can filter the Profiler table by namespace, operation type, and
metric. To filter the table: 

1. From the :guilabel:`All Namespaces` drop-down, choose which database
   and collections to profile in the table. 

#. From the :guilabel:`All Operations` drop-down, choose which operation
   types to profile. 

#. From the :guilabel:`Operation Execution Time` drop-down, choose which
   metric you want to profile. Available options are:

   - Operation Execution Time (default)
   - Keys Examined
   - Docs Returned
   - Examined:Returned Ratio
   - Num Yields
   - Response Length
