General Changes
---------------

Change Stream Pre-Image Metrics
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the
``changeStreamPreImages.purgingJob.docsDeleted`` and
``changeStreamPreImages.purgingJob.bytesDeleted`` serverStatus metrics
may report estimates rather than exact values. These estimates occur
when size and count information is not available for the
``config.system.preimages`` collection. For details, see
:ref:`server-status-changeStreamPreImages`.

MongoDB 9.0 also adds a new ``changeStreamPreImages.markerCreation``
serverStatus document. This document reports metrics related to the
pre-image sampling passes that build the initial truncation
information used to remove pre-images. For details, see
:ref:`server-status-changeStreamPreImages`.

Multi-Document Transaction Limit
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the server limits the number of concurrently
open multi-document transactions for external clients. When the number
of open transactions reaches the limit set by the
:parameter:`maxConcurrentMultiDocumentTransactions` parameter (default
``10000``), the server rejects new multi-document transactions and
returns a ``TooManyOpenTransactions`` error. To learn more, see
:parameter:`maxConcurrentMultiDocumentTransactions`.

Server-side JavaScript
~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the server-side JavaScript functions
(:group:`$accumulator`, :expression:`$function`, and :query:`$where`)
are no longer deprecated. MongoDB 9.0 re-enables these functions using a
WebAssembly (WASM)-based JavaScript engine, which improves security
through stronger sandboxing and isolation than prior versions. These
functions were previously deprecated in MongoDB 8.0. To learn more, see
:ref:`server-side-javascript`.

Sharding
--------

``checkMetadataConsistency`` Inconsistency Types
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the following :dbcommand:`checkMetadataConsistency`
:ref:`inconsistency types <inconsistency-types>`:

- :data:`AuthoritativeShardCatalogCollectionsPresent`
- :data:`IncompatibleUniqueIndexOnShardedCollection`
- :data:`InconsistentShardCatalogCollectionMetadata`
- :data:`LegacyShardCacheCollectionsPresent`

MongoDB 9.0 removes the ``ShardCatalogCacheCollectionMetadataMismatch``
inconsistency type.

Cursor Namespace in Command Responses
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, when you run a ``find``, ``aggregate``, or ``listIndexes``
command on a time series collection, the ``cursor.ns`` field in the
response returns the user-facing namespace you originally targeted. In previous
versions, the server could return the internal namespace.

Change Stream Shard Targeting
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, change streams on sharded clusters open
cursors only on the shards that hold relevant data and adjust
targeting automatically as the cluster topology changes. MongoDB 9.0
also adds the ``ignoreRemovedShards`` parameter to the
:pipeline:`$changeStream` aggregation stage. When set to ``true``, a
change stream continues and skips events from a shard that was removed
from the cluster instead of returning an error. For details, see
:pipeline:`$changeStream`.

BSON Validation
~~~~~~~~~~~~~~~

MongoDB 9.0 deprecates the :setting:`net.wireObjectCheck` configuration option
and its corresponding ``--objcheck`` and  ``--noobjcheckand`` CLI arguments.
Starting in 9.0, MongoDB validates all BSON objects that the server ingests by
default. If the server receives invalid BSON data, MongoDB returns an error.

Time Series
-----------

Data Storage
~~~~~~~~~~~~

Starting in 9.0, MongoDB stores time series collections as a single
namespace that contains time series data compressed into buckets. Time
series collections are no longer writable non-materialized views.

Aggregation

$queryStats Output
~~~~~~~~~~~~~~~~~~

MongoDB 9.0 updates the :pipeline:`$queryStats` output to streamline metrics
organization. This update includes the following new output fields:

.. list-table::
   :header-rows: 1
   :widths: 38 72

   * - Field
     - Description

   * - ``metrics.cursor``

     - A document that contains metrics relevant to the cursor and batching
       protocol

   * - ``metrics.queryExec``

     - A document that contains metrics relevant to query execution

   * - ``metrics.queryPlanner``

     - A document that contains metrics relevant to the query planner

   * - ``metrics.writes``

     - A document that contains metrics relevant to operation writes

For more information on the new output structure, see :ref:`$queryStats Output
<queryStats-output>`.

Security
--------

``useInternalAuthzForX509`` Parameter
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the :parameter:`useInternalAuthzForX509`
parameter. When set to ``true``, clients that authenticate
using ``MONGODB-X509`` use internal authorization,
even when LDAP authorization is configured. For details, see
:parameter:`useInternalAuthzForX509`.

``usersInfo`` ``authenticatedMechanism`` Field
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

MongoDB 9.0 adds the ``authenticatedMechanism`` field to the
:dbcommand:`usersInfo` command. This optional string field
specifies an authentication mechanism to determine which
authorization backend ``usersInfo`` queries when looking up
user authorization information. For details, see
:dbcommand:`usersInfo`.

Replication
-----------

New replSetGetStatus Metrics for Phase Tracking
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Starting in MongoDB 9.0, the following metrics are available when using
the :dbcommand:`replSetGetStatus` command during a logical initial sync:

- :data:`replSetGetStatus.initialSyncStatus.phase`
- :data:`replSetGetStatus.initialSyncStatus.totalAttempts`
- :data:`replSetGetStatus.initialSyncStatus.bytesPerSecond`

Each document in
:data:`~replSetGetStatus.initialSyncStatus.initialSyncAttempts` also
reports the ``phase``, ``nodeUptimeSecs``, and ``phaseDurations`` for that
attempt. For details, see
:data:`replSetGetStatus.initialSyncStatus.initialSyncAttempts`.
