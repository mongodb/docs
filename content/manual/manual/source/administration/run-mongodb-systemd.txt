====================================
Run the MongoDB Service with systemd
====================================

.. meta::
   :keywords: on-prem
   :description: Learn how to start the MongoDB service on Linux with systemd, including how to launch it automatically at system startup and manage it with systemctl commands.

.. facet::
   :name: genre
   :values: reference

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 1
   :class: singlecol

Linux distributions use systemd to start up and manage services through
standard command-line tools. If you installed MongoDB Enterprise or
MongoDB Community through the package manager, you can manage the
:binary:`~bin.mongod` process through the ``systemctl`` command.

Syntax
------

.. code-block:: bash

   sudo systemctl <command> mongod

Commands
~~~~~~~~

.. list-table::
   :header-rows: 1
   :stub-columns: 1
   :widths: 20 80

   * - Command
     - Description
   * - ``enable``
     - Configures systemd to start the MongoDB service during boot.
   * - ``restart``
     - Restarts the MongoDB service.
   * - ``start``
     - Starts the MongoDB service.
   * - ``status``
     - Shows the status of the MongoDB service.
   * - ``stop``
     - Stops the MongoDB service.

Compatibility
-------------

On self-managed deployments, you can manage the :binary:`~bin.mongod`
process with the ``systemctl`` command on any supported systemd-based
distribution of Linux.

For details on supported platforms, see:

- :ref:`Supported Platforms for MongoDB Enterprise
  <landing-enterprise-platform-support>`
- :ref:`Supported Platforms for MongoDB Community
  <landing-community-platform-support>`

Behavior
--------

User Privileges
~~~~~~~~~~~~~~~

Most commands that run through systemd require a user with elevated
privileges. While the ``root`` user can administer the
:binary:`~bin.mongod` process directly through the ``systemctl``
command, other users must run these commands with ``sudo`` privileges.

System Journal
~~~~~~~~~~~~~~

When run through systemd with the default configuration,
:binary:`~bin.mongod` logs messages through the system journal. The
journal allows you to search for specific issues or messages with the
``journalctl`` command.

Examples
--------

Start MongoDB
~~~~~~~~~~~~~

To start the MongoDB service, run the following command:

.. code-block:: bash

   sudo systemctl start mongod

Show MongoDB Status
~~~~~~~~~~~~~~~~~~~

To show the status of the MongoDB service, run the following command:

.. io-code-block::

   .. input::
      :language: bash

      systemctl status mongod

   .. output::
      :language: none

      ● mongod.service - High-performance, schema-free document-oriented database
           Loaded: loaded (/lib/systemd/system/mongod.service; enabled;
           vendor preset: enabled)
           Active: active (running) since Mon 2026-09-21 09:41:13 UTC;
           4 days ago
             Docs: https://docs.mongodb.org/manual
         Main PID: 8642 (mongod)
           Memory: 148.1M
               CPU: 2m 15s
           CGroup: /system.slice/mongod.service
                   └─8642 /usr/bin/mongod --config /etc/mongod.conf

The status of the service is not privileged information. You do not need
``sudo`` to run the ``status`` command.

Stop MongoDB
~~~~~~~~~~~~

To stop the MongoDB service, run the following command:

.. code-block:: bash

   sudo systemctl stop mongod

Restart MongoDB
~~~~~~~~~~~~~~~

To restart the MongoDB service, run the following command:

.. code-block:: bash

   sudo systemctl restart mongod

Start MongoDB on Boot
~~~~~~~~~~~~~~~~~~~~~

To configure the system to start the MongoDB service on startup, run the
following command:

.. io-code-block::

   .. input::
      :language: bash

      sudo systemctl enable mongod

   .. output::
      :language: none

      Created symlink /etc/systemd/system/multi-user.target.wants/mongod.service → /usr/lib/systemd/system/mongod.service.

Show MongoDB Logs
~~~~~~~~~~~~~~~~~

To show log messages sent by MongoDB to the system journal, run the
following command:

.. io-code-block::

   .. input::
      :language: bash

      sudo journalctl -u mongod

   .. output::
      :language: none
