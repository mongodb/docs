======================================
Unsupported Commands in Atlas Clusters
======================================

.. meta::
   :description: Discover which database commands and command-line options Atlas restricts or does not support across cluster types, including M0, Flex, and M10+ clusters.

.. default-domain:: mongodb

.. contents:: On this page
   :local:
   :backlinks: none
   :depth: 2
   :class: onecol

.. |starter| replace:: {+Free-clusters+} and {+Flex-clusters+}

This page compares command support for {+Free-clusters+},
{+Flex-clusters+}, M10+ {+atlas-core-cluster+}s, and M10+
{+atlas-infinite-cluster+}s in the following sections:

- :ref:`Unsupported Commands <unsupported-commands-paid>` lists MongoDB
  commands and shell methods that |service| doesn't support, organized
  by command category.

- :ref:`Unsupported Command Line Options <unsupported-cli-options>` lists
  |mongodump| and |mongorestore| options that |service| doesn't support.

- :ref:`Limited Commands <limited-mdb-commands>` lists commands that |service|
  supports with restrictions for each cluster type.

|service| requires clients to authenticate to access an |service|
cluster. |service| provides a curated list of :ref:`Database User
Privileges <atlas-user-privileges>` that grant access to a subset of
MongoDB commands. The tables in the Unsupported Commands section list
the commands that fall outside this subset for each cluster type.

|service| Free, Flex, and Infinite {+clusters+} don't support all functionality
available to other {+clusters+}. To learn more, see:

- :ref:`atlas-free-tier`
- :ref:`flex-cluster-limitations`
- :ref:`atlas-infinite-availability`

Unsupported Commands
--------------------

The following tables list the MongoDB commands, shell methods, and
privilege actions that |service| doesn't support, by cluster type. To
ensure cluster stability and performance, |service| automates the
functionality that these commands provide. |service| restricts other
commands based on a cluster's tier or database edition.

A :icon-fa5:`times` indicates that the {+cluster+} type doesn't support
the command.

.. note::

   If you use an unsupported command or invalid syntax in |starter|,
   |service| returns the following error message:

   .. code-block:: shell
      :copyable: false

       <$command> is not allowed or the syntax is incorrect,
       see the Atlas documentation for more information.

   To learn more about valid syntax, see :manual:`Database Commands
   </reference/command>`

.. _limited-commands-paid:

M10+ Core
~~~~~~~~~

|service| limits the :method:`db.killOp()` method to the MongoDB user
who ran the operation.

|service| doesn't support the :dbcommand:`killAllSessions` command
unless the database user has:

- the :authaction:`killAnySession` privilege, or
- the :atlasrole:`killOpSession` role.

|service| supports the following sharding commands on only ``M30+``
sharded {+atlas-core-cluster+}s.

.. list-table::
   :widths: 40 30 30
   :header-rows: 1

   * - Command
     - Shell Method
     - Privilege Action

   * - :dbcommand:`abortRewriteCollection`
     -
     - :authaction:`rewriteCollection`

   * - :dbcommand:`reshardCollection`
     - :method:`sh.reshardCollection() <sh.reshardCollection>`
     - :authaction:`reshardCollection`

   * - :dbcommand:`rewriteCollection`
     -
     - :authaction:`rewriteCollection`

   * - :dbcommand:`unshardCollection`
     - :method:`sh.unshardCollection()`
     - :authaction:`unshardCollection`

M10+ Infinite
~~~~~~~~~~~~~

|service| limits the :method:`db.killOp()` method to the MongoDB user
who ran the operation.

|service| doesn't support the :dbcommand:`killAllSessions` command
unless the database user has:

- the :authaction:`killAnySession` privilege, or
- the :atlasrole:`killOpSession` role.

{+atlas-infinite-cluster+}s only support the :dbcommand:`profile`
command when the :ref:`database profiler level
<set-profiling-level-level>` is ``0``.
